# Адаптивная практика

Это правила наставника и контракт записи помощи в существующий unit-learning,
не отдельная система оценивания. Для unit применяй их перед первым заданием.

## Подбор и помощь

Прочитай цель и план занятия, исходную самооценку и предпочтения, критерии unit,
learning_progress, реальные ошибки/ответы и learning.adaptive. Подбери одно
задание по непроверенному критерию или конкретному пробелу; запиши rationale,
ссылаясь на эти факты. Не повышай сложность только из-за стажа и не заставляй
повторять подтверждённое без причины. При недостатке данных предложи небольшую
пробную задачу. Смысловой подбор и оценка остаются ответственностью наставника.

Сначала покажи только условие и дай решить самостоятельно. При затруднении:
небольшой намёк → конкретная подсказка → подробное объяснение. Между ступенями
дай возможность попробовать. По прямой просьбе полного решения сразу покажи
решение с разбором, без обязательных промежуточных подсказок. Сохрани исходную
просьбу и реально показанный разбор; не придумывай просьбу ради обхода ступеней.

После ошибки сначала объясни её причину и предложи исправление. Запиши настоящий
ответ как needs_review, а существенное объяснение способа решения как помощь.
Разбор ошибки может идти внутри первой подсказки, затем углубляться. Простое
сообщение «неверно» не заменяет разбор. Если по просьбе ученика требуется полный
разбор, сохрани его как solution с исходной просьбой.

Исправленная попытка после помощи остаётся practice_with_help; самостоятельное
освоение проверяй новой задачей с другим ходом решения/данными, без готового
ответа. Перефразирование показанного решения не является новой проверкой.
Программа сравнивает только нормализованную формулировку и не доказывает
смысловую новизну. Не отмечай успех без реального ответа по критериям.

Фиксированной нормы заданий нет. После ошибки предложи исправление, после помощи
— новую самостоятельную задачу, после успеха — выбор следующего шага или паузы.
Если ученик хочет дальше, сохрани фактический checkpoint и незавершённую практику;
не требуй решить всё. Используй существующий жизненный цикл занятия, не меняй
Roadmap без согласия. Пользователю показывай диалог, не служебные записи.

## Контракт записи

В `learn-unit` добавлен взаимоисключающий `--practice-file`. CAS, хеш unit,
блокировки и журнал остаются прежними. Требуется session. Для занятия передай
`--lesson-id`; задача сохраняет эту связь и доступна в другом чате.

Перед выдачей нового задания сохрани:
```json
{"action":"task","id":"map-replacement-1","question":"Каковы значение и размер после put(a,2), put(a,3)?","criteria":[1],"rationale":"Проверить замену значения: прошлый ответ путал значение и размер"}
```
ID уникален в пределах unit и его версии; разные занятия получают разные ID.
Перед показом существенной помощи сохрани фактическое содержание:
```json
{"action":"help","task_id":"map-replacement-1","level":"hint","content":"Проследи, появился ли новый ключ при втором put.","request":null}
```
Уровни: hint, concrete, explanation, solution. Обычная помощь начинается с hint,
идёт последовательно; explanation можно повторять. Solution допускается сразу
только с непустой исходной просьбой в request. После solution к hint не возвращайся.
Если запись не удалась, сообщи об этом: не обещай сохранения помощи/прогресса.

Результаты пиши прежним `--event-file`, добавляя `task_id`. Question должен
соответствовать заданию, criteria — быть его подмножеством. Hints учитывает все
существенные показанные сообщения помощи, включая полный разбор; минимум — число
сохранённых сообщений для этой формулировки. Needs_review сохраняет ошибочную
попытку и после помощи; правильная попытка с помощью — practice_with_help.
Solved_independently/checked_later запрещены для задания с сохранённой помощью,
включая попытку убрать task_id или выдать ту же формулировку за новый ID.

`learning.practice` возвращает задачи текущей версии, help, solution_shown,
last_attempt и next_action. Без lesson-id доступны все задачи unit; с ним —
только выбранного занятия. Отсутствующий last_attempt означает, что попытка не
записана, а не что ученик ошибся. Новая задача сама по себе не отменяет прошлые
знания и не создаёт оценок. При чтении ничего не записывается.

Расширения аддитивны в unit_learning_v2 и сегментированном v3. Старые v1/v2
читаются без миграции; отсутствующие задания/помощь не выдумываются. Для старых
оценок без task_id сохраняются прежние гарантии: нельзя восстановить неучтённые
подсказки задним числом. Старые версии плагина новые типы событий не понимают.
Факт просьбы, корректность ответа, полнота записи помощи и смысловая новизна
новой задачи доверены наставнику; Python проверяет связи и объективные ограничения.
