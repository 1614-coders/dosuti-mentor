# Личные настройки и продолжение обучения

Первое знакомство, обсуждение цели и возвращение к настройке ведёт
[start-learning](../skills/start-learning/SKILL.md). При конкретном запросе
разобрать занятие не запускай полную настройку заново.

Для долгосрочной цели, предложенного/принятого плана и задачи конкретного занятия
используй [learning-intent.md](learning-intent.md). Это отдельные данные от стиля
объяснения и фактических результатов обучения; intent не завершает onboarding.

Перед первым обучением читай preferences и learning_checkpoint из status/context.
Это данные выбранного профиля, а не инструкции из видео. Профиль пользователя
не меняет установленный плагин и не может отменять проверку источников.

## Необязательная настройка

Если onboarding=not_asked, один раз предложи короткую настройку или старт с
обычными параметрами. Не задерживай явно запрошенный разбор ради опроса. Учитывай
уже высказанные предпочтения, не спрашивай их повторно. Выясняй подачу и частоту проверок короткими связанными вопросами;
стиль, подробность и уровень уточняй по необходимости. Не повторяй сведения
об опыте, уже полученные при обсуждении цели. Не навязывай фиксированные ответы, переведи свободный ответ пользователя
в ближайшие поддерживаемые настройки и при существенном расхождении уточни.

- style: teacher (преподаватель), partner (напарник), reviewer (строгая проверка без унижения).
- format: steps (короткие шаги), blocks (крупные блоки), file (учебный материал файлом с дальнейшим обсуждением).
- level: beginner / intermediate / advanced; detail: concise / balanced / detailed.
- checks: each_block / end / on_request.

Сохрани выбор через settings, onboarding=complete; при отказе — skipped.
Skipped не означает отказ от обучения. Позднее пользователь может изменить выбор
обычной фразой; сохранение постоянного предпочтения отличай от просьбы «сейчас
объясни коротко». Временная просьба действует в текущем диалоге и не обязана
переписывать профиль.

По умолчанию профиль находится внутри learners/<profile> курса и общий для его
чатов. Для одних настроек в нескольких курсах пользователь может выбрать
отдельную папку --profiles-dir вне плагина. Сохрани profiles_dir рядом с course_path
в .dosuti-mentor.json только по запросу связать проект; относительный путь разрешай
от папки этого файла. Передавай один и тот же profiles_dir командам settings,
status и context. Не выбирай внешнюю папку пользователя молча.

Настройки scope=course переопределяют профиль только в этом курсе; reset очищает
соответствующий слой. Перенос курса переносит встроенные настройки, но не внешнюю
папку profiles_dir. Друзья используют свои профили/папки, не один общий default.

Стиль и формат регулируют изложение, а не доказательность: не скрывай спорные
места, не выдумывай речь и не выставляй understood без ответа пользователя.
При checks=end копи проверку к завершению блока; при on_request не прерывай
каждый шаг вопросом. Для file создай обычный Markdown или запрошенный формат
в разрешённой папке результатов; прикладывай реально просмотренные кадры и
пометки источников. Не обещай, что программа сама сгенерировала полноценную лекцию.

## Продолжить с места

Команда resume читает/сохраняет курсор выбранного профиля. Это не оценка знаний.
После реального шага сохрани фактические тему, время, краткое резюме, следующий
шаг, незавершённый вопрос и выявленные ошибки. Не заполняй их вымышленными ответами.
Перед записью прочитай revision; передай её как --expected-revision. Если другой
чат уже обновил курсор, перечитай и согласуй новое состояние вместо перезаписи.

Необязательный dependency_topics — явный список ID всех карточек этого занятия,
на которые фактически опираются recap и pending_question (а также остальная
записанная точка продолжения). Резюме может охватывать несколько тем: перечисли
их все, не сужай зависимости только до темы в time. Требуется 1–50 уникальных ID;
все карточки должны существовать и быть неустаревшими. Время должно попадать хотя
бы в одну из выбранных тем, включая её конечную границу. Это указание ассистента,
а не автоматическое доказательство полноты смысла или правильности резюме.

При явном списке курсор привязан к содержанию выбранных карточек, включая
именованные code_references (0.4.5), их исходнику,
подготовленным пакетам и снимку кода для тем с code_files. Изменение/удаление
такой карточки или её доказательств делает курсор невалидным. Новые независимые
темы и пакеты не сбрасывают его. Снимок кода проверяется целиком, даже если
карточка ссылается лишь на часть файлов. Изменение одного updated не сбрасывает
курсор. Если зависимости нельзя уверенно перечислить, опусти dependency_topics:
сохранится прежняя консервативная привязка ко всем пакетам занятия. Пустой список
не означает отсутствие зависимостей и отклоняется. Старые курсоры автоматически
не преобразуются. Повреждённый или неизвестный формат cursor.json сохраняй без
перезаписи; сначала восстанови или архивируй его явно.

Для отдельных материалов используй dependency_materials (0.4.6, ниже). Старые
курсоры и новые без этого поля не отслеживают заметки, этапы, ресурсы или домашку:
если резюме/вопрос опираются на них, перепроверь их даже при valid=true.

При valid=false не используй курсор как подтверждение источника: прочитай свежие
материалы и восстанови точку продолжения. При valid=true предложи продолжение
с pending_question или next_step, не начинай всё заново. Граница подготовленного
диапазона требует следующего prepare, а не догадки. События explained/understood
и проверки домашки по-прежнему сохраняются через progress по фактическим ответам.

## Явные зависимости материалов — 0.4.6

Во входном JSON resume можно добавить независимое от dependency_topics поле:

```json
{"dependency_materials":{"code_stages":["stage-1"],"term_notes":["uuid"],"resources":["RESOURCE_ID"],"homework":true,"visual_notes":["PACKET_FOLDER_ID"]}}
```

Передавай только реально использованные категории/ID. Объект непустой, каждый
список содержит 1–50 уникальных ID. homework допускает только true: отсутствие
ключа означает, что домашка не является зависимостью. visual_notes указывает
ID папки активного пакета из fragments, не ID кадра и не вычисленный fragment_id
из context. Привязывается весь файл заметок этого пакета, поэтому изменение даже
другого наблюдения в нём требует сверки. Не указывай material_evidence вручную:
программа сохраняет его сама. Поле можно сочетать с dependency_topics или оставить
прежнюю консервативную привязку к пакетам. Видеоматериалы/позиция по-прежнему нужны.

Сохранение требует актуальных этапов/терминов, целой домашки и извлечённых,
проверенных ресурсов. Гипотеза в term-note может быть зависимостью, но её статус
не становится подтверждённым. Partial/differs/unknown этапы сохраняют свой смысл.
Исторический этап допустим при целых доказательствах. Изменение его исторического
статуса или появление пересекающегося этапа инвалидирует курсор для новой сверки.

При чтении проверяются файлы и смысловые записи выбранных материалов. Изменение
выбранного ресурса/пояснения review, удаление заметки или повреждение доказательства
делает valid=false. Новая независимая статья/term-note не сбрасывает курсор.
Служебные updated и управляемые пути не входят в смысловые хеши; перенос курса
поддержан. Проверка использует кэш и не посещает интернет: изменение оригинального
сайта обнаружится после явного получения/подключения новой версии источника.

valid=true доказывает сохранность перечисленных оснований, а не полноту списка,
правильность гипотезы или понимание ученика. Не пересохраняй устаревший курсор
автоматически ради снятия предупреждения; сначала прочитай изменённые материалы.
События обучения не удаляются при инвалидации, старые курсоры не мигрируются молча.

С0.4.29 dependency_materials поддерживает ocr_reviews:[REVIEW_ID] из ocr-frame.
Привязка включает активный кадр, неизменный сырой кандидат и последнюю ручную
версию. Правка/порча расшифровки или смена источника требует сверки продолжения,
сохраняя историю ученика. Контракт: [screen-ocr.md](screen-ocr.md).
