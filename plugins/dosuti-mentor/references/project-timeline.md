# История проекта между занятиями — 0.4.17, этап 5A

Старый project-map остаётся обзором занятий/символов. project-timeline — отдельная
явная серия по выбранным снимкам, без автоматического угадывания общего проекта.
Старые курсы читаются без миграции и создания реестра.

```sh
PYTHON PLUGIN_ROOT/scripts/course.py project-timeline --course COURSE
PYTHON PLUGIN_ROOT/scripts/course.py project-timeline --course COURSE --timeline-file JSON --expected-revision N
PYTHON PLUGIN_ROOT/scripts/course.py project-timeline --course COURSE --timeline-id PROJECT
```

Первая команда только перечисляет ID/название/хеш/число линий; это не проверка всех
исходников. Для сверки конкретной серии нужен --timeline-id. Последняя возвращает
record, tracks с проверенными шагами/сравнениями, stale и reasons.

Входной JSON:

```json
{
  "id":"backend-project",
  "title":"Проект преподавателя: сохранённые состояния",
  "tracks":[
    {"id":"application","title":"Приложение","steps":[
      {"id":"first","lesson":"lesson-01","repository":"default","version":"current","gap_before":false,"notes":"Снимок из материалов первого урока; экранное соответствие не проверено"},
      {"id":"second","lesson":"lesson-02","repository":"default","version":"current","gap_before":false,"notes":"Следующее выбранное состояние; причина изменений ещё не установлена"}
    ]}
  ],
  "uncertainties":["Промежуточный код мог не попасть в приложенные файлы"]
}
```

tracks — отдельные линии проекта/репозитория; ID линии задаёт ассистент на основании
материалов. Дополнительный репозиторий может быть другой линией. Не объединяй
несвязанные lambdas/edo-twelve только потому, что пользователь прислал оба.
В каждом шаге явные lesson и repository (default либо именованный ID).
version=current отслеживает текущий снимок выбранного урока/репозитория. Вместо
current можно указать content_sha256 исторического снимка ровно этого же урока и
репозитория: новая текущая версия не подменит его. Порядок steps задан вручную,
не выводится из имени файла, даты или сортировки lessons. В одном уроке допустимы
два разных исторических состояния с разными ID шагов.

Проверяются файлы снимка и вычисленная идентичность inventory; автоматически
фиксируется code_sha256. Его не передавай во входном JSON. Изменение current или
повреждение pinned делает шаг stale; сравнение с таким концом unavailable, без
придуманных изменений. Остальные целые части серии доступны с собственными статусами.
Для исправления причины сначала сверь основание; не пересохраняй вслепую ради stale.

Соседние целые снимки сравниваются по путям и содержимому:

- added/removed/modified — наблюдаемая разница файлов, не порядок редактирования автора.
- same_content_move_candidate — уникальная пара удалённого/добавленного файла с тем
  же SHA256. Это кандидат на перенос, не доказанное переименование или его причина.
  Файл мог быть скопирован/создан отдельно; изменённое содержимое не сопоставляется.
- Неоднозначные одинаковые файлы не соединяются: ambiguous_moves сохраняет группы,
  а сами изменения остаются added/removed. Пустые файлы не теряются.

gap_before=true у следующего шага запрещает выводить переход через известный пробел:
comparison.status=gap, список изменений не строится. Временная непрерывность видео
автоматически не определяется; отсутствие gap-флага не доказывает непрерывность.
Даже observed-сравнение не доказывает, что изменения выполнялись на экране.
lecture_match всегда unverified. Notes/uncertainties — аннотации ассистента,
не цитата преподавателя или автоматически установленная мотивация.

До10 линий,2–50 шагов на линию и100 шагов всего; до100 серий в курсе.
Вывод сравнений: до200 изменений и50 неоднозначных групп; до20 членов каждой
стороны группы, с полными counts/truncated. Это не полный diff текста кода.
Для файла можно дополнительно использовать старый diff-code, учитывая его семантику.

Реестр project-timelines.json имеет схему project_timelines_v1, CAS-ревизию,
смысловой хеш и историю замен. До900000 байт без автоархива/молчаливой обрезки.
Повреждённый/неизвестный реестр не перезаписывается. Записи сериализованы общей .study-units.lock, затем
.project-timelines.lock. Снимки/прикрепления к урокам меняются независимо: при чтении
основания проверяются заново, атомарный снимок всего курса не обещается.

Связи хранят ID/хеши, поэтому перенос курса сохраняет серию. Для старых уроков
перед переносом нужен make-portable; внешнее видео само не копируется.
Старая project-map и diff-code не заменены и не получают эти новые свойства молча.

С0.4.18 явная связь kind=timeline в unit отслеживает выбранный переход и привязанные
этапы видео. Обучение через небольшие задачи организует teach-project, результаты
хранит learn-unit. См. [project-learning.md](project-learning.md). Само создание
серии без явной зависимости не обновляет unit или результаты. Не объявляй серию
восстановленной историей реального проекта без фактических материалов/проверки.
