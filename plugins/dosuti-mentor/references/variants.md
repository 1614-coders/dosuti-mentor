# Несколько репозиториев и варианты распознавания — 0.4.4

## Код

Обычный attach --kind code сохраняет основной снимок, как прежде. Дополнительный:

```sh
python course.py attach --course COURSE --lesson LESSON --kind code --repository streams --source CODE_FOLDER_OR_URL
```

ID — обычный slug; default зарезервирован для основного снимка. Поддержаны те же
источники: локальная папка/файл/ZIP, GitHub, публичный ZIP/сырой текст. У каждого
именованного источника своя история. Повтор с тем же ID обновляет только его;
--repository ID --none отмечает отсутствие, сохраняя историю.

Context возвращает teacher_code для совместимости и teacher_repositories:
default + именованные снимки. Их текущая целостность проверяется перед выдачей.
Project-map включает repositories; его прежние files/changes/dependencies
относятся к основному снимку. Сравнение выбранного репозитория двух занятий:

```sh
python course.py diff-code --course COURSE --previous OLD --lesson NEW --repository streams
```

Отсутствие снимка в одном занятии даёт ошибку, не фиктивное удаление всех файлов.
Code-stage по code_sha256 может ссылаться на любой текущий/исторический снимок;
набор файлов и хеши определяют источник. Term-note attached_code может ссылаться
на любой текущий снимок, но не исторический. Не путай одинаковые имена файлов из
разных репозиториев: показывай ID, путь и этап. Соответствие экрану остаётся ручным.

Старые visual_notes attached_code и topic.code_files относятся к основному снимку.
В 0.4.5 для дополнительных снимков появились source_repository и code_references
(см. ниже). С 0.4.6 code-stage можно явно включать в dependency_materials
(personal-learning.md); курсоры без этого поля требуют отдельной проверки.
Все текущие/исторические пути именованных снимков переносятся вместе с курсом.

## Варианты распознавания

```sh
python course.py fragments --course COURSE --lesson LESSON
python course.py fragments --course COURSE --lesson LESSON --keep FRAGMENT_ID --expected-revision REVISION
```

Вывод содержит ID папки пакета, active, coverage, packet_sha256 и ревизию занятия.
Для нескольких неперекрывающихся частей повторяй --keep. Передай ПОЛНЫЙ список
пакетов, которые должны остаться активными. Команда проверяет ревизию под
блокировкой, целостность выбранных пакетов, исходник и сохранение всех диапазонов,
уже покрытых активными пакетами. Выбор с пропуском отклоняется без изменения урока.

Невыбранные активные пакеты переходят в retired_fragments, файлы остаются. Выбранный
исторический пакет можно вернуть той же командой. История выбора сохраняется.
Контекст/поиск/темы работают по активным пакетам; зависимости тем/курсора проверяются
заново, старые оценки/события сохраняются. При изменении транскрипции/кадров записи
code-stage/term-note могут потребовать сверки — это нормальная реакция.

Выбирай после сравнения речи/кадров, а не по наличию словаря или названию модели.
Хеши не оценивают точность ASR. Команда выбирает целые пакеты, не склеивает их
по предложениям. Частично перекрывающиеся интервалы требуют набора с полным
покрытием; безопасное автоматическое обрезание пакетов не реализовано.

С 0.4.7 явный выбор защищает покрытые выбранными пакетами диапазоны. Последующий
prepare, включая уже запущенный, сохраняет пересекающийся результат как неактивный
кандидат с activation_reason=explicit_selection_overlap. Завершение обработки
не означает активацию: проверь fragments и сообщение команды. Работы остаются
complete, а activation_status показывает active/candidate. Кандидата можно выбрать
обычным --keep с актуальной ревизией и сохранением полного активного покрытия.

Новый непересекающийся диапазон активируется автоматически; совпадение одной
границы не считается пересечением. Защита не расширяется до следующего явного
выбора. Пакет, захватывающий и защищённое, и новое, целиком остаётся кандидатом:
для немедленного продолжения отдельно подготовь новый участок или явно выбери
полный набор. Автоматического обрезания нет. Повторное использование уже активной
публикации не меняет выбор. Импорт подчиняется тем же правилам, что обычный prepare.

На старом курсе без истории явного выбора сохраняется прежняя активация. При
старой истории выбора, но без нового guard, защищается текущее активное покрытие;
новая публикация сохраняет guard. Ранее перезаписанный старой версией выбор не
восстанавливается автоматически. Проверяй фактический набор и при необходимости
повтори --keep. Повреждённый guard блокирует публикацию до явного восстановления
метаданных; не удаляй его молча ради активации. Реестр вручную не редактируй.
# Уточнение 0.4.5

Темы поддерживают code_references с ID репозитория; экранные заметки attached_code
поддерживают source_repository. Старые поля относятся к default. Правила и пример:
course-navigation.md. В 0.4.6 явные зависимости отдельных заметок/этапов добавлены
через dependency_materials (personal-learning.md).
