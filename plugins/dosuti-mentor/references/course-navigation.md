# Навигация по темам и учебному проекту

## Темы и поиск

После проверки содержательного блока можно сохранить topic: краткое название,
смысловое описание, ключевые слова на языке ученика, диапазон видео, файлы
прикреплённого снимка кода. Это аннотация ассистента, не цитата преподавателя.
Команда принимает только полностью подготовленный диапазон и существующие файлы.
Не создавай карточки по одному названию видео. Изменение относящихся к теме пакетов или связанного снимка кода делает
карточки устаревшими; перед повторным сохранением сверяй их заново.

На просьбу «где объясняли…» используй search. Это локальный поиск по словам
ASR и проверенным по источнику карточкам тем. Отдельной embedding-модели нет.
Для поиска по смыслу переформулируй вопрос в несколько подходящих терминов,
при необходимости на языке лекции; не меняй исходные слова автора и не выдавай
отсутствие лексического совпадения за отсутствие темы. Поиск вернёт время,
происхождение, кадры и предупреждения. Перед объяснением прочитай context нужного
диапазона; при отсутствии результата предложи уточнение или просмотр соседних тем.
Карточки из повреждённых/устаревших источников не используй как надёжный ответ.

## Карта проекта

project-map показывает занятия по порядку, проверенные снимки кода, добавленные,
удалённые и изменённые файлы. Символы и предполагаемые связи извлекаются простым
лексическим анализом; комментарии, одинаковые имена и динамический код могут
дать ложные связи. Не называй их доказанным графом вызовов. Отсутствующий снимок
разрывает сравнение — оно не означает, что преподаватель удалил весь код.

Для объяснения связи темы и класса сопоставь карту с topic, diff-code и кадрами.
Отдельно укажи, что подтверждено приложенным кодом, что видно на видео, а что
является твоим выводом. По запросу покажи небольшую таблицу или диаграмму,
не выгружай весь технический JSON ученику. Выполнение преподавательского проекта
для построения карты не требуется и автоматически не запускается.

## Законченный учебный фрагмент (0.3.2)

При сохранении topic можно добавить `boundary_review`:
`{"start":"complete","end":"complete","notes":"Почему начало понятно, а пример завершён; что сверено"}`.
Допустимые значения каждой границы: complete, continuation, unknown. Осмотри речь,
кадры и код вокруг границ; отсутствие обрыва ASR не доказывает завершённость мысли.
Пустое пояснение не принимается. Длинную тему можно разбить на несколько законченных
шагов, сохраняя порядок преподавателя. Незаконченные границы отмечай честно.

`context --course COURSE --lesson LESSON --topic-id ID` возвращает полный интервал
темы, кадры и этапы кода с обычными настройками/прогрессом ученика. Он требует
актуальную тему и обе границы complete. Старые темы без проверки границ остаются
доступны для поиска, но для этого режима требуют повторной сверки и сохранения.
`--time` и `--topic-id` взаимоисключающие; `--window` относится только к --time.

В обычном временном окне `boundary_speech` отмечает ASR-сегменты, пересекающие край.
Их полный текст сохранён, однако кадры за окном не добавляются автоматически.
При таком предупреждении получи соседний контекст и проверь конец выражения/пример.
Не выдавай успешную проверку хешей или complete за автоматическое понимание лекции:
границы размечает ассистент, ошибочную разметку следует исправить.

## Актуальность тем 0.3.3

Новые карточки имеют evidence_scope=topic_interval_v1: проверяются пересекающиеся
пакеты и пакет у предшествующей границы, который может дать опорный кадр.
Добавление отдельного более позднего участка не сбрасывает тему. Изменение любого
места внутри связанного пакета пока требует повторной сверки, даже если оно вне
темы. При длинном едином пакете проверка остаётся консервативной.
Старые темы без evidence_scope сохраняют проверку всех пакетов до повторной
сверки и сохранения. Не пересохраняй их автоматически ради снятия stale.
Курсор чата и связанный снимок кода по-прежнему проверяются целиком.

## Именованные ссылки на код (0.4.5)

У topic есть необязательное поле `code_references`, например:
`[{"repository":"streams","files":["src/Tasks.java"]}]`.
Оно допускает 1–50 разных репозиториев с непустыми уникальными списками файлов.
`default` обозначает основной код. Старое `code_files` продолжает ссылаться только
на основной снимок; оба поля можно сочетать. При сохранении программа сама
добавляет `code_sha256` каждого снимка: во входном JSON его указывать нельзя.

Проверяются существование файлов и целостность текущего снимка. Изменение всего
связанного снимка делает тему stale, даже если изменён другой файл. Несвязанный
репозиторий не сбрасывает тему. Явный курсор с `dependency_topics` включает эти
ссылки в смысловой хеш темы: смена репозитория даже на одинаковые байты требует
повторной сверки. Старые курсоры и темы сохраняют прежние правила.
Поиск возвращает `code_snapshots` по ID репозиториев и не включает stale темы.
Это аннотация ассистента, не доказательство соответствия кода экрану.

У visual_notes с `source_kind=attached_code` можно указать `source_repository`.
Если поля нет, используется только default; по совпадению хеша репозиторий не
угадывается. `source_sha256` должен относиться к явно выбранному снимку. После
его замены заметка становится historical/requires_review; неизвестный источник
получает unverifiable. История и исходная пометка verification сохраняются.

Начиная с 0.4.6 отдельные visual_notes, code-stage, term-note, домашку и ресурсы
можно явно связать с курсором через dependency_materials (personal-learning.md).
Старые курсоры и новые без этого поля их не отслеживают: проверяй отдельно.
