# Планирование загрузки и обслуживание (0.4.0)

## Качество и предварительный размер

`download-plan --course COURSE --lesson LESSON --video-quality 720` делает только
запрос метаданных сайта, не скачивая видео. Для локального файла или проверенного
кэша сеть не нужна. Для direct HTTP/Яндекс пока не выполняется отдельный запрос
размера: оценка unknown. Проверка кэша читает его для сверки SHA256.

`prepare ... --video-quality best|360|480|720|1080` задаёт потолок высоты видео
для yt-dlp; default best сохраняет прежнюю политику лучшего формата. У неизвестного
разрешения нельзя гарантировать потолок: такой формат отклоняется при выборе числа.
Для прямых файлов и Яндекс качество не меняется. Более низкое качество может сделать
код нечитабельным; выбирай по реальному размеру текста на экране. Изменение настройки
не заменяет закреплённый кэш; для другой версии байтов нужна новая регистрация урока.

План оценивает суммарный размер выбранных потоков по filesize, filesize_approx либо
битрейту×длительности; unknown остаётся unknown. Даже exact_metadata — заявление
площадки, не гарантия будущего размера. Свободное место сравнивается только с оценкой
скачивания, без резервирования пространства. Аудио ASR, кадры, копии рабочих пакетов,
слияние потоков и временные файлы требуют дополнительного места. Не обещай, что
prepare поместится на диск, исходя только из этого числа. Метаданные могут устареть
между планом и загрузкой. План не загружает авторизованные материалы и не обходит DRM.

## Окружение

`doctor --course COURSE [--model-path PATH]` проверяет Python, наличие модулей,
curl/git/ffprobe и запуск bundled ffmpeg. При указании модели проверяет структуру
и сохранённые хеши файлов. Это чтение без установки/ремонта, загрузки модели в память,
проверки точности речи или работоспособности драйверов. Модуль может быть обнаружен,
но не импортироваться из-за несовместимости native-библиотек. Проверка модели может
занять время; одновременное скачивание модели способно дать временный not_ready.
Отсутствие ffprobe или git не блокирует все сценарии локального обучения.

## Предварительный план очистки

`cleanup-plan --course COURSE` читает размеры и пути из метаданных уроков, показывает
рабочие .jobs и .fetch с признаками ссылок. Неизвестные поля с абсолютными путями
также рассматриваются как зависимости. Рабочее состояние complete само по себе
не означает ненужность: опубликованный пакет, процесс и восстановление нужно
проверять отдельно под соответствующими блокировками.

Текущий план консервативен: decision=preserve для всех папок, proposed_deletions=[],
deletion_supported=false. Автоматическая очистка ещё не реализована; команда не
освобождает место и не предлагает удалить retired-источники, код или прогресс.
Это карта для разработки очистки, а не готовый механизм безопасного удаления.
Не выполняй rm по этому отчёту. Даже отсутствие ссылки в уроке не исключает внешнюю
ссылку/чат или работающий процесс. Для одной папки может быть несколько зависимостей.
Обход ограничен, при ошибках/лимитах scan_complete=false; никаких выводов о полной
безопасности не делается. Снимок не атомарный, противодействие злонамеренной
одновременной подмене файлов тем же пользователем не реализовано.

История проекта/курсор/аннотации остаются неизменными. Следующий этап очистки должен
доказывать сохранность опубликованных свидетельств, проверять активность работ и
повторно проверять зависимости непосредственно перед применением.

## Ограниченная очистка рабочих дублей (0.4.1)

`cleanup-job --course COURSE --lesson LESSON --job-key KEY` строит конкретный план.
После просмотра `plan.files`, публикации и ограничения внешних ссылок можно применить
`cleanup-job ... --apply --expected-revision REVISION`. Не применяй очистку курса
пользователя без его запроса на освобождение места; разработка/тестирование функции
не означает согласие на удаление реальных рабочих файлов.

Допускается только зарегистрированная complete-работа, у которой есть активный
полностью проверенный опубликованный пакет с тем же источником, аудио и кадрами.
Байты каждого удаляемого аудио/кадра должны совпадать с опубликованной копией.
Явные абсолютные ссылки на рабочий payload из метаданных всех занятий блокируют
очистку. Операция получает блокировки урока и работы с коротким ожиданием; если
занято, повтори позже. При изменении ревизии сначала прочитай новый план.

Удаляются только audio.wav и отдельные файлы frames из manifest. Сохраняются
все опубликованные/исторические материалы, исходники, прогресс, рабочие заметки,
расшифровка, checkpoint и файлы блокировок. Каталог работы не удаляется. Сумма
логических байт не гарантирует освобождение такого же места на APFS.

Перед удалением записывается payload-cleaned.json. После очистки обычный prepare
переиспользует проверенную активную публикацию; новый ASR не запускается. При
недоступной/повреждённой публикации подготовка требует восстановления либо явного
--rebuild. Если очистка прервалась после части файлов, receipt сохраняет тот же
путь продолжения; повторная очистка этой работы отклоняется, оставшиеся дубли
автоматически не удаляются. Повреждённый receipt требует явного восстановления.

cleanup-plan остаётся общим консервативным обзором, не автоматически применяемым
списком. Внешние ссылки (вне метаданных курса/например ручной путь в другом чате),
произвольные параллельные читатели и злонамеренная подмена файлов тем же пользователем
не обнаруживаются полностью. Не используй рабочие .jobs как постоянный источник
обучения: для этого нужны опубликованные пути из context. Очистка HLS/direct cache,
неполных работ, старых публикаций, кода и ученических данных не входит в эту команду.
