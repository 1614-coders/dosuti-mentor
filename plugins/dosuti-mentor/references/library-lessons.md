# Из r10 в персональный урок

Используй библиотеку только для конкретного пробела после материалов ученика и
проверки существующих unit. Если они достаточны, не вызывай поиск r10. Для готового
unit используй уже закреплённые source_contexts — не перечитывай ZIP при каждом
уроке/возвращении в чат. Путь/режимы/права — [source-library.md](source-library.md).

## Обоснованный выбор

Из уже полученных preferences, learning_progress и при необходимости diagnostic
собери кратко: подтверждённые знания, самооценку и непроверенные предпосылки отдельно.
Не запускай эти чтения второй раз, если свежие данные есть в текущем запросе.
Выбери направление/S-ID/язык материала и basic/applied/transfer по ближайшей цели.
Это фильтры, не смысловая проверка. Сопоставь конкретный scope и prerequisites с целью
и знаниями; затем теорию/формат/практику. Не выбирай основу только по A/B или бренду.

На 1–3 кандидата запиши явное решение suitable/conditional/unsuitable, основание,
статус предпосылок и небольшой план теории/практики. Confirmed здесь — записанное
суждение наставника с основанием из существующих результатов, не новая независимая
оценка программы. Не объявляй самооценку подтверждённой. При needs_check/missing
нельзя писать suitable; conditional возвращает check_prerequisites: короткая проверка
или нужное вводное объяснение перед сложной частью, без вымышленного mastery.
Unsuitable не попадает в аннотацию урока. Для полного новичка не создавай фиктивных
предпосылок: подбери вводный материал, а проверяй только действительно нужную базу.

Опциональный короткий JSON-запрос подготовки (до16KiB) в рабочей области профиля:

```json
{
  "goal":"Выбирать столбцы таблицы через SELECT",
  "gap":"Нужны вводный пример и собственная задача",
  "learner_materials_sufficient":false,
  "knowledge":{"confirmed":["Строки и столбцы проверены ранее"],"reported":[],"uncertain":[]},
  "reviews":[{
    "entry_id":"E10-001","verdict":"suitable","prerequisites":"confirmed",
    "basis":"Предыдущий самостоятельный ответ подтверждает работу со строками/столбцами",
    "theory_plan":"Один пример SELECT/FROM, без повторения знакомой базы",
    "practice_plan":"Собственная новая таблица и выбор двух столбцов без показа решения"
  }]
}
```

Передай --lesson-request REQUEST к той же команде source_library.py с направлением,
темой, уровнем и языком. Она делает один подбор только указанных в reviews входов и выдаёт компактный brief,
без повторения всего поискового ответа. Заранее отклонённые unsuitable не читаются;
если отклонены все, поиска/открытия ZIP нет вообще. Третья опора не читается заново ради последующего исключения по лимиту двух ссылок.
Если кандидаты уже есть в текущем процессе,
lesson_brief(selection, request) — чистая проекция без файлового чтения. При
learner_materials_sufficient=true ZIP вообще не открывается, даже если путь недоступен.
Без настроенной библиотеки продолжай существующий research, не блокируй урок.

## Сохранение через существующий unit

Brief — подготовка, не готовый урок и не независимая проверка пригодности. Возьми
из adaptation небольшой план объяснения и самостоятельной практики. Используй
домашку ученика первой; иначе составь собственное задание, не копируй условия/решения
тренажёра при reference_link. Сложность и помощь подбирай прежними механизмами.
Наличие practice/grader в карточке не доказывает их выполнение или правильность.

Сохрани **только reference_markdown** как UTF-8 материал с собственными
библиографическими аннотациями и добавь его в unit как существующий kind=text,
role=assistant, с точным диапазоном строк. Это аннотация r10, не текст самого сайта:
не переименовывай её в role=external и не выдавай за прочитанный первоисточник.
Рядом добавь собственный материал теории/практики, либо домашку/материалы ученика.
Порядок source_contexts не заменяет этот выбор. Не добавляй ZIP как text-источник.

Штатный unit сохранит хешированную копию в study-sources и проверит её при чтении.
В ней остаются r10/entry/source/URL, архивный SHA, даты, scope, версии, license/AI,
примечания вне YAML и историческая maintenance. Если нужен именно внешний текст,
отдельно установи права на этот объект/действие и выполни прежний research capture;
данная аннотация такого разрешения не даёт. Хеш связывает запись, не доказывает её
истинность. Новых хранилищ/типов source/миграций этот переход не требует.

Не сохраняй весь brief, knowledge или персональный basis в общий материал unit.
Они относятся к текущему ученику: используй существующий профильный lesson_context
(goal/plan) и checkpoint, а не общий текстовый снимок. Аннотация reference_markdown
не содержит полей личного запроса. Перед сохранением собственных материалов
проверь отсутствие приватных ответов/имён; произвольный авторский текст программа
не может автоматически признать обезличенным.

## Урок и продолжение

Прочитай learn-unit --compact и работай по плану текущего занятия. Покажи лишь
1–2 нужные ссылки по месту объяснения; не выгружай ученику весь brief, JSON,
лицензионный реестр и альтернативы. Важную оговорку по используемому утверждению
обозначь явно. Собственные объяснения и задачи отделяй от сведений источника.
Непроверенное/противоречивое не превращай в факт: fact_assurance сохраняется.

Максимум две опоры в reference_markdown; третья явно учитывается в omitted_count.
Если полные оговорки не помещаются в24KB или весь brief в32KB, выбери меньше
источников/контекста — не обрезай права. При смене цели/версии/ограничений повторно
проверь нужную опору; при обычном продолжении используй сохранённую копию без
нового поиска. Регистрация, explained и план практики не создают evidence освоения.
