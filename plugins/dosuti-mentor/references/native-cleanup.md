# Очистка хостовых сборок OCR —0.4.35

Отдельная утилита scripts/native_cleanup.py работает только с частным хостовым
кэшем dosuti-mentor-native-UID в системной временной папке. Корень выбирается
runtime, не файлом плана и не курсом. CLI не принимает произвольный путь к кэшу.
Это не очистка видеолекций, OCR-расшифровок, ответов или частей документов курса.

На macOS сначала получить и сохранить UTF-8 JSON-план:

```sh
PYTHON PLUGIN_ROOT/scripts/native_cleanup.py plan > PLAN.json
PYTHON PLUGIN_ROOT/scripts/native_cleanup.py apply --plan-file PLAN.json
```

Сначала показать пользователю entries/reclaimable_bytes. apply запускать по просьбе
очистить проверенный хостовый кэш, не по одному запросу посмотреть размер.
plan не создаёт папок/lock-файлов и не компилирует/запускает движок, сети нет.
На Windows/Linux возвращает unsupported_platform без попытки доступа к UID/Swift.
Для существующего кэша нужен доступный Swift toolchain, чтобы определить текущий
ключ: если его нельзя определить, очистка прекращается, а не угадывает.

План сохраняет текущую сборку. Другие сборки становятся eligible только после
сверки полного manifest/binary SHA, безопасных владельца/прав/типов файлов и
структуры каталога. По умолчанию возраст не менее7суток от более нового mtime
binary/manifest; это возраст сборки, НЕ время последнего использования.
--min-age-days принимает0..3650. Будущие даты/неполные/неизвестные файлы сохраняются.
Сканирование ограничено128каталогами, scan_complete=false означает неполный обзор.
reclaimable_bytes — сумма размеров содержимого binary+manifest, не гарантия
изменения свободного дискового пространства с учётом блоков/снимков файловой системы.

apply сверяет контрольную сумму плана, фиксированный корень и ключи, затем повторно проверяет
каждую сборку под build.lock. Текущая, занятая или изменённая со времени плана
сохраняется с причиной. Ожидания активного процесса нет. Другая версия runtime
может позже пересобрать старый движок по необходимости.

Каталог сборки и build.lock не удаляются/не заменяются: старые ожидающие процессы
должны использовать ту же блокировку. Под lock manifest атомарно переименовывается
в evicted.json, затем удаляются проверенный binary и этот маркер. Ошибка оставляет
incomplete_eviction; повтор apply с тем же планом или запуск движка0.4.35+ может
проверить/завершить операцию. Изменённый marker/binary не удаляется автоматически.
При прерванной очистке не запускай старый runtime, который не знает evicted.json:
сначала заверши её новой версией, иначе старый runtime может потребовать ручной
сверки кэша. Все версии удерживают build.lock до окончания использования binary.

Команда не удаляет посторонние содержимое, устаревший кэш с прежним префиксом
lecture-tutor-native-UID, lock-файлы или данные курса. Общая очистка частей больших
документов требует отдельной координации читателей и остаётся незавершённой.
