# Обучение по общей теме — 0.4.12

Один интерфейс работает с видео- и текстовыми unit. Сначала создаётся карточка
unit с проверенными источниками (study-units.md). Для существующей lesson без unit
остаются прежние teach-lecture, progress и resume; автоматической миграции нет.

```sh
PYTHON PLUGIN_ROOT/scripts/course.py learn-unit --course COURSE --profile USER --unit-id UNIT --session CHAT_ID
PYTHON PLUGIN_ROOT/scripts/course.py learn-unit --course COURSE --profile USER --unit-id UNIT --session CHAT_ID --event-file EVENT_JSON --expected-revision N --expected-unit-sha256 SHA
PYTHON PLUGIN_ROOT/scripts/course.py learn-unit --course COURSE --profile USER --unit-id UNIT --session CHAT_ID --checkpoint-file CHECKPOINT_JSON --expected-revision N --expected-unit-sha256 SHA
```

N — learning.revision, SHA — unit.content_sha256 из реально просмотренного
контекста до ответа/оценки. Подменять старый SHA новым без сверки нельзя. Профиль
в курсе общий для чатов, session ID разделяет точки продолжения. profiles-dir
опционально разделяет предпочтения, но не переносит журнал результатов.
Ответ содержит unit, preferences, learning_intent и learning. В последнем —
критерии, число попыток, текущих/устаревших попыток, объяснений, checkpoint и история.
При выборе профиля другой пользователь не наследует результаты первого.

`learning.topic_summary` — read-only итог для завершения диалога, не событие
«тема освоена». Он содержит outcome, номера demonstrated/unverified criteria,
число текущих/устаревших попыток и объяснений, checkpoint этой session и четыре
next_choices: practice, repeat_topic, choose_next_topic, pause. suggested_choice
не меняет маршрут или журнал. explained без ответа даёт not_assessed; все
критерии подтверждаются только актуальными самостоятельными ответами с валидным
временем evidence. Устаревшие материалы требуют review_sources. Итог не запускает
очистку и не создаёт новую оценку.

## Событие

Базовый JSON содержит stage, details, question, answer, hints, criteria.
С0.4.19 допускаются error_tags и отдельная стадия checked_later с recheck_of;
версия журналаv2 и контракт [adaptive-learning.md](adaptive-learning.md). Пример:

```json
{"stage":"solved_independently","details":"Почему решение соответствует критерию","question":"Фактическое задание","answer":"Реальный ответ ученика","hints":0,"criteria":[1]}
```

criteria — уникальные номера проверенных критериев карточки от1. Записывай только
то, что действительно проверено, а не все критерии заранее. Для ответа нужны
question/answer и непустые criteria. hints — число подсказок0–100.

- explained: answer=null, hints=0, criteria=[]; question может быть null.
  Не считается учебной попыткой или демонстрацией критерия.
- practice_with_help: ответ есть, hints>=1; критерии не считаются самостоятельными.
- solved_independently: ответ есть и hints=0; решение оценивает ассистент, а не CLI.
- needs_review: ответ есть, с вопросом и проверенными критериями; реальная ошибка
  или пробел. Изменение источника само по себе не создаёт ученику такую оценку.

Для каждого критерия действует последняя фактическая оценка текущей версии темы.
Новое объяснение её не перезаписывает. Новая попытка с помощью/ошибкой может
показать, что критерий снова требует работы. all_criteria_demonstrated=true только
когда каждый критерий имеет актуальную solved_independently либо checked_later. Не считать это
автоматическим доказательством знания: вопрос, ответ и оценку записывает ассистент.

## Точка продолжения

```json
{"recap":"Что реально разобрано","next_step":"Следующий шаг","pending_question":"Незавершённый вопрос или null"}
```

Для checkpoint нужен --session. Он не создаёт попытку или оценку. Берётся последняя
точка этой session для выбранного unit; другие чаты её не перезаписывают. Общие
попытки видны всем чатам профиля. Старый lesson/resume по-прежнему общий профильный
курсор: новые session-checkpoint относятся только к learn-unit.

## Источники, история и ограничения

События закрепляются за смысловым хешем unit. Смена карточки, источников или
устаревшая предпосылка делает старые попытки неактуальными для текущего результата,
но не удаляет их. Аналогично checkpoint.valid=false; unit.stale скрывает контекст
и запрещает новые записи. При восстановлении тех же целых оснований прежние
попытки опять относятся к той же версии. Учебная цель из intent независима:
её изменение не уничтожает ответы, но требует пересмотра маршрута.

Журнал learners/USER/unit-learning.json имеет версию, CAS и атомарную запись под
блокировкой. Тексты полей до4000 символов, criteria до50.
С0.4.20 при превышении900000 байт включается unit_learning_v3: маленький манифест
с активным хвостом и SHA256-ссылками на файлы unit-learning-segments/*.json.
Сегменты сохраняют исходные события и глобальные ревизии; recheck_of не меняется.
До256 сегментов, каждый до900000 байт; при этом пределе отказ без удаления истории.
С0.4.21 сегменты проверяются последовательно: очередь удерживает только последние
оценки/решения и checkpoints, чтение темы сохраняет историю только выбранной unit.
Все сегменты всё равно проверяются на целостность; время чтения зависит от истории.
С0.4.22 запись тоже использует последовательную проверку и компактное состояние;
в сегментированный журнал добавляется только новое событие. Счётчики выбранной темы
и история history-limit0–100 собираются за тот же проход без хранения всех её ответов.
Память зависит от размеров сегмента, активного хвоста, числа тем/версий/критериев
и сессий, а не только от количества попыток. Все сегменты читаются и проверяются;
время не стало постоянным. Прямой полный load для диагностики сохраняется.
Сегменты публикуются до атомарной замены манифеста; сбой может оставить неиспользуемый
сегмент, но прежний манифест остаётся рабочим. Не удаляйте сегменты вручную.
Чтение v1/v2 не меняет файлы; переход происходит только при явной записи и размере.
Обратная совместимость направлена вперёд: старый плагин v3 не читает.
Для переноса копируйте профиль целиком вместе с сегментами. --history-limit0–100 выводит
события выбранной темы. История может включать ответы других сессий того же профиля.
Повреждённый/неизвестный журнал сохраняется; valid=false и новые записи отклоняются.
Чтение старого профиля не создаёт файл; перенос курса сохраняет журнал и связи.

Нет автоматического оценивания ответа, компиляции или долгосрочной диагностики.
Код, домашку, reviewed ресурсы и accepted research связывай явно по study-units.md;
видео-контекст не делает все вложенные материалы зависимостями unit.
Внешние изменения файлов не блокируются ОС-публикацией всего курса: при чтении
они выявляются текущей проверкой, атомарный снимок произвольных внешних правок
не гарантируется. Старые SQLite-оценки не объединяются с этим журналом молча.

Для чтения очереди повторения используй study-next; learning.adaptive объясняет
следующий шаг и даты. Выбор skip/defer/resume сохраняется --review-file отдельно
от оценки. Подробно: [adaptive-learning.md](adaptive-learning.md).


С0.4.20 learning.evidence_time_valid отдельно сообщает о корректных временах
последних оценок текущих критериев. assessment_and_time_verified объединяет этот
признак с all_criteria_demonstrated. Последний по-прежнему описывает оценку ответа,
а не надёжность даты. При неизвестной/будущей/выходящей за диапазон расписания дате
сначала сверяйте время; такой ответ не подтверждает checked_later. Эти признаки
не являются внешней временной аттестацией или доказательством знаний.


С0.4.26 новая checked_later отклоняется и при изменении только конечной
пунктуации/Unicode-формы вопроса. Это защита от очевидного повтора, не оценка
семантической новизны: переименование переменных/перефразирование проверяет
преподаватель. Старые записи читаются по прежним правилам, их оценки и даты
автоматически не пересматриваются.
