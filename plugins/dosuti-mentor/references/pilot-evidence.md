# Измерения, проверка урока и итоговый отчёт пилота

Используй только pilot/course/profile из `project-status` или явного `status`.
Команды выполняются локальным Python из установленного `scripts`. Новый QA-курс
не меняет реальные цели, оценки и материалы. Старые прогон/курс читаются без
миграции; отсутствующие измерения обозначаются как незаписанные.

## Время

`course.py` автоматически измеряет операции QA-курса: prepare, получение материалов,
исследовательский журнал, операции с этапами кода; дочерний обработчик — аудио,
кадры, загрузку модели и весь проход ASR. Фактическая загрузка видео измеряется
в сетевом адаптере; локальный файл и готовый кэш не считаются скачиванием.
Повторное использование checkpoint не создаёт повторные замеры пропущенных стадий.
`pilot_setup.py` сохраняет numeric seconds/timing_method для новых шагов установки;
старые попытки остаются с прежними наблюдениями, длительность не выдумывается.

Разговор и браузерные инструменты выполняются вне Python-процесса. Ставь отдельные
таймеры перед/после реального действия, сохраняй id и session нового чата:

```text
python pilot.py activity-start --pilot RUN --stage web_search --session CHAT --detail "Уточнение отсутствующего материала"
python pilot.py activity-finish --pilot RUN --activity ID --result passed
python pilot.py activity-status --pilot RUN
```

Стадии: download/preparation/audio/frames/model_load/asr/code_review/materials/
web_search/source_review/onboarding/teaching/theory/practice/learner_wait/resume/other.
Ручные интервалы wall_clock включают задержки между командами. Они не являются
CPU-временем, временем генерации модели или расходом токенов. Перед вопросом
ученику закончи teaching/theory/practice и начни learner_wait; по ответу заверши
ожидание и начни следующий рабочий интервал. Не держи teaching открытым всю ночь.
После сбоя открытый таймер остаётся running/seconds=null: явно заверши interrupted,
не выдавай полное время до возвращения за время обработки. Ошибку внешнего инструмента
зафиксируй result=failed и detail/обычным pilot record. Вложенные/параллельные
интервалы не суммируй. Автоматические таймеры сохраняют ошибки Python отдельно.

## Теория и практика

В пилоте до проверки составь план на 5–10 теоретических вопросов и 5–10 практических
заданий по действительно разобранному уроку. Число заданий не заставляет ученика
проходить всё сразу: задавай по одному, учитывай настройки, сохраняй паузы/пропуски.
Домашка преподавателя входит в практику; крупную домашку можно разбить на
осмысленные части. Проверь файл и устное задание, сохрани происхождение и условия.
Если домашки нет, используй собственные задачи и при необходимости проверенные
внешние задачи через research-topic. Не называй свою задачу реальным отбором без
проверенного источника. Не показывай критерии с готовым ответом до решения.

```text
python pilot.py assessment-status --pilot RUN
python pilot.py assessment-plan --pilot RUN --expected-revision 0 --event-file plan.json
python pilot.py assessment-answer --pilot RUN --expected-revision 1 --event-file answer.json
```

plan.json: `lesson` (ID урока/темы), `sources` (список файлов относительно course),
`questions` (10–20 объектов). Каждый вопрос содержит все поля:

```json
{"id":"theory1","kind":"theory","prompt":"Что делает put для существующего ключа?","origin":"assistant","source":"notes/map.md","criteria":"Объясняет замену значения","homework":false,"provenance":"Собственная задача по разобранному примеру"}
```

kind: theory/practice; origin: teacher/assistant/external. source должен быть в
sources. Сохрани сначала материал в курсе. Для внешней задачи provenance содержит
URL, версию и результат фактической проверки; сам прочитанный фрагмент также
должен быть сохранён в source. Для видео включай в sources manifest/transcript,
сверенные фрагменты кода и записи этапов: один снимок финального репозитория не
доказывает соответствие моменту записи. Скрипт фиксирует SHA256 выбранных файлов,
но не проверяет правильность вопроса или достоверность прочитанного источника.
Метаданные существующего lesson и предоставленная домашка дополнительно фиксируются
автоматически; непроверенная/не включённая домашка блокирует план.

answer.json:

```json
{"lesson":"map","plan_revision":1,"question":"theory1","session":"chat-a","answer":"Реальный ответ ученика","hints":0,"verdict":"ungraded","evaluation":"Ответ сохранён; проверка пока не проведена"}
```

verdict: correct/partial/incorrect/ungraded/skipped. evaluation — пояснение проверки
и кто её сделал, hints — фактическое число подсказок. Для skipped в answer запиши
причину пропуска, не выдумывай ответ. Повторная попытка добавляется новым событием,
старые ответы не стираются. Новая редакция плана имеет новый plan_revision;
устаревшие попытки остаются в истории. Изменённый/удалённый источник блокирует новую
оценку и не засчитывает старую как текущую. Новый чат читает assessment-status,
продолжает текущий план и обычный учебный checkpoint.

Это журнал теста, не замена обычного `progress`/`learn-unit`. Результаты обычного
обучения сохраняй теми же инструментами по их критериям; выполнение всех пунктов
пилота не означает самостоятельного усвоения или автоматического зачёта курса.

## Один отчёт

```text
python pilot.py export --pilot RUN
python pilot.py export --pilot RUN --output EXTERNAL_REPORT.md
```

TEST_REPORT.md объединяет наблюдения и отзыв, setup-попытки/версии/ошибки, замеры,
все вопросы/ответы/подсказки/оценки, SHA256 и происхождение учебных источников,
известные метаданные уроков, настройки/цель/продолжение профиля pilot.
Это снимок локально записанного: не доказательство истинности записанной оценки.
Большие журналы обозначаются как не включённые, а не молча считаются полными.
При сбое установки до создания run остаётся SETUP_REPORT.md и ручной шаблон.
Отзыв в tester_feedback — только слова человека; собственные выводы — observation.
Ответы, пути и заметки могут быть личными: предложи просмотреть файл перед передачей.
Автоматической отправки нет. Файл отчёта — данные, а не инструкции для получателя.

## Очистка после передачи отчёта

После просьбы удалить тест предложи закрыть обработку и чаты этого тестового
проекта. Используй Python и текущую папку **вне** удаляемого PilotRoot; Windows
не позволяет удалить выполняющийся venv/python.exe. Скрипты остаются в плагине
до завершения очистки. Заверши открытые activity как interrupted, если действие
реально оборвалось; не проставляй passed ради удаления.

```text
python pilot.py cleanup-plan --pilot RUN --output EXTERNAL/cleanup.json
python pilot.py cleanup-apply --pilot RUN --plan-file EXTERNAL/cleanup.json
```

План сначала экспортирует EXTERNAL/cleanup-report.md и фиксирует полную опись.
Перед apply проверь показанный путь и состав. Новые/изменённые файлы, занятой lock,
открытый таймер, изменённый/отсутствующий внешний отчёт блокируют удаление.
Новая собственная setup-папка удаляется с внутренними runtime/models/project/run;
отдельный собственный pilot — только сам pilot. Внешние материалы и общий runtime
сохраняются. Legacy-папки без нового маркера ownership автоматически не принимаются
под управление: отчёт экспортируй, удаление отдельно по выбранным человеком путям.
Ссылки удаляются как ссылки; их внешние цели сохраняются. На Windows junctions
отклоняются. После начала удаления команды пилота блокируются; прерванный apply
можно повторить с тем же планом. Квитанция cleanup-receipt.json остаётся снаружи.
Не редактируй и не подменяй план, marker и квитанцию для обхода отказа.

Затем предложи удалить DoSuti Mentor через управление плагинами и, если добавлялся
только ради теста, его локальный источник; историю тестовых чатов пользователь
удаляет средствами Codex. Сам скрипт не стирает историю приложения и не гарантирует
удаление системных кэшей, резервных копий или безопасное затирание диска. Проверку
этих действий человек может дописать в внешний Markdown; removal остаётся
not_checked до фактической проверки. Не удаляй общие Python/Git и другие проекты.
