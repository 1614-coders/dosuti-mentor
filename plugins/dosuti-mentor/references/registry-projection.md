# Продолжение темы: память реестра 0.4.37

Внутренний study_units.load(root,include_history=False) используется при выборе
темы в learn-unit. Данные актуальных тем и глобальная revision возвращаются как
прежде; history в этом внутреннем представлении пуст. Не передавать такое
представление в запись реестра: для редактирования/экспорта по-прежнему используется
load(root) со всей историей. Публичный формат хранения не меняется.

Все SHA256/размеры частей и общий SHA256 проверяются до проекции. Проверенные
байты до64MiB удерживаются, затем потребляются/освобождаются по частям. UTF-8
декодируется инкрементально, в том числе при разрыве многобайтного символа.
Полный текст segmented реестра не собирается. json_projection.Reader передаёт
каждое вложенное значение стандартному JSONDecoder; для history вызывается
validate_history по одному элементу без удержания массива. Проверяются каждая
историческая запись/семантический хеш, число записей/revision, все текущие записи
и граф зависимостей. Для корневого объекта duplicate keys отклоняются; старые
inline JSON ограничены900000байт и предварительно читаются прежним read_json.

Это не индекс и не выборочное чтение файлов с диска. Все части по-прежнему
читаются; проверенные исходные байты сначала находятся в памяти. Большое текущее
поле units или отдельная запись требуют цельного буфера для стандартного JSONDecoder.
Повторный разбор очень больших отдельных значений на границах частей может быть
дороже; нет обещания ускорения. Обычное редактирование реестра, CLI списка тем и
другие потребители полной истории остаются на прежнем пути.

Выбор темы продолжает checked_units: сверяются исходные снимки, видеопакеты,
зависимости и ручные проверки соответствующих источников. История попыток не
обнуляется, session-checkpoints остаются отдельными, устаревший source делает
продолжение недействительным. Сопоставление кода моменту видео не объявляется
доказанным этим изменением. Проекция ничего не записывает, не создаёт lock-файлов,
не удаляет части и не создаёт оценок ученика.

Измерение benchmark.py в локальном отчёте0.4.37: два синтетических реестра
2.96/8.80МБ,80/240старых редакций,3свежих процесса на вариант. Сравнение
полного load и projected load, Python3.12 macOS arm64, tracemalloc не RSS.
Медианы peak:6.20→4.30МБ и18.30→10.15МБ, снижение31–45%; время28.3→30.1мс
и67.7→71.8мс. Это экономия памяти ценой небольшого замедления на этих данных,
не гарантия для реального курса. Первый вариант с полным текстом дал лишь3.4%
и заменён до выпуска. Windows и учебная точность этим замером не проверяются.
