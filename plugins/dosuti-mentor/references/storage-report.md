# Место на диске (0.3.9)

`storage-report --course COURSE [--max-entries 200000]` возвращает JSON без изменения
файлов курса. Группы показывают видео/скачивание, подготовленные кадры и речь,
рабочие файлы обработки, код, вложения, домашку и данные учеников. Группа определяется
по расположению: это не проверка того, нужен ли файл и можно ли его удалить.
Показываются 20 крупнейших обычных файлов относительно курса и свободное место
файловой системы. В обычный status полный обход не добавлен.

logical_bytes — сумма размеров каждого пути. Жёсткие ссылки могут повторять одни
и те же данные. unique_file_ids и allocated_file_bytes учитывают один файловый ID
один раз, если система предоставляет inode/число блоков. Выделенный объём не включает
блоки каталогов; APFS-клоны, сжатие/дедупликация, внешние жёсткие ссылки и квоты не
позволяют трактовать его как точный объём, который освободится. На системах без
st_blocks allocated_file_bytes=null. reclaimable_bytes всегда null.

Обход ограничен 1..1000000 записей, default200000. При лимите или ошибке чтения
scan_complete=false; приводятся число ошибок и не более 50 путей. Не называй такой
отчёт полным. Символические ссылки и специальные файлы пропускаются, их цели не
читаются. Это не защита от враждебной одновременной подмены каталогов тем же
пользователем. Измерение не атомарное: работающая обработка может менять размеры.

Внешние видео, shared model/runtime и другие курсы не входят в отчёт. Отсутствие
видео в группе video_cache может означать, что урок ссылается на внешний локальный
файл. Отчёт не проверяет хеши, готовность пакетов, безопасность удаления или понимание
ученика. Он не создаёт команды удаления. Перед будущей очисткой нужно отдельно
проверять активные процессы, сохранённые источники, исторические снимки и ссылки
из урока/тем/курсоров. Большие .jobs могут быть нужны для продолжения после сбоя.

Для одного большого документа доступен [отчёт по частям](document-report.md).
Он проверяет текущие байты, но также не разрешает удаление.


## Остатки после аварийного завершения (0.4.44)

`recovery_artifacts` показывает число и логический объём файлов вида
`learners/PROFILE/unit-learning.json.UUID.tmp`. Это диагностика, а не разрешение
удалить файл. Для выбранного профиля:

```sh
python scripts/course.py cleanup-progress --course COURSE --profile PROFILE
python scripts/course.py cleanup-progress --course COURSE --profile PROFILE --apply
```

Первая команда показывает кандидатов, вторая повторно проверяет и удаляет их.
Обе берут блокировки `.study-units.lock` и `unit-learning.lock` в порядке писателя.
Могут создаваться служебные lock-файлы; учебные записи при просмотре не меняются.
При занятой блокировке команда отказывает: повторить после завершения записи.
Удаляются только валидные временные unit-журналы с UUID и обычные сегменты с
верным SHA256, которых нет в действующем манифесте. Повреждённый текущий журнал
останавливает всю очистку. Непроверенный временный журнал сохраняется и блокирует
удаление сегментов, на которые он потенциально ссылается. Ссылки, жёсткие ссылки,
неизвестные имена и другие профили сохраняются. Прогресс не сбрасывается.
Обход ограничен 2000 записями на каталог. Проверка не защищает от враждебного
процесса того же пользователя, игнорирующего блокировки и подменяющего каталоги.
Общая очистка видео, моделей, иных временных файлов и всех `.jobs` сюда не входит.
