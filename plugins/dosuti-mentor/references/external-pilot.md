# Внешний тестовый прогон

CLI запускается выбранным Python runtime (Windows: venv/Scripts/python.exe).
Пути ниже — примеры, Codex подставляет фактические. Скрипт находится в scripts
установленного пакета. Подключение плагина и установка runtime предшествуют skill;
сбой до запуска записывается вручную и переносится в журнал при доступности.

```text
python pilot.py start --pilot NEW_DIRECTORY
python pilot.py status --pilot DIRECTORY
python pilot.py record --pilot DIRECTORY --expected-revision 0 --event-file event.json
python pilot.py export --pilot DIRECTORY
```

start отказывает для любой существующей папки: не используй обычный курс.
Создаёт pilot.json и отдельный course/course.json. Если инициализация оборвалась,
сохрани отчёт из существующего журнала; не переписывай папку повторным start.
status возвращает course и профиль pilot. Это локальная изоляция данных по путям,
а не песочница всех действий Codex. Обычные учебные команды не перенаправляются
автоматически: передавай эти значения явно.

Событие UTF-8 JSON, четыре обязательных поля:

```json
{"step":"environment","status":"blocked","observation":"Фактически наблюдавшаяся ошибка и действия для воспроизведения","tester_feedback":""}
```

step: installation/environment/onboarding/route/preparation/teaching/practice/
resume/feedback/removal. status: passed/failed/skipped/blocked/not_checked.
observation: основание статуса, до8000символов; tester_feedback: только полученный
от человека отзыв, до8000символов. Никогда не помещай секреты и полный текст
личных материалов. Успех — ручное наблюдение, скрипт не проверяет его истинность.
До200событий и900000байт журнала; история не перезаписывается. Ревизия из status,
конфликт требует повторного чтения и сверки. Отчёт показывает последние статусы
и полную историю правок. Пропущенное и непроверенное не считаются успехом.

export обновляет DIRECTORY/TEST_REPORT.md без сети; --output сохраняет внешний
снимок. Он объединяет установку, замеры, материалы, ответы, оценки и отзыв;
личные данные могут оказаться в отчёте. Перед передачей нужен просмотр.
Непроверенное и пропущенное не считаются успехом. Подробный контракт:
[pilot-evidence.md](pilot-evidence.md).

Очистка собственной тестовой папки выполняется отдельными cleanup-plan/cleanup-apply
после внешнего экспорта. Плагин и история чатов удаляются отдельно средствами Codex.
Общий runtime и другие курсы не удаляются. QA-оценки в обычный курс не переносятся.

## Подключённый тестовый проект0.4.40

Для подготовки окружения до журнала курса прочитай [pilot-setup.md](pilot-setup.md).

```text
python pilot.py connect-project --pilot DIRECTORY --project EMPTY_PROJECT --expected-revision 0
python pilot.py project-status --project PROJECT
```

connect-project — явное действие для нового пустого тестового проекта или проекта,
уже принадлежащего этому прогону. Не заменяет другой курс или обычные файлы проекта.
Добавляет .dosuti-pilot.json с адресом прогона и project connection с профилем pilot.
Можно передать --runtime/--model-path. Повтор с актуальной ревизией идемпотентен.
Маркер записывается первым: после сбоя соединения повтор восстанавливает подключение.

В новом чате текущего тестового проекта прочитай project-status без --pilot.
connected=true даёт run/course/profile и журнал. Учебные данные читаются обычными
командами из найденного курса, а не из контекста прежнего чата. Отключение/другой
курс имеют приоритет; при chat overrides передай --chat с известным стабильным ID.
Не выбирай один default ID для всех чатов. Переход к другой папке/другому проекту
не даёт права искать тестовые данные по всему компьютеру. После переноса всей
папки относительный маркер находит run, но абсолютную connection надо явно обновить.

Это техническая привязка, а не проверка resume: passed ставится после фактического
продолжения в новом чате и сверки сохранённых цели/настроек/плана/учебного шага.
