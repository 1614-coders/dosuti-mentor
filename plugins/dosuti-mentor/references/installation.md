# Установка из GitHub и техническая настройка

Инструкция для ассистента. Пользователь может передать ссылку на репозиторий и
попросить установить DoSuti Mentor. Это разрешение подготовить установку; необходимые
сетевые и системные действия выполняй через разрешения хоста. Учебные вопросы не задавай.

## Manifest и точки входа

Корневой `plugin.json` — основной portable manifest. `.codex-plugin/plugin.json`
сохранён для совместимости Codex; его пути также разрешаются от корня плагина,
а не от `.codex-plugin`. Оба manifest пакета 1.0.0 согласованы по версии и
точке технической настройки. Фактическую установленную версию сверяй с manifest
установленной копии и источником установки. В пакете указано
`extensions.com.openai.onboardingSkill = ./skills/setup-dosuti/SKILL.md`.
Каталог `skills/` остаётся общим для обоих форматов.

`setup-dosuti` проверяет и настраивает локальные компоненты; `start-learning`
начинает или продолжает обучение только по учебному запросу. При обновлении с
0.7.0 сохрани прежний plugin ID и marketplace, обнови весь пакет штатным способом,
проверь фактически установленную версию и доступность обоих навыков.
Не правь кеш manifest вручную и не переустанавливай учебные данные ради смены версии.
Наличие onboardingSkill — декларация действия настройки, а не доказательство,
что оно уже выполнено или что началось знакомство.

## Подключение marketplace

Проверь фактически доступный Codex CLI и его команды через --help. Существующие
источники/установки посмотри перед записью; не меняй другие плагины и не редактируй
config.toml вручную. Для CLI с поддержкой plugin используй:

```powershell
codex --version
codex plugin marketplace list
codex plugin marketplace add 1614-coders/dosuti-mentor --ref main
codex plugin add dosuti-mentor@dosuti-mentor-local
codex plugin list --json
```

dosuti-mentor-local — существующее имя marketplace в манифесте репозитория.
Его не переименовывай при переходе на GitHub. Официальный источник — только
публичный HTTPS-репозиторий и ветка main. В каталоге `.agents/plugins/marketplace.json`
пакет имеет `source: git-subdir`, URL `https://github.com/1614-coders/dosuti-mentor.git`,
`path: ./plugins/dosuti-mentor` и `ref: main`. Это отдельная привязка самого пакета:
даже каталог из develop указывает на main. Не добавляй ref к local source:
старые каталоги с `source: local` берут файлы из своей папки и сами не переключаются.
Корневой `install-dosuti.sh` и упакованный `scripts/Install-DoSuti.ps1` только настраивают runtime
из уже выбранного пакета; они не выбирают и не обновляют ветку плагина.
Для ручного ZIP/clone используй только main и проверяй происхождение пакета;
предпочтительный способ — Git marketplace по командам выше, без отдельного клонирования.
Установка публичного пакета не требует прав записи в GitHub или токена владельца.
Не запрашивай push/admin scopes, не вставляй токены в URL или конфигурацию.
Поле политики `authentication: ON_INSTALL` не даёт прав записи в репозиторий.
Codex получает Git marketplace сам. Повторный add не нужен, если нужный источник уже
настроен. Если такое же имя указывает на другой источник, остановись и обсуди замену;
не удаляй/заменяй его молча. Плагин, уже установленный в нужной версии, не переустанавливай.
Используй только команды, реально поддерживаемые --help установленного CLI.

Если команды codex нет, приложение и CLI не следует считать одним исполняемым файлом.
Не ищи его рекурсивно по диску, не копируй бинарник в проект и не устанавливай Node/CLI
молча. Предложи установить Codex CLI по официальной инструкции с разрешением
пользователя; минимальный ручной шаг — установить CLI и открыть новую сессию терминала.
Если доступен поддерживаемый интерфейс управления marketplace в приложении, можно
использовать его, но не выдумывай пункты меню. При корпоративном запрете нужен администратор.

Установка плагина не гарантирует загрузку его навыков в уже открытый чат. В CLI
после установки нужна новая сессия. В приложении проверь видимость setup/start-learning;
при необходимости предложи новый чат или перезапуск. Если setup не загружен в текущем
контексте, ассистент может прочитать установленный SKILL.md и выполнить описанные
технические шаги доступными инструментами; не утверждай, что навык уже вызван автоматически.

## Обновление установленного плагина

Обычный пользователь может передать запрос из [README](../../../README.md#как-обновить).
Официальные установка и обновление используют стабильную ветку main.
Не обещай конкретную доступную версию по тексту этого руководства: проверь источник
и manifest фактически установленного пакета. Не используй develop для официальной
установки или обновления.

1. Останови записи и обработку, сохрани [ручную копию учебных данных](#ручная-копия-учебных-данных-при-остановленных-процессах).
2. Сверь `codex plugin marketplace list`, источник и его ref. Для известного Git-
   источника dosuti-mentor-local, настроенного на main, в доступном CLI поддерживается:

   ```text
   codex plugin marketplace upgrade dosuti-mentor-local
   codex plugin list --json
   ```

   Upgrade обновляет Git-источник; это не подтверждение, что уже открытый чат
   загрузил новую копию плагина. Не используй несуществующую команду `plugin update`.
   Для локального источника сначала нужен проверенный новый пакет, а не Git upgrade.
   При чужом источнике/ref или корпоративном запрете остановись, не удаляй настройки.
3. По результату установленного пакета/штатного интерфейса установи фактический
   PLUGIN_ROOT. Сверь manifest установленной копии и новый чат; один номер в
   каталоге доступных плагинов не доказывает загрузку этой версии.
4. Повтори [настройку компонентов](#локальные-компоненты) с прежним DATA_ROOT и
   проверь результат. Если пакеты подходят, повторной установки не будет.
   При ошибке не объявляй готовность и не удаляй прежнюю рабочую среду.
5. Открой новый чат; если навыки прежние, перезапусти приложение. Затем `$start-learning`.

Команды подтверждены справкой `codex plugin ... --help` доступного клиента;
в другом клиенте сначала проверь его --help или штатное управление плагинами.
Официальный порядок Git-источников: [OpenAI Plugins](https://developers.openai.com/plugins/build/plugins).
Проверка документации/справки не является живым тестом установки или обновления.

## Переход со старого источника на main

`marketplace upgrade` обновляет настроенный Git ref, но не переводит локальный источник
или develop на main. Старые ZIP-копии и репозитории на диске тоже не меняют ветку
сами. Не обещай, что изменение каталога исправит уже сохранённую конфигурацию Codex.

1. Прочитай `codex plugin marketplace list`, проверь фактический источник и ref.
   Если вывод не показывает ref, используй доступный интерфейс/администратора для
   проверки выбранной записи, не угадывай её по имени. Сохрани прежний путь/ref
   для возврата и выясни, не задан ли источник политикой администратора или проекта.
2. Если источник другой, получи явное согласие на замену подключения. Останови
   занятия и обработку, сохрани ручную копию данных по инструкции ниже. Проверь
   DATA_ROOT и внешние курсы: не удаляй папку источника, кеш, курсы или настройки.
   Если учебные данные находятся внутри управляемого кеша источника, остановись:
   сначала нужен отдельный безопасный перенос данных. Не меняй политику администратора.
3. Только после согласования и проверки `--help` замени регистрацию источника:

   ```text
   codex plugin marketplace remove dosuti-mentor-local
   codex plugin marketplace add 1614-coders/dosuti-mentor --ref main
   codex plugin add dosuti-mentor@dosuti-mentor-local
   codex plugin list --json
   ```

   Если источник уже Git/main, remove/add не нужны: используй upgrade из раздела
   обновления. Если remove/add завершается ошибкой, остановись и сообщи состояние;
   не удаляй файлы вручную и не объявляй обновление завершённым. Исходный локальный
   каталог сохраняется для возврата; восстановление его регистрации требует согласия.
4. Перечитай список источников и установленный manifest. Проверь навыки setup/start,
   runtime через --check/--verify по инструкции ниже и открой новый чат.
   Не выдавай версию из develop за установленную из main. Сравни фактические версии
   до и после смены источника: переход на более раннюю версию может быть откатом.
   Не открывай новые данные старым плагином без проверки совместимости и ручной копии.

Это порядок смены источника, а не автоматическая миграция учебных данных.
Наличие доступа на чтение публичного кода не даёт права записи в оригинал.

## Поддержка платформ пакета 1.0.0

Windows x64/local NTFS имеет статус experimental / limited support. Установка
runtime не доказывает готовность всей обработки материалов. В контрольном CI
каждый Windows-профиль имеет 7 failures, 41 errors и 85 skipped. При ошибках
HomeSession, WorkerIO, publication или prepared/extraction останови зависимый шаг;
не удаляй staging/прогресс и не обходи отказ платформы. Нативные исправления
будут проверяться отдельно. H01 в этот пакет не включён.

Статус поддержки macOS/Linux определяется результатами релизной приёмки.
Для локальных компонентов нужен CPython 3.11/3.12. Новая среда требует
Pillow >=13.0.0,<14; старую уязвимую версию нельзя считать проверенной.
Повторная настройка исправной среды переиспользует её, устаревшие зависимости
проверяются и обновляются штатным staging-механизмом. Форматы курсов и прогресса
не меняются. При подготовке пакета (9 ноября 2026 года) живой Codex smoke test
имел статус NOT VERIFIED; актуальное подтверждение проверяй по протоколу приёмки.

## Локальные компоненты

PLUGIN_ROOT получи из результата установки/списка плагинов или штатного интерфейса.
Не фиксируй путь кеша или номер версии вручную. Все файлы ниже входят в пакет плагина.

На Windows x64 выполни с разрешением на запуск процесса и загрузку:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "PLUGIN_ROOT\scripts\Install-DoSuti.ps1"
```

Процессный ExecutionPolicy не меняет постоянную политику Windows и не преодолевает
корпоративную Group Policy. При её блокировке сообщи ограничение, не предлагай
отключать системную защиту. По умолчанию DATA_ROOT=%LOCALAPPDATA%\DoSutiMentor.
Подходящий CPython 3.11/3.12 используется повторно; иначе скачивается проверенная
приватная копия. Параметры прежние: -HomePath, -Python, -Offline.
На macOS/Linux при наличии подходящего python3:

```sh
python3 -B PLUGIN_ROOT/scripts/bootstrap.py
```

Обычная установка не создаёт курс, профиль, анкету и модели. bootstrap после
установки запускает приватный Python, проверяет обязательные версии пакетов по requirements.txt, импорты (включая
PDF) и FFmpeg; verified=true
появляется только при успехе. Проверка уже установленной среды без загрузок:

```text
PRIVATE_PYTHON -B PLUGIN_ROOT/scripts/bootstrap.py --verify --home DATA_ROOT
```

Если среда совместима, повторный bootstrap только проверяет её. При несовместимых
зависимостях он вызывает setup_local.py --if-needed: под существующей блокировкой
снова проверяет среду, затем при необходимости собирает staging и проверяет его
до переключения. Прежняя среда сохраняется как venv-previous-*; при сбое действует
существующий откат. Таймаут проверки сам по себе не запускает переустановку.
Неизвестная папка без pyvenv.cfg и незавершённый runtime не удаляются автоматически.
Параметры --check и --verify ничего не устанавливают: первый проверяет платформу,
второй — существующее окружение.

Перед обновлением пакета останови записи/обработку и сделай полную копию DATA_ROOT
и внешних курсов по [справочнику](../../../docs/technical-guide.md#совместимость-и-безопасный-откат).
Установи нужную опубликованную версию поддерживаемым интерфейсом Codex, получи
её фактический PLUGIN_ROOT и повтори установщик с прежним DATA_ROOT. Для Windows
с нестандартным хранилищем передай -HomePath, для macOS/Linux — --home.
Не запускай обновление из заменяемого приватного Python: используй подходящий
базовый CPython 3.11/3.12 (Windows-установщик выбирает его сам).

При ошибке/отказе не запускай обучение и не сообщай об успешной установке.
Покажи причину и предложи повтор после её устранения. Если переключение прервалось,
сначала проверь блокировки, прежний target и сохранённые venv-previous-*; не удаляй
их и не выбирай копию произвольно. Явный ремонт выполняй после проверки/согласования
через базовый Python: BASE_PYTHON -B PLUGIN_ROOT/scripts/setup_local.py --runtime DATA_ROOT/runtime.
Он использует тот же staging, проверку и откат; неизвестный каталог нужно сохранить.
После восстановления повтори bootstrap --verify. Наличие папки не доказывает готовность.
Откат пакета на 0.7.0 требует совместимой копии курса до обновления, а не только
возврата старого runtime.

## Ручная копия учебных данных при остановленных процессах

Автоматических команд копирования и восстановления учебных данных в плагине нет.
Не используй прежний экспериментальный инструмент для распаковки уже созданных
архивов. Сохрани такие архивы без изменений; их отдельная проверка не является
частью этой инструкции. Резервные папки runtime и штатный откат установщика —
другой механизм, они не заменяют копию учебных данных.

1. Уточни фактический DATA_ROOT по существующей конфигурации. По явно выбранным
   подключениям составь список внешних курсов, отдельных profiles_dir и нужных
   материалов вне этих папок. Не обходи чужие проекты и не угадывай пути.
   Общие настройки находятся в DATA_ROOT, настройки и прогресс курса — внутри
   курса либо явно указанной внешней папки профилей. Одна DATA_ROOT не гарантирует
   сохранения внешних данных.
2. Дождись завершения операций, закрой работающие с этими данными Codex/CLI,
   импорт, установку и редакторы. Приостанови синхронизацию выбранных папок.
   Все подключения SQLite должны быть закрыты. Если остановку записей подтвердить
   нельзя, копию сейчас не создавай; копирование работающей базы обычным файловым
   менеджером не гарантирует согласованность.
3. Вручную скопируй целиком DATA_ROOT и каждую выбранную внешнюю папку в новую
   отдельную папку, не внутри источников и не поверх прежней копии. Сохрани
   скрытые файлы, структуру, права доступа и отдельное соответствие исходных путей
   папкам копии; одноимённые внешние курсы не объединяй. Для SQLite копируй весь
   каталог, включая имеющиеся DB, -wal, -shm и -journal, независимо от имени базы.
   Не удаляй журналы, не делай VACUUM/checkpoint и не открывай оригинал на запись
   ради подготовки копии. После аварийного завершения процессов сохрани весь набор
   для отдельной проверки; не обещай его исправность только по наличию файлов.
4. До возобновления записей сравни состав и размеры файлов, по возможности SHA256
   средствами ОС. Хеш подтверждает совпадение байтов, не корректность базы.
   Сохрани оригиналы до проверки копии: при ошибке ничего в них не удаляй и
   не заменяй. Копия содержит личные ответы всех включённых профилей и не шифруется
   самим плагином; ограничь доступ средствами ОС, не клади её в общую папку.
5. Для пробного возврата или переноса используй ещё одну новую папку, сохраняя
   нетронутую резервную копию. Проверь совместимость версии, явно укажи новый
   DATA_ROOT, затем подключи выбранный курс через [connections.md](connections.md)
   с прежним профилем и новой папкой. Относительные привязки пересмотри относительно
   нового проекта; абсолютные пути старого компьютера автоматически не исправляются.
   Проверь настройки, сохранённый ответ и точку продолжения через штатный study-next.
   SQLite проверяй только на пробной копии: успешное открытие без нужных записей
   не подтверждает полноту. Не сливай копию с существующим курсом и не заменяй его.

Runtime, модели и зависимости нельзя считать переносимыми между ОС: настрой их
штатным установщиком, отдельно от проверки учебных данных. Невключённые материалы,
внешняя библиотека, ACL/владельцы другого компьютера не обещаются восстановленными.
Если состав или целостность SQLite сомнительны, остановись и сохрани все экземпляры
для проверки; не пытайся исправлять единственную копию.

## Необязательная библиотека

Библиотека r10 не устанавливается и не скачивается автоматически. Для разового
использования передай source_library.py --library с абсолютным путём к ZIP,
для окружения процесса Codex — DOSUTI_SOURCE_LIBRARY. Подробности, контрольная
сумма и ограничения — в [source-library.md](source-library.md); пользовательский
запрос и проверка результата — в [справочнике](../../../docs/technical-guide.md#необязательная-библиотека-r10).
Не меняй глобальное окружение или профиль молча. Отсутствие библиотеки не является
ошибкой установки плагина.

## Граница первого начала обучения

Только явный $start-learning разрешает создание стандартного учебного курса.
На первом вызове используй learning_start.py по start-learning.md: существующее
подключение важнее умолчания, иначе курс и профиль создаются в DATA_ROOT/courses/default.
