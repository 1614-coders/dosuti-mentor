# Старт обучения и переходы между задачами

Начни с запроса человека. Для знакомства используй восемь вопросов в порядке
ниже, по одному за раз; любой вопрос или весь опрос можно пропустить.
Не задерживай конкретно запрошенную помощь ради знакомства.

## Пустой вызов $start-learning

Для нового пользователя явный вызов без текста запускает знакомство. Не спрашивай
«Что сделать?» и не требуй прислать лекцию до выяснения цели.

Сначала прочитай подключение текущего проекта/чата и preferences. Если подключения
нет, для выбранного пользователем учебного проекта предложенное место по умолчанию —
подпапка `.dosuti-course` этого проекта. Не помещай её в установленный плагин или
распакованный исходник. Новый пустой выделенный каталог можно создать при запуске
обучения: init с нейтральным названием «Моё обучение», затем project-connect через
connection.py с прочитанной expected_revision и profile=default. Так новый чат этого
проекта использует тот же профиль. Учитывай явно отключённое подключение: не включай
его молча. Не перезаписывай существующие файлы, не инициализируй существующий курс.
Если проект неизвестен, каталог занят чужими данными или не хватает разрешений,
объясни препятствие и уточни место хранения; не обещай сохранение до успешной записи.

На Windows используй выбранный пользователем runtime; стандартный интерпретатор
после Install-DoSuti.ps1 находится в LOCALAPPDATA/DoSutiMentor/runtime/venv/Scripts/python.exe.
Для иной папки установки используй её runtime/venv/Scripts/python.exe, не запускай
установщик заново и не скачивай ASR-модель ради знакомства. Добавь runtime к binding,
чтобы следующий чат не угадывал интерпретатор. Создание/подключение выполняет ассистент
по commands.md и connections.md, пользователь не копирует эти внутренние команды.

В первом сообщении: короткое приветствие из навыка, затем **«Вопрос 1 из 8»**,
точная формулировка outcome и его варианты ниже. Заверши возможностью ответить
своими словами, пропустить вопрос или сделать паузу; не добавляй ещё один вопрос.
Когда профиль доступен и показан первый вопрос, сохрани in_progress через settings,
не создавая фиктивного ответа. Так пауза до первого ответа тоже восстановится.
Если профиль уже in_progress, приветствие заново не требуется: номер вопроса —
позиция onboarding_next в восьми вопросах, а не количество ответов плюс один.
Для complete/skipped повторный запуск использует сохранённое вместо новой анкеты.

После каждого ответа или «пропустить» сразу запиши только этот ответ/пропуск через
settings, убедись в результате записи, затем покажи следующий onboarding_next.
При «пауза» оставь in_progress и не добавляй ответов. В новом чате прочитай тот же
профиль. При «измени ответ на вопрос 4» замени только learning_format; если новый
ответ не указан — задай только этот вопрос. Остальные ответы и пропуски сохраняются.

После восьмого ответа: краткий итог и **одно предложение добровольной диагностики**
с ориентиром 10–20 вопросов и вариантами «Да», «Без диагностики», «Позже».
Это единственный следующий вопрос. Не добавляй девятый вопрос о комментарии;
необязательные дополнения можно принять в любой момент. Не записывай accept до
явного согласия. При «позже» ничего не запускай; при явном отказе запиши decline
и предложи ближайший учебный шаг без диагностики. Не спрашивай об отказанной
диагностике при каждом новом запуске. При согласии используй существующий diagnostic;
при неясной области сначала уточни её, не выдумывай компетенции.

JSON, технические пути, названия внутренних состояний и команды в этом справочнике
предназначены ассистенту. В обычном разговоре показывай вопросы и понятные результаты.

## Как выбрать ближайший шаг

| Запрос | Что выяснить, если неизвестно | Первый результат |
|---|---|---|
| «Хочу учиться» | Что хотелось бы уметь и зачем | Рабочая формулировка цели |
| Две лекции | Материалы, затруднения, желаемый результат | Подготовить запись или продолжить готовое занятие |
| Зачёт | Срок, список тем, формат проверки | Ближайший приоритетный блок и практика |
| Учебный проект | Что должно получиться, исходные знания | teach-project: небольшая задача по явным состояниям проекта |
| Профессия | Роль, стартовые знания, время, регион/компании при необходимости | Предварительный маршрут для обсуждения |
| «Найди материал по многопоточности» | Уровень/версия/вопрос, наличие поиска | research-topic: ограниченный поиск и небольшая тема с практикой либо описание ограничения |
| «Продолжим» | Сохранённая цель/план, задача сессии, актуальный курсор | Продолжение с фактического места |
| «Сегодня стримы» | Только масштаб изменения, если двусмысленен | Задача этой сессии, общая цель сохранена |

Предварительная профессия может требовать широкого обсуждения, но не обещай
трудоустройство или процент готовности. Рынок анализируй только по реально
прочитанным датированным источникам. Инструментального карьерного трека пока нет.
Материалы, которые удалось найти, ещё нужно прочитать и сверить; ссылка сама
по себе не является проверенным учебным источником. Не обходи правила курса ради
приветствия или составленного плана.

## Диагностика в целевом пути

Когда для маршрута важны исходные знания, предложи короткую добровольную проверку.
Само предложение не запускает журнал: `accept` — только после согласия, `decline` —
после явного отказа. Без диагностики можно начать учиться и предложить предварительный
маршрут с неизвестной базой. Прямой вопрос/лекция не требуют этого шага.
CLI `diagnostic`, формат событий, сложности и возобновление описаны в
[adaptive-learning.md](adaptive-learning.md). Перед продолжением прочитай профиль:
не повторяй уже сохранённые вопросы, paused возобновляй через resume. Итог —
конкретные подтверждения, места для практики и неизвестное, без общей оценки.

## Короткое знакомство и первый урок

Сначала выбери переход по запросу, а не по заполненности анкеты:

| Вход | Действие и состояние профиля |
|---|---|
| Конкретный вопрос, код или лекция при любом onboarding | Начать помощь/подготовку сразу. Не создавать intent, маршрут или диагностику без явного выбора; onboarding оставить прежним |
| «Продолжим» | Прочитать intent и фактическую точку продолжения; неизвестную сессию не выдумывать. Не запускать знакомство заново |
| Пустой $start-learning, not_asked | Приветствие и «Вопрос 1 из 8»; знакомство сохранить как in_progress |
| Цель уже сообщена без конкретной разовой задачи | Сохранить однозначно известные ответы, задать первый нерешённый вопрос с его номером; не повторять известное |
| in_progress, в том числе в новом чате | Прочитать onboarding_answers профиля, продолжить с onboarding_next; пауза сохраняет in_progress |
| Настройка завершена / явно пропущена | Сохранить complete / skipped; полное приветствие больше не повторять |
| Исправление ответа после complete/skipped | Заменить только выбранный ответ через settings; не открывать весь опрос заново |

onboarding хранится только в preferences профиля и принимает
`not_asked|in_progress|complete|skipped`. Старое отсутствие поля означает not_asked;
чтение старого профиля не требует миграции. Старые complete/skipped без ответов
не запускают анкету заново. Существующие intent/preferences могут подсказать
ответ, но не превращай предположение в сохранённый выбор. До выбора профиля
опирайся на чат и не обещай межчатное восстановление до фактической записи.

### Восемь вопросов знакомства

Порядок фиксирован. Показывай «Вопрос N из 8», один вопрос за сообщение,
варианты ниже и «Можно ответить своими словами или пропустить». Учитывай уже сообщённое.
Варианты служат ориентиром; область обучения не ограничивается программированием.
Ответы — пожелания и самооценка, не подтверждённые знания или прогресс.

1. **«Что ты хотел бы получить от нашего сотрудничества?»** (`outcome`, несколько вариантов):
   «Разбираться в отдельных темах» (`topics`), «Освоить конкретный навык» (`skill`),
   «Пройти образовательный курс» (`course`), «Освоить профессию» (`profession`),
   «Развиваться в существующей профессии» (`growth`), «Пока не определился» (`undecided`).
2. **«Какую область или тему ты хочешь изучать?»** (`subject`): свободный ответ.
3. **«Как ты оцениваешь текущий уровень знаний?»** (`self_assessment`):
   «Начинаю с нуля» (`zero`), «Знаю отдельные основы» (`basics`),
   «Есть базовые знания и небольшой опыт» (`basic_experience`),
   «Уверенно разбираюсь» (`confident`), «Имею значительный опыт» (`significant_experience`),
   «Не могу оценить уровень» (`unknown`).
4. **«Как тебе удобнее учиться?»** (`learning_format`):
   «Сначала теория, затем практика» (`theory_then_practice`),
   «Краткая теория и сразу практика» (`brief_then_practice`),
   «Сначала пример, затем объяснение» (`example_then_explanation`),
   «Обучение через задачи и проекты» (`tasks_projects`),
   «Подробный пошаговый разбор» (`step_by_step`), «Адаптивный формат» (`adaptive`).
5. **«Какую роль должен выполнять ассистент?»** (`assistant_role`):
   «Преподаватель» (`teacher`), «Наставник» (`mentor`), «Напарник» (`partner`),
   «Экзаменатор» (`examiner`), «Гибкая роль» (`flexible`).
6. **«Как часто проверять знания?»** (`check_frequency`):
   «После небольших блоков» (`each_block`), «После завершения темы» (`end`),
   «Только по запросу» (`on_request`), «Регулярно по плану» (`scheduled`),
   «Адаптивно» (`adaptive`).
7. **«Насколько подробными должны быть объяснения?»** (`explanation_detail`):
   «Краткими» (`concise`), «Сбалансированными» (`balanced`),
   «Подробными» (`detailed`), «Адаптивными» (`adaptive`).
8. **«Есть ли конкретные сроки или ограничения?»** (`constraints`, несколько вариантов и свободные детали):
   «Есть срок достижения цели» (`deadline`), «Есть определённое время на обучение» (`study_time`),
   «Уже имеются учебные материалы» (`existing_materials`),
   «Хочу учиться в свободном темпе» (`free_pace`), «Пока не определился» (`undecided`).

После восьми предложи необязательную диагностику по порядку выше. Свободное дополнение
пользователя можно сохранить как onboarding_comment без отдельного девятого вопроса;
отсутствие комментария не мешает завершению.

В существующем preferences.json рядом с `values` хранятся `onboarding_answers`:
ключи вопросов и записи `{"status":"answered","value":...}` либо
`{"status":"skipped"}`. `settings` возвращает `onboarding_pending` в указанном
порядке и первый нерешённый `onboarding_next` (null после всех восьми).
Для complete/skipped, включая старые профили без ответов, pending пуст и next=null;
обычное чтение или изменение настроек не открывает опрос заново.
Ответы сохраняются независимо от чата. Пропуск не является отрицательной оценкой.
Дефолтные style/format/level/checks не являются ответами на опрос.

Для записи создай UTF-8 JSON-файл средствами файловых инструментов:

```json
{"answers":{"outcome":["topics","skill"],"subject":"Музыка","constraints":{"selected":["study_time"],"details":"Два вечера в неделю"}},"comment":"Примеры из музыки"}
```

Все поля необязательны: передавай только реальные новые/изменённые ответы.
`outcome` — непустой массив без повторов; `constraints` — объект с `selected`
(массив без повторов) и/или непустым `details`; остальные ответы — строки из
вариантов, subject — непустой свободный текст. Текст ограничен 4000 символами.
Неизвестные вопросы, варианты, повторные/конфликтующие пропуски отклоняются до записи.

```sh
PYTHON PLUGIN_ROOT/scripts/course.py settings --course COURSE --profile USER --onboarding-file ANSWERS_JSON
PYTHON PLUGIN_ROOT/scripts/course.py settings --course COURSE --profile USER --onboarding-skip self_assessment
PYTHON PLUGIN_ROOT/scripts/course.py settings --course COURSE --profile USER --onboarding skipped
```

Можно сочетать файл с отдельными пропусками других вопросов и повторять
`--onboarding-skip`. Целый пропуск записывай отдельно: он сохраняет полученные
ответы и отмечает оставшиеся skipped. Частичное заполнение даёт in_progress;
когда все восемь отвечены/явно пропущены — complete. Старый complete читается без миграции, но новая запись
complete при нерешённых вопросах, включая все восемь, отклоняется. Пауза не завершает опрос. Редактирование конкретного ответа
тем же файлом заменяет только его; обычный settings --set/--reset сохраняет ответы.
После возврата к skipped можно изменить нужный вопрос без повторного приветствия.

Хранение ответов не меняет `values`, intent, диагностику или прогресс. Сохраняй
явную учебную цель отдельно через intent, а постоянные параметры подачи — через
существующий settings --set при осознанном соответствии. Не все новые варианты
имеют точный эквивалент старых настроек. Не подменяй adaptive/scheduled вымышленной
реализацией и не запускай опрос/запись ради прямого разового вопроса.

| Ситуация | Разумный переход |
|---|---|
| Свой курс, нужна помощь | Выяснить порядок и затруднение; запросить ближайшую лекцию и неизвестные код/домашку/ресурсы. Не требовать загрузить весь курс |
| Тема для себя, материалов нет | Уточнить исходные знания и желаемый результат; предложить небольшой урок. Поиск выполнять, когда он нужен/запрошен, с проверкой источников |
| Учебный проект | Выяснить результат проекта и опыт, выбрать посильную задачу с объяснением; готовые видео не обязательны |
| Профессия | Уточнить роль, знания и время; предложить предварительный маршрут. При наличии курса связать с ним маршрут, не заменять курс автоматически |
| «Не знаю, как лучше» | Объяснить выбор одного следующего шага и дать возможность поправить. Диагностика допустима как предложение; оценки — только по реальным ответам |
| «Сразу разбери эту лекцию» | Начать по явной задаче; недостающие настройки оставить открытыми, не запускать всю анкету |
| «Сегодня только домашка» | Изменить задачу текущего чата, сохранить общую цель и результаты |
| «Теперь хочу освоить профессию» | Обновить явную цель, пересмотреть план, сохранить прежние ответы и прогресс |

### От подготовки к обучению

До долгой обработки назови источник, фактический диапазон и действие:
«Сначала подготовлю …; затем разберём …». Показывай фактический прогресс;
не придумывай время окончания. Готовые только аудио/кадры ещё не готовы для урока.

После проверки источников сообщи кратко, какой диапазон доступен, где есть
пробелы и что будет первым учебным шагом. Если пользователь уже попросил обучать,
сразу начни первый смысловой блок в выбранном формате, без повторного «начинаем?».
Если просили только подготовить — сообщи результат, не начинай урок автоматически.
При частичной подготовке не называй готовой всю запись. Объяснение, ответ ученика
и освоение — разные события; готовность пакета не записывает учебный прогресс.
При возвращении в другом чате прочитай сохранённое, не проводи знакомство заново.

## Курс и запись договорённостей

При известном курсе используй его Python/runtime из настроек. Корень плагина —
папка двумя уровнями выше skills/start-learning; файлы курса и runtime вне пакета.
При необходимости прочитай commands.md для выбора рабочего Python и создания курса.
Для intent и разговора не нужен запуск ASR или setup_local.py. При неизвестной
папке курса можно сначала обсудить цель в чате; не утверждай, что она сохранена,
пока запись не выполнена. Перед созданием курса выбери с пользователем понятное
место данных, если оно не следует из уже известных предпочтений/рабочей папки.
Не инициализируй существующий курс заново.

```sh
PYTHON PLUGIN_ROOT/scripts/course.py intent --course COURSE --profile USER --session CHAT_ID
PYTHON PLUGIN_ROOT/scripts/course.py settings --course COURSE --profile USER
PYTHON PLUGIN_ROOT/scripts/course.py settings --course COURSE --profile USER --onboarding in_progress
PYTHON PLUGIN_ROOT/scripts/course.py intent --course COURSE --profile USER --session CHAT_ID --update-file CHANGE_JSON --reason REASON --expected-revision REV
```

CHANGE_JSON — реальный UTF-8 файл с изменением из learning-intent.md; записывай
его средствами файловых инструментов, не подставляй текст пользователя в shell.
Сохраняй только изменившееся: intent={} невалиден, повторный вход сам по себе
не должен добавлять событие. При CAS-конфликте перечитай, затем учти более свежую
договорённость, вместо слепого повтора. При valid=false сохрани повреждённый журнал
и объясни ограничение; можно продолжить разговор без ложного обещания записи.

Стабильный CHAT_ID используй из доступного контекста либо выбери slug для текущего
занятия и сохраняй его в контексте чата. Не используй один default для задач всех
чатов. Подключение курса чату/проекту теперь хранит connection.py (connections.md);
нативный ID чата автоматически не обнаруживается.
Если ID прошлой сессии неизвестен, не выдумывай её задачу; общая цель всё равно
читается без --session. SQLite-прогресс и resume отдельны от intent; общий курсор
не становится независимым курсором каждого чата только из-за отдельной задачи.

Состояние знакомства и настройки подачи хранится через settings. При паузе
in_progress сохраняется без искусственного complete или skipped. skipped не означает запрет
позже задать вопрос. Если пользователь просит вернуться, прочитай настройки и
обсуди недостающее/новое; complete записывай после фактически завершённой настройки,
не по одному лишь выбору цели. Уровень по умолчанию не представляй как диагностику.

## Что реально доступно

Плагин готовит видео, связывает код/домашку/ресурсы, даёт доказательный контекст
и хранит настройки, прогресс, цели и планы. Codex объясняет, задаёт вопросы,
проверяет решения и может обсуждать проект/профессию. Наличие поиска определяется
инструментами текущего чата. Специализированный подбор курса из интернета, анализ
рынка, автоматическая адаптивная программа и автоматическое восстановление развития проекта —
следующие этапы. Не рекламируй их как готовую локальную автоматизацию.

Навык доступен через явный $start-learning и обычное распознавание подходящего
запроса, если клиент поддерживает навыки. Манифест объявляет его onboardingSkill;
это точка входа при запуске настройки, не процесс, начинающий работать сразу после
скачивания. Фактический UI установки/настройки зависит от клиента; универсальное
автоматическое приветствие при открытии любого чата не заявляется.
