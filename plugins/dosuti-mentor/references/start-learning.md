# Старт обучения и переходы между задачами

Начни с запроса человека. Для знакомства используй восемь вопросов в порядке
ниже, по одному за раз; любой вопрос или весь опрос можно пропустить.
Не задерживай конкретно запрошенную помощь ради знакомства.

## Пустой вызов $start-learning

Для нового пользователя явный вызов без текста запускает знакомство. Не спрашивай
«Что сделать?» и не требуй прислать лекцию до выяснения цели.

Техническая настройка выполняется отдельно через setup-dosuti; установка сама не
запускает обучение. На явном $start-learning используй выбранный проверенный Python:

```text
PRIVATE_PYTHON -B PLUGIN_ROOT/scripts/learning_start.py --project PROJECT --chat CHAT_ID
```

Если чат без проекта, опусти --project. Существующий явный выбор курса используй
без автозамены; для известной нестандартной установки передай --home DATA_ROOT.
Помощник сначала читает подключение текущего проекта/чата. При отсутствии выбора
он использует управляемый дом платформы и создаёт courses/default и learners/default
только при первом начале обучения. Не спрашивай, где хранить курс: на Windows
по умолчанию это %LOCALAPPDATA%/DoSutiMentor. Подключение умолчания сохраняется в
этом доме через существующий формат connections; текущий проект не изменяется.
Так другие чаты и проекты без собственного подключения используют тот же профиль.
Явные отключения, старые подключения и недоступный курс не подменяются умолчанием.
При needs_chat_id=true сначала выясни ID; не присваивай всем чатам один session.
Если enabled=false или course_status не available, объясни причину и не начинай
анкету с обещанием сохранения. Неизвестная непустая папка и повреждённые данные
сохраняются; в исключительной ситуации уточни дальнейшее действие.
Отсутствие управляемого дома означает незавершённую техническую настройку;
используй setup-dosuti, не скачивай среду или модель молча ради приветствия.

На Windows используй проверенный runtime; стандартный интерпретатор
после Install-DoSuti.ps1 находится в LOCALAPPDATA/DoSutiMentor/runtime/venv/Scripts/python.exe.
Для иной папки установки используй её runtime/venv/Scripts/python.exe, не запускай
установщик заново и не скачивай ASR-модель ради знакомства. learning_start сохраняет
runtime в стандартном binding; существующие runtime/model_path/profiles_dir не меняет.
Создание/подключение выполняет ассистент, пользователь не копирует внутренние команды.

В первом сообщении: дословное приветствие из onboarding_message, затем **«Вопрос 1 из 8»**,
точная формулировка outcome и его варианты ниже. Заверши возможностью ответить
своими словами, пропустить вопрос или сделать паузу; не добавляй ещё один вопрос.
Когда профиль доступен и показан первый вопрос, сохрани in_progress через settings,
не создавая фиктивного ответа. Так пауза до первого ответа тоже восстановится.
Если профиль уже in_progress, приветствие заново не требуется: номер вопроса —
позиция onboarding_next в восьми вопросах, а не количество ответов плюс один.
Для complete/skipped повторный запуск использует сохранённое вместо новой анкеты.

После каждого ответа или «пропустить» сразу запиши только этот ответ/пропуск через
settings, убедись в результате записи, затем покажи следующий onboarding_next.
При «пауза» оставь in_progress и не добавляй ответов. В новом чате прочитай тот же
профиль. При «измени ответ на вопрос 4» замени только learning_format; если новый
ответ не указан — задай только этот вопрос. Остальные ответы и пропуски сохраняются.

После восьмого ответа прочитай diagnostic: уже начатую проверку продолжай,
завершённую не повторяй. Переход от её итогов к маршруту и уроку описан в
[learning-cycle.md](learning-cycle.md).
Если проверки ещё нет: краткий итог и **одно предложение добровольной диагностики**
из 15 вопросов для полной новой попытки и вариантами «Да», «Без диагностики», «Позже».
Можно пропускать вопросы, сделать паузу или закончить раньше.
Это единственный следующий вопрос. Не добавляй девятый вопрос о комментарии;
необязательные дополнения можно принять в любой момент. Не записывай accept до
явного согласия. При «позже» ничего не запускай; при явном отказе запиши decline
и предложи ближайший учебный шаг без диагностики. Не спрашивай об отказанной
диагностике при каждом новом запуске. При согласии используй существующий diagnostic;
при неясной области сначала уточни её, не выдумывай компетенции.

JSON, технические пути, названия внутренних состояний и команды в этом справочнике
предназначены ассистенту. В обычном разговоре показывай вопросы и понятные результаты.

## Как выбрать ближайший шаг

| Запрос | Что выяснить, если неизвестно | Первый результат |
|---|---|---|
| «Хочу учиться» | Что хотелось бы уметь и зачем | Рабочая формулировка цели |
| Две лекции | Материалы, затруднения, желаемый результат | Подготовить запись или продолжить готовое занятие |
| Зачёт | Срок, список тем, формат проверки | Ближайший приоритетный блок и практика |
| Учебный проект | Что должно получиться, исходные знания | teach-project: небольшая задача по явным состояниям проекта |
| Профессия | Роль, стартовые знания, время, регион/компании при необходимости | Предварительный маршрут для обсуждения |
| «Найди материал по многопоточности» | Уровень/версия/вопрос, наличие поиска | research-topic: ограниченный поиск и небольшая тема с практикой либо описание ограничения |
| «Продолжим» | Сохранённая цель/план, задача сессии, актуальный курсор | Продолжение с фактического места |
| «Сегодня стримы» | Только масштаб изменения, если двусмысленен | Задача этой сессии, общая цель сохранена |

Предварительная профессия может требовать широкого обсуждения, но не обещай
трудоустройство или процент готовности. Рынок анализируй только по реально
прочитанным датированным источникам. Инструментального карьерного трека пока нет.
Материалы, которые удалось найти, ещё нужно прочитать и сверить; ссылка сама
по себе не является проверенным учебным источником. Не обходи правила курса ради
приветствия или составленного плана.

## Диагностика в целевом пути

Когда для маршрута важны исходные знания, предложи короткую добровольную проверку.
Само предложение не запускает журнал: `accept` — только после согласия, `decline` —
после явного отказа. Без диагностики можно начать учиться и предложить предварительный
маршрут с неизвестной базой. Прямой вопрос/лекция не требуют этого шага.
CLI `diagnostic`, формат событий, сложности и возобновление описаны в
[adaptive-learning.md](adaptive-learning.md). Перед продолжением прочитай профиль:
не повторяй уже сохранённые вопросы, paused возобновляй через resume. Итог —
конкретные подтверждения, места для практики и неизвестное, без общей оценки.

## Короткое знакомство и первый урок

Сначала выбери переход по запросу, а не по заполненности анкеты:

| Вход | Действие и состояние профиля |
|---|---|
| Конкретный вопрос, код или лекция при любом onboarding | Начать помощь/подготовку сразу. Не создавать intent, маршрут или диагностику без явного выбора; onboarding оставить прежним |
| «Продолжим» | Прочитать intent и фактическую точку продолжения; неизвестную сессию не выдумывать. Не запускать знакомство заново |
| Пустой $start-learning, not_asked | Приветствие и «Вопрос 1 из 8»; знакомство сохранить как in_progress |
| Цель уже сообщена без конкретной разовой задачи | Сохранить однозначно известные ответы, задать первый нерешённый вопрос с его номером; не повторять известное |
| in_progress, в том числе в новом чате | Прочитать onboarding_answers профиля, продолжить с onboarding_next; пауза сохраняет in_progress |
| Настройка завершена / явно пропущена | Сохранить complete / skipped; полное приветствие больше не повторять |
| Исправление ответа после complete/skipped | Заменить только выбранный ответ через settings; не открывать весь опрос заново |

onboarding хранится только в preferences профиля и принимает
`not_asked|in_progress|complete|skipped`. Старое отсутствие поля означает not_asked;
чтение старого профиля не требует миграции. Старые complete/skipped без ответов
не запускают анкету заново. Существующие intent/preferences могут подсказать
ответ, но не превращай предположение в сохранённый выбор. До выбора профиля
опирайся на чат и не обещай межчатное восстановление до фактической записи.

### Восемь вопросов знакомства

Точные утверждённые приветствие, вопросы и пронумерованные варианты находятся в
[onboarding-dialog.md](onboarding-dialog.md). Не пересказывай их своими словами.
settings/preferences возвращает `onboarding_message` для дословного показа:
на первом not_asked это приветствие вместе с вопросом 1, позже — только текущий
вопрос. Сохрани текст первого чтения перед записью in_progress, чтобы приветствие
не потерялось при повторном чтении. Не выводи сам JSON ответа инструмента.
Эмодзи допустимы только в приветствии, не в вопросах/вариантах.

Порядок канонических ключей прежний: outcome, subject, self_assessment,
learning_format, assistant_role, check_frequency, explanation_detail, constraints.
Номера вариантов относятся к ТЕКУЩЕМУ вопросу. Для 1 и 8 допускаются несколько
вариантов; в других вопросах сочетание допустимо, если смысл понятен. Не требуй
выбрать ближайший вариант вместо сохранения собственного ответа. При существенной
неоднозначности уточни только её в рамках того же номера.

#### Уточнение области — всё ещё вопрос 2

При выборе широкой области сохрани известное сразу: value с областью, text с
фактической репликой, area с известной областью, pending=true. Поле area для выбора
из списка — точная формулировка выбранного варианта (например «Программирование и
разработка.»). Статус записи становится clarifying, onboarding_next остаётся subject.
Покажи одно уточнение с вариантами из onboarding-dialog.md. Можно ответить свободно.
Подбирай варианты по известной области; незнакомую область не превращай в программирование.

Узнав направление, запиши subject с value/направлением, direction, text с новой
репликой и без pending=true. Известная area и предыдущий text незавершённого
уточнения сохраняются при дополнении. Не объявляй частичный ответ завершённым
до конкретизации или явного отказа уточнять. Если пользователь уже сказал «Java
Backend», сразу сохрани конкретное направление и перейди к вопросу 3 — повторное
уточнение не требуется. Понимание свободного ответа выполняет наставник, не
автоматический классификатор по ключевым словам.

При «не хочу уточнять» сохрани известные область/текст с pending=false и переходи
дальше; это не ошибка и не незнание. При «не определился» помоги выбрать небольшой
пробный интерес, без требования окончательной профессии. Явный «Пропустить вопрос»
допускает skipped; не путай его с отказом конкретизировать уже известную область.
Уточнения не увеличивают восемь основных вопросов. В вопросе 8 можно уточнить
недостающие дату, часы или материалы; не требуй загружать весь курс сразу.

#### Сохранение без потери свободного ответа

В существующем preferences.json записи legacy `{"status":"answered","value":...}`
и `{"status":"skipped"}` продолжают читаться. Для новых свободных и смешанных
ответов используй тот же --onboarding-file, расширенную форму значений answers:

```json
{"answers":{"assistant_role":{"value":"mentor","text":"2, но не решай за меня"},"explanation_detail":{"text":"Сначала схема, затем контрпример"},"constraints":{"value":{"selected":["study_time"],"details":"По вечерам"},"text":"2 — по часу во вторник и пятницу"}}}
```

value сохраняет прежние канонические варианты. Если точного соответствия нет,
не придумывай его: value=null (или опусти его во входном файле), text — фактический
ответ. Для сочетания нескольких фиксированных вариантов value может быть массивом.
Для outcome массив остаётся прежним; constraints сохраняет selected/details.
Не подменяй пользовательский текст комментарием ассистента и не записывай
выдуманные ответы. Сохраняй text также при ответе номером/номерами и дополнении.

Пример незавершённого вопроса 2:

```json
{"answers":{"subject":{"value":"Программирование и разработка.","area":"Программирование и разработка.","text":"1","pending":true}}}
```

После уточнения:

```json
{"answers":{"subject":{"value":"Java Backend","direction":"Java Backend","text":"Хочу Java Backend"}}}
```

В сохранённой записи status=answered или clarifying, value, необязательные
text/area/direction; pending — только флаг входного обновления. text/area/direction
ограничены 4000 символами: превышение отклоняется, текст не обрезается молча.
Для вопроса 2 текст уточнения присоединяется к фактическому предыдущему ответу через перевод строки.
Область сохраняется, если новая реплика не меняет её явно. Это дополнение текущего
ответа, а не параллельная история/система настроек. Для полностью нового ответа
не добавляй pending=true без причины.

```sh
PRIVATE_PYTHON -B PLUGIN_ROOT/scripts/course.py settings --course COURSE --profile USER --onboarding-file ANSWERS_JSON
PRIVATE_PYTHON -B PLUGIN_ROOT/scripts/course.py settings --course COURSE --profile USER --onboarding-skip self_assessment
```

Все ключи обновления необязательны; передавай только фактические изменения.
Редактирование одного ответа сохраняет остальные; обычные --set/--reset не стирают
onboarding_answers. Старые complete/skipped без записей не запускают новую анкету.
При отдельном изменении незавершённое уточнение показывай по onboarding_next,
не повторяй остальные вопросы. Пауза и чтение не создают ответа или оценки.

После восьми ответов/пропусков — предложение добровольной диагностики по порядку
выше, без девятого вопроса. Старый onboarding_comment по-прежнему читается, но
свободные ответы теперь сохраняются в записи именно своего вопроса.
Ни хранение ответов, ни самооценка не меняют values/intent/оценки автоматически.
Для обучения читай text вместе с value, area/direction; умолчание effective не
является основанием проигнорировать явный свободный выбор ученика.

#### Начало диагностики по сохранённым ответам

До согласия читай diagnostic без записи. starting_guidance содержит предмет,
специализацию, самооценку, outcome и сохранённую intent.goal; это основания выбора
ПЕРВОГО вопроса НОВОЙ попытки, не проверенные знания. При ещё не сохранённой ясной
цели запиши её существующим intent, не придумывай цель из пропусков.

Таблица начальной сложности:

| Самооценка | Начало | Предметная подача |
|---|---|---|
| zero | basic | Простая базовая задача |
| basics | basic | Основы и начальное применение |
| basic_experience | applied | Практическое применение |
| confident | applied | Прикладная задача повышенной сложности |
| significant_experience | transfer | Сложная практика, анализ и перенос |
| unknown / собственная оценка без точного соответствия / пропуск | difficulty=null, calibration=true | Наставник выбирает предметную калибровочную задачу, без присвоения уровня |

Фактический текст self_assessment читай вместе с value, subject.area/direction и
целью: названные пробелы задают предмет первого задания. Понятную самооценку
интерпретирует наставник и сохраняет существующий value рядом с неизменным text;
скрипт не определяет уровень регулярными выражениями или по количеству лет.
Примеры: «только начинаю Java» → zero/basic; «применяю коллекции и ООП, но сложные
задачи трудны» → basic_experience/applied либо калибровка при недостатке контекста.
Заявленная работа Java Backend и интерес к многопоточности/архитектуре требуют
предметной задачи, а не определения переменных. Стаж не подтверждает знания.

По согласию передай accept с компетенциями и question_policy="fixed_15_v1".
Это явный маркер новой попытки с бюджетом 15; старые попытки без него не меняются.
Используй current.question_budget для номера и остатка: покажи «Вопрос N из 15».
Сохранённый prompt уже расходует слот; ответ, пропуск и пауза не расходуют второй.
При возвращении покажи прежний pending_prompt с прежним номером. После ответа или
пропуска вопроса 15 status автоматически completed; дополнительный complete не нужен.
Досрочное завершение через complete разрешено и не выдумывает ответ на ожидающий вопрос.

Если starting_guidance.difficulty
задан, next_difficulty можно опустить: CLI подставит его в обычный accept
diagnostic_learning_v1. При difficulty=null/next_action=
interpret_text_or_select_subject_calibration автоматической подстановки нет:
сначала интерпретируй сохранённый текст, если он однозначен, или выбери предметную
калибровочную задачу с явным next_difficulty basic/applied/transfer. Обоснуй выбор
в существующем reason, не называй сложность задания подтверждённым уровнем ученика.
Незнакомый предмет уточни; не выбирай базовые определения только из-за неопределённости.
Отказ от диагностики по-прежнему не требует выбора сложности.
Старые клиенты с явным next_difficulty поддерживаются, но не выбирай basic по
умолчанию вопреки продвинутой самооценке. После accept используй именно сохранённый
current.next_difficulty; начальная подсказка не перезаписывает активную проверку.
В paused/accepted продолжай сохранённую попытку, не делай новый accept.

Формулировку предметного задания выбирает наставник по теме, специализации и цели.
Для продвинутой Java: анализ изменяемого ключа HashMap, нарушения equals/hashCode
и исправления конструкции, а не «Что такое переменная?». Для новичка Java допустима
простая трассировка присваивания. Это примеры сложности, не фиксированный банк задач.
Если предмет неизвестен, уточни интересующую область до предметной диагностики.

Для новой адаптивной диагностики добавь selection_policy="adaptive_v1" к accept
с fixed_15_v1. Перед следующим вопросом читай selection_guidance: результат и помощь,
конкретные критерии, цель, охват компетенций и оставшийся бюджет. Подробная политика
в разделе «Выбор следующего задания» adaptive-learning.md. Код проверяет точные
повторы и четвёртый подряд вопрос при наличии другой непроверенной темы; смысловую
задачу, важность для цели и сложность выбирает наставник. Insufficient требует
уточнения, а не вывода о незнании. Сохраняй обоснование через selection_reason.

Перед новым заданием зафиксируй rubric в prompt, затем оцени фактический answer
через assessment: correct/partial/incorrect/insufficient, решения по критериям,
помощь independent/assisted/unknown, способ проверки и ограничения. Полный контракт —
в разделе «Структурированная оценка одного ответа» adaptive-learning.md. Оценка
относится к конкретному вопросу; не выводи из неё освоение всей компетенции.
Критерии не дописывай после ответа. Старые записи без rubric/assessment не мигрируй.
Итоговая summary.competence_map учитывает все ответы текущей попытки, точные критерии,
сложность и помощь; insufficient/legacy unknown означают недостаток данных, не пробел.
Объясни scope, confirmed_levels, противоречия и ограничения досрочного завершения.
По карте и сохранённой цели предложи персональный intent.proposal с фактическими
основаниями; accept_proposal — только после согласия пользователя. Подробная политика
в разделе «Итоговая карта и предложение учебного маршрута» adaptive-learning.md.
Не предлагай учить подтверждённый объём заново без конкретной причины.

Ошибка продвинутого ученика не означает, что он ничего не знает: сначала проверь
конкретный пробел, при необходимости снижай сложность и проверяй предпосылки.
Сохраняй фактические evidence/next_difficulty/next_competence/selection_reason.
Самооценка никогда не создаёт confirmed или освоенные критерии. Отказ от проверки
не блокирует обучение; интерфейс оценки, pause/resume/complete и CAS прежние.

| Ситуация | Разумный переход |
|---|---|
| Свой курс, нужна помощь | Выяснить порядок и затруднение; запросить ближайшую лекцию и неизвестные код/домашку/ресурсы. Не требовать загрузить весь курс |
| Тема для себя, материалов нет | Уточнить исходные знания и желаемый результат; предложить небольшой урок. Поиск выполнять, когда он нужен/запрошен, с проверкой источников |
| Учебный проект | Выяснить результат проекта и опыт, выбрать посильную задачу с объяснением; готовые видео не обязательны |
| Профессия | Уточнить роль, знания и время; предложить предварительный маршрут. При наличии курса связать с ним маршрут, не заменять курс автоматически |
| «Не знаю, как лучше» | Объяснить выбор одного следующего шага и дать возможность поправить. Диагностика допустима как предложение; оценки — только по реальным ответам |
| «Сразу разбери эту лекцию» | Начать по явной задаче; недостающие настройки оставить открытыми, не запускать всю анкету |
| «Сегодня только домашка» | Изменить задачу текущего чата, сохранить общую цель и результаты |
| «Теперь хочу освоить профессию» | Обновить явную цель, пересмотреть план, сохранить прежние ответы и прогресс |

### От подготовки к обучению

До долгой обработки назови источник, фактический диапазон и действие:
«Сначала подготовлю …; затем разберём …». Показывай фактический прогресс;
не придумывай время окончания. Готовые только аудио/кадры ещё не готовы для урока.

После проверки источников сообщи кратко, какой диапазон доступен, где есть
пробелы и что будет первым учебным шагом. Если пользователь уже попросил обучать,
сразу начни первый смысловой блок в выбранном формате, без повторного «начинаем?».
Если просили только подготовить — сообщи результат, не начинай урок автоматически.
При частичной подготовке не называй готовой всю запись. Объяснение, ответ ученика
и освоение — разные события; готовность пакета не записывает учебный прогресс.
При возвращении в другом чате прочитай сохранённое, не проводи знакомство заново.

## Курс и запись договорённостей

При известном курсе используй его Python/runtime из настроек. Корень плагина —
папка двумя уровнями выше skills/start-learning; файлы курса и runtime вне пакета.
При необходимости прочитай commands.md для выбора рабочего Python и создания курса.
Для intent и разговора не нужен запуск ASR или setup_local.py. При неизвестной
папке курса можно сначала обсудить цель в чате; не утверждай, что она сохранена,
пока запись не выполнена. Для нового стандартного курса используй существующий learning_start.py и
управляемое хранилище по умолчанию; обычный запуск не требует вопроса о папке.
Не инициализируй существующий курс заново.

```sh
PYTHON PLUGIN_ROOT/scripts/course.py intent --course COURSE --profile USER --session CHAT_ID
PYTHON PLUGIN_ROOT/scripts/course.py settings --course COURSE --profile USER
PYTHON PLUGIN_ROOT/scripts/course.py settings --course COURSE --profile USER --onboarding in_progress
PYTHON PLUGIN_ROOT/scripts/course.py intent --course COURSE --profile USER --session CHAT_ID --update-file CHANGE_JSON --reason REASON --expected-revision REV
```

CHANGE_JSON — реальный UTF-8 файл с изменением из learning-intent.md; записывай
его средствами файловых инструментов, не подставляй текст пользователя в shell.
Сохраняй только изменившееся: intent={} невалиден, повторный вход сам по себе
не должен добавлять событие. При CAS-конфликте перечитай, затем учти более свежую
договорённость, вместо слепого повтора. При valid=false сохрани повреждённый журнал
и объясни ограничение; можно продолжить разговор без ложного обещания записи.

Стабильный CHAT_ID используй из доступного контекста либо выбери slug для текущего
занятия и сохраняй его в контексте чата. Не используй один default для задач всех
чатов. Подключение курса чату/проекту теперь хранит connection.py (connections.md);
нативный ID чата автоматически не обнаруживается.
Если ID прошлой сессии неизвестен, не выдумывай её задачу; общая цель всё равно
читается без --session. SQLite-прогресс и resume отдельны от intent; общий курсор
не становится независимым курсором каждого чата только из-за отдельной задачи.

Состояние знакомства и настройки подачи хранится через settings. При паузе
in_progress сохраняется без искусственного complete или skipped. skipped не означает запрет
позже задать вопрос. Если пользователь просит вернуться, прочитай настройки и
обсуди недостающее/новое; complete записывай после фактически завершённой настройки,
не по одному лишь выбору цели. Уровень по умолчанию не представляй как диагностику.

## Что реально доступно

Плагин готовит видео, связывает код/домашку/ресурсы, даёт доказательный контекст
и хранит настройки, прогресс, цели и планы. Codex объясняет, задаёт вопросы,
проверяет решения и может обсуждать проект/профессию. Наличие поиска определяется
инструментами текущего чата. Специализированный подбор курса из интернета, анализ
рынка, автоматическая адаптивная программа и автоматическое восстановление развития проекта —
следующие этапы. Не рекламируй их как готовую локальную автоматизацию.

Навык доступен через явный $start-learning и обычное распознавание подходящего
запроса, если клиент поддерживает навыки. Манифест объявляет его onboardingSkill;
это точка входа при запуске настройки, не процесс, начинающий работать сразу после
скачивания. Фактический UI установки/настройки зависит от клиента; универсальное
автоматическое приветствие при открытии любого чата не заявляется.
