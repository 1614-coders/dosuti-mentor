# Учиться через проект — 0.4.18, этапы 5B/5C

История хранится в project-timeline, учебная задача — unit с целями/критериями,
ответы/продолжение — learn-unit. Новый teach-project связывает эти инструменты,
не вводя второй журнал оценок или автоматическую сборку чужого проекта.

## Конкретный переход как источник

В sources карточки unit:

```json
{"kind":"timeline","timeline_id":"backend-project","track_id":"application","before":"first","after":"second","stages":{"before":null,"after":"save-metadata"},"role":"teacher","notes":"Порядок подтверждён приложенными материалами; экранный этап проверен только для конца перехода"}
```

before/after — соседние шаги выбранной линии в указанном порядке; перескочить
вставленный шаг нельзя. stages всегда содержит before/after: null либо ID code-stage
соответствующего занятия. lesson не задаётся: он берётся из шага, как и репозиторий
и версия. Снимок этапа/файл должны принадлежать выбранному концу перехода.
Генерируемый evidence_sha256 не указывай во входе.

Закрепляются заголовок/сомнения серии, название линии, оба шага и содержание/пересечения
привязанных этапов видео. Новая идентичная запись серии, добавление несвязанной линии
или шага после выбранной пары не меняют основание. Вставка между before/after,
смена порядка/заметок/версии/gap, правка stage/его кадров или порча снимка требуют
сверки. Это распространяется на unit и зависимые темы/попытки/checkpoints; ответы
сохраняются историей. Восстановление тех же оснований возвращает актуальность.

Контекст содержит endpoints с конкретными шагами/historical/lecture_match/stage,
comparison observed либо gap, uncertainties и continuous_video_evolution_verified=false.
Даже два matches не доказывают непрерывность записи или причину изменения.
Stage partial/differs/unknown не преобразуется в matches; пересечения сохраняются.
Повреждённое основание скрывает весь unit-контекст и запрещает новые оценки.

Связь относится только к выбранной паре. Повреждение несвязанного снимка другой
линии не мешает ей, но целостность общего реестра аннотаций проверяется целиком.
Управляемые записи timeline сериализованы с unit/learn-unit через .study-units.lock
перед .project-timelines.lock. Прикрепления к lesson/правки stage и внешних файлов
имеют свою синхронизацию; атомарного снимка всех файлов курса нет.

Stage закрепляет аннотацию и выбранные кадры, а не всю расшифровку. Если объяснение
опирается на речь/пакет ASR, добавь отдельный kind=video с нужным диапазоном. Иначе
обновление неиспользуемой расшифровки не является зависимостью этого перехода.
Непривязанные вложения не становятся основаниями unit автоматически.

## Материал и практика

Для объяснения кода добавь отдельные источники kind=code по
[study-units.md](study-units.md): конкретный lesson/repository/version/file и строки.
У перехода нет автоматического полного текстового diff; truncated/counts честно
показывают пределы. Читай нужные файлы выбранных снимков, не последнюю рабочую папку.
Для исторического примера предпочтителен content_sha256; current означает явное
отслеживание текущего прикрепления, не состояние, обязательно показанное в видео.

Собственный assistant-текст должен содержать небольшую цель, объяснение фактических
изменений, конкретный код примера, практику, критерии и статус проверки сборки.
Возможную мотивацию обозначай гипотезой, если речь/материалы её не подтверждают.
Не прячь решение в выдаваемом ученику задании; показывай его после попытки или по
явной просьбе, не засчитывая как самостоятельное выполнение.

Пример практики: по сохранённым состояниям счётчика исправить накопление значения
при повторном ключе, проверить несколько ключей и отсутствие ключа. Критерии:
объяснить изменившееся поведение; реализовать и проверить свежую вариацию самому.
Факт работающего HashMap-примера не доказывает знание всего проекта или авторской
мотивации. При реальной домашке преподавателя сохраняй её текст отдельным homework
и проверь покрытие критериев вместо выдуманной замены.

Код ученика находится в отдельной выбранной папке. Sealed-снимки преподавателя
не редактируются. Статический разбор/фактическая компиляция/запуск — разные свидетельства.
Правила исполняемых примеров: [research-lesson.md](research-lesson.md).
Оценка только по ответу, через [unit-learning.md](unit-learning.md).

## Совместимость и ограничения

Старые unit без timeline, старый project-map/diff-code и SQLite-прогресс сохраняют
семантику. Создание серии само по себе не меняет результат ученика: нужна явная
зависимость kind=timeline. Без неё текстовая копия остаётся независимой.
Перенос курса сохраняет ID/хеши и журнал; старым урокам нужен make-portable.

Нет автоматического доказательства общей идентичности проекта, причин изменения,
контрольного потока или отсутствия пропуска записи. Нет сопоставления переименований
с изменённым содержимым. Нет автоматической оценки/сборки и отдельного сервиса задач.
Навыки — инструкции текущей модели; их валидация не доказывает качество преподавания.
