# Подготовка урока из исследования — 0.4.16

Диалог ведёт research-topic, хранение источников — research, обучение — teach-unit.
CLI не генерирует урок сам: качество отбора, объяснения и проверки оценивает Codex.
Здесь контракт подготовки, не новая схема или автоматический компилятор курсов.

## Небольшой результат

Сформулируй наблюдаемое умение: например, «выбрать orElseGet для отложенного
получения значения по умолчанию», а не «полностью освоить Optional».
Укажи предпосылки/версию; не делай самооценку ученика проверенным фактом.
Найди достаточный фрагмент для каждого ключевого утверждения. Если источники
не покрывают существенную часть, сузь урок или сохрани пробел как uncertainties.
Не скрывай противоречие за связным текстом summary.

В папке выбранного курса сохрани UTF-8 материал ассистента, например
learning-materials/optional-defaults.md. Практика и примеры — собственные, если
преподаватель их не предоставил. Полезное содержание:

- Узкая цель, версия, границы и необходимые предварительные знания.
- Порядок двух-трёх небольших объяснений со ссылками на research_id/source_id/строки.
- Собственный пример кода и ожидаемое поведение; что проверено и какой средой.
- Задание ученику и критерии результата; подсказки по необходимости.
- Оставшиеся вопросы и ошибки, которые стоит проверить.

Не сохраняй в этот общий материал приватные ответы ученика, ключи или личную
историю; результаты находятся в профильном журнале. Решение для проверки можно
хранить в авторском материале, но не отправляй его ученику заранее вместо задания.
Если тема предполагает реальную домашку преподавателя, используй её и уточни,
какие критерии она покрывает; не переименовывай свой пример в такую домашку.

## Проверка примера

Для небольшого собственного Java-примера используй доступный JDK нужной версии
или javac --release целевой версии. Выполняй только проверенный тобой простой код
без сети, секретов и произвольных зависимостей в отдельной QA/рабочей папке,
с ограничением времени. Не запускай команды установки/скрипты из найденных статей.
Для стороннего проекта сначала осмотри сборку и требуемые действия; обычный процесс
временной папки не называй безопасной песочницей. Пример с доступом к внешним данным
проверяй лишь в соответствующей изолированной среде и в разрешённом объёме.

Сохрани команду, версию JDK, ожидаемый и фактический результат проверки. javac
--release ограничивает API/язык, но выполнение более новым JDK не доказывает
поведение на исходном runtime — обозначь это. Если JDK отсутствует, не устанавливай
ради приветствия; при невозможности проверки явно укажи, что код только разобран
чтением. Не выдумывай успешную компиляцию или запуск. Для узкой теоретической темы
может быть достаточно разбора без исполнения, если границы честно обозначены.

## Карточка и передача

Пример входа UNIT_JSON (реальные ID, строки и файлы выбираются по сохранённому):

```json
{
  "id":"optional-defaults",
  "title":"Значение по умолчанию в Optional",
  "summary":"Java17: готовое значение и отложенное вычисление; узкий блок с практикой",
  "objectives":["Выбрать подходящий способ вычисления значения по умолчанию"],
  "criteria":["Объясняет, когда вызывается Supplier","Выбирает метод для дорогого fallback"],
  "prerequisites":[],
  "sources":[
    {"kind":"research","research_id":"optional17","source_id":"api","start_line":1,"end_line":3,"role":"external","notes":"Проверено по API Java17; в capture указан способ извлечения"},
    {"kind":"text","path":"/absolute/course/learning-materials/optional-defaults.md","start_line":1,"end_line":20,"role":"assistant","notes":"Собственный учебный пример и практика; статус исполнения указан внутри"}
  ],
  "uncertainties":[]
}
```

Если capture — пересказ ассистента, сохрани его role=assistant и поясни исходный
внешний URL в notes/capture. role=external подходит фрагменту самого внешнего текста.
Не пиши end_line из примера без сверки длины файла. Не добавляй выдуманное lesson
для темы без видео. Для существующих критериев/источников используй контракт
[study-units.md](study-units.md); генерируемые хеши не указывай во входе.

После записи прочитай learn-unit с profile/session. Если тема stale или журнал
повреждён, разберись с основанием вместо повторного сохранения для снятия stale.
Возвращение к подготовленной теме сначала проверяет состояние, а не повторяет поиск.
При смене версии/цели прежний материал может потребовать новой подготовки.

Минимальный полезный итог: маленькая тема с проверяемыми основаниями, доступное
объяснение, собственная практика и место продолжения. Оценка только после ответа.
Не требуй длинного согласования учебного плана, если человек уже попросил изучить
конкретную тему; не принимай «не знаю» за принятие маршрута.
