# Команды локального курса

Разреши PLUGIN_ROOT как корень установленного dosuti-mentor. Все команды ниже —
примеры; подставляй реальные пути. Не используй папку plugin/cache для курса или
моделей: она может заменяться при обновлении. Не требуется API-ключ.

## Runtime

CPython 3.11 или 3.12 подходит для первой версии. Runtime можно разделять между
курсами одного пользователя. `bootstrap.py` создаёт venv и скачивает библиотеки с PyPI.
Веса модели скачиваются с Hugging Face при первом prepare. Это сетевые загрузки,
а распознавание звука происходит локально.

```sh
python3 PLUGIN_ROOT/scripts/bootstrap.py --home DATA_ROOT
```

После этого используй DATA_ROOT/runtime/venv/bin/python; на Windows —
DATA_ROOT/runtime/venv/Scripts/python.exe. Повторный запуск проверяет готовую среду
без пересборки; неисправную сохраняет до явного ремонта. bootstrap.py --verify
проверяет приватный Python, импорты и FFmpeg без установки. Windows-установщик
поставляется внутри PLUGIN_ROOT/scripts/Install-DoSuti.ps1.

При явном start-learning без выбранного курса:

```sh
PRIVATE_PYTHON -B PLUGIN_ROOT/scripts/learning_start.py --project PROJECT --chat CHAT_ID
```

Для чата без проекта --project не нужен. Новый стандартный курс находится в
управляемом доме; старые подключения и явные отключения имеют приоритет.

## Приём материалов

```sh
PYTHON PLUGIN_ROOT/scripts/course.py init --course COURSE --title "Java: проект"
PYTHON PLUGIN_ROOT/scripts/course.py add-lesson --course COURSE --lesson lesson-01 --order 1 --title "Первое занятие" --video VIDEO_PATH_OR_URL
PYTHON PLUGIN_ROOT/scripts/course.py attach --course COURSE --lesson lesson-01 --kind code --source CODE_FOLDER_OR_GITHUB_URL
PYTHON PLUGIN_ROOT/scripts/course.py attach --course COURSE --lesson lesson-01 --kind homework --source HOMEWORK_FILE
PYTHON PLUGIN_ROOT/scripts/course.py attach --course COURSE --lesson lesson-01 --kind resources --source ARTICLE_URL --resource-type article
```

`--ref BRANCH_OR_TAG` у attach фиксирует выбранную ветку/тег GitHub; итоговый
commit всегда сохраняется. Локальный код может быть папкой, ZIP или файлом.
Чтобы записать ответ «материалов нет», используй attach с `--kind ... --none`.
Домашку, присланную текстом, сначала сохрани в файле внутри курса, затем attach.
Новые дополнительные ссылки добавляются отдельными вызовами attach.

Локальное видео закрепляется по SHA256 при регистрации, доступный внешний файл —
при получении через prepare/frame. Изменённое видео зарегистрируй новым занятием:
замена байтов по тому же пути не заменяет материалы и прогресс старого занятия.
Если файла ещё нет при регистрации, его идентичность будет закреплена при получении.
Относительный путь VIDEO_PATH разрешается при регистрации относительно текущей
папки терминала и сохраняется как абсолютный, поэтому последующий запуск из
другой папки не меняет источник. Диск C:/ и UNC распознаются как локальные пути;
на macOS путь Windows требует файла на этом компьютере.

В 0.1.5 managed-пути занятия имеют относительные якоря от корня курса. После
переноса каталога status/context/prepare/diff-code получают актуальные пути
к prepared, снимкам кода, домашке, ресурсам и видео внутри курса. Байты пакета
при этом не переписываются: context вычисляет текущие пути кадров. Оригинальный
source_path в manifest — исторический путь, не актуальная команда открытия.
Старый tutor_context.md может содержать прежние абсолютные пути; используй context.
Для курса из прежних версий до переноса выполни:

```sh
PYTHON PLUGIN_ROOT/scripts/course.py make-portable --course COURSE
```

Команда сохраняет якоря для уже известных внутренних файлов и не добавляет
хеши старому материалу. Если старый курс уже перенесён без якорей, потребуется
восстановить прежнее расположение для миграции либо добавить материалы заново.
Видео и runtime снаружи курса не копируются. .dosuti-mentor.json находится в
проекте: обнови course_path после переноса, проверь python_path/model_path.
Относительные пути настроек ассистент разрешает от папки этого JSON; относительные
CLI-аргументы — от текущей папки запуска. Сам venv не обещает переносимость.

Снимки кода сохраняют inventory (путь, размер, SHA256), запрещают символические
ссылки и получают режим только для чтения на проверенной платформе macOS.
Git commit остаётся в origin, Git-служебная папка не входит в снимок. Сам исходник
можно менять — снимок от него независим. При обнаружении ссылки предоставь
обычные файлы. context/diff-code проверяют сохранённый снимок; при повреждении
или отсутствии inventory заново attach из доверенного источника. Не исправляй
эталон снятием ограничения записи. Проверка старых снимков в history не выполняется
автоматически при чтении status.

Сохранение состояния лекции защищено блокировкой файла: копирование материалов
и распознавание выполняются вне блокировки, затем команда обновляет свежее
состояние. Не удаляй `.lesson.lock` во время работы и не редактируй lesson.json
вручную параллельно с командами. Это защита локальных процессов; работа нескольких
компьютеров через сетевую файловую систему не проверена.

Для сравнения приложенного кода двух занятий:

```sh
PYTHON PLUGIN_ROOT/scripts/course.py diff-code --course COURSE --previous lesson-01 --lesson lesson-02
```

Можно ограничить сравнение конкретным относительным путём через `--file`.
Diff показывает различия снимков, а не доказывает соответствие видео.

## Подготовка и доступ к источнику

```sh
PYTHON PLUGIN_ROOT/scripts/course.py prepare --course COURSE --lesson lesson-01 --duration 600
PYTHON PLUGIN_ROOT/scripts/course.py prepare --course COURSE --lesson lesson-01 --start 600 --duration 600
PYTHON PLUGIN_ROOT/scripts/course.py context --course COURSE --lesson lesson-01 --time 150 --window 120 --profile default
PYTHON PLUGIN_ROOT/scripts/course.py frame --course COURSE --lesson lesson-01 --time 430
```

Видео принимается через адаптеры: локальный файл, публичный файл Яндекс.Диска,
прямая HTTP(S)-ссылка с расширением mp4/mkv/webm/mov/avi/m4v/mpeg/mpg/ts
(параметры URL допускаются), либо страница сайта через yt-dlp. Расширение в URL
не является доказательством видео: после скачивания FFmpeg проверяет видеопоток.
Страница входа/ошибки не публикуется. Для ссылки без расширения применяется
экстрактор сайта. Список поддерживаемых площадок и ограничения меняются:
[официальные источники yt-dlp](https://github.com/yt-dlp/yt-dlp/blob/master/supportedsites.md).
Это не обещание скачивания с любого сайта. Приватные/DRM-источники, плейлисты и
эфиры не поддерживаются этим сценарием; получи обычный файл лекции.

У всех удалённых адаптеров общий кэш video/download.json с исходной ссылкой,
размером и SHA256 файла. Готовый проверенный кэш используется без сетевых запросов,
включая запросы Яндекс-метаданных и yt-dlp. Устаревший подписанный адрес не нужен.
Кэш относится к закреплённой версии лекции; новое содержимое той же страницы
не заменяет её автоматически. Новый файл скачивается в отдельную временную папку,
проходит проверку и лишь затем получает маркер. Параллельные запуски блокируются.
Сбой обычного скачивания очищает его временную папку; повтор начинает видео заново,
побайтовое resume скачивания видео здесь не реализовано. Старый проверенный файл
не перезаписывается. SIGKILL может оставить закрытую временную папку/лишний файл;
они не принимаются за готовую лекцию. При исчезновении закреплённого файла новый
обязан совпасть с его SHA256; повреждённый существующий кэш явно отклоняется.
Старый кэш принимается только с уже сохранённым pin. Не создавай pin задним числом
ради использования неподтверждённых старых файлов.

Статьи и прочие дополнительные ссылки по HTTP(S) сохраняются через attach как
registered_not_read. Ассистент отдельно получает текст доступными инструментами,
сохраняет источник и сверяет его с лекцией; скачивание видео не читает статьи.

Без --duration prepare обрабатывает остаток записи от --start. Большие записи
можно готовить частями, чтобы ограничить время и память. Кадры по умолчанию каждые
10 секунд; это не гарантирует обнаружения всех изменений. frame извлекает один
исходный кадр около указанного времени. Для видео/кода сверка остаётся работой
ассистента. Дополнительное видео можно зарегистрировать как отдельный источник
курса с названием "Дополнение к lesson-01" и соответствующей ссылкой в resources.

При просьбе снизить нагрузку на процессор используй `prepare ... --cpu-mode economy`.
У `lecture.py` есть такой же флаг. Economy: 2 потока ASR, 1 поток декодирования,
фильтров и кодирования FFmpeg; BLAS/OMP в отдельном worker ограничены 2 потоками.
Модель, параметры декодирования речи и частота кадров сохраняются. Это ограничение
параллелизма, не жёсткая квота CPU или ОЗУ: обработка может занять больше времени.
Стандартный режим (`--cpu-mode standard`, по умолчанию) оставляет прежние 4 потока ASR
и автоматическое число потоков FFmpeg. Готовые этапы при переключении используются
повторно; фактический режим ASR записан в recognition пакета, параметры извлечения —
в checkpoint. Отсутствие полей режима у старого курса не требует его пересоздания.
Установку зависимостей и проверку загрузки модели этот флаг не ограничивает.

### Сверка экранных изменений

```sh
PYTHON PLUGIN_ROOT/scripts/course.py scan-screen --course COURSE --lesson lesson-01 --start 540 --duration 60 --sample-every 0.5
```

scan-screen работает локально без ASR и новых моделей. Оно сохраняет образцы
примерно каждые 0,5 секунды (при VFR первый следующий подходящий кадр), а также
индекс изменений. Ограничение одного запуска: 300 секунд и 1200 интервалов выборки.
Для длинного урока сверяй небольшие смысловые участки. Все извлечённые образцы
сохраняются в evidence/screen-scans; список кандидатов уменьшает повторение
статичных экранов, но не удаляет остальные образцы. Стоимость — декодирование
видео, дополнительные JPEG на диске и время просмотра ассистентом.

Кандидат выбирается по изменению яркости/плиток изображения либо как исходный
и периодический образец. Курсор, подсказка и прокрутка тоже могут стать кандидатом;
небольшое/краткое изменение может быть пропущено. Это не OCR, не восстановление
версий кода и не подтверждение смысла. Проверка намеренно показывает пропуск
события, целиком помещающегося между образцами. Уменьшение интервала помогает,
но не даёт гарантии полноты.

screen.json содержит все строки с относительным file, id, source_seconds,
review_candidate и sha256. source_seconds/approx_seconds теперь вычисляются
из времени декодированного кадра относительно выбранного start, а не из номера
картинки. timestamp_accuracy=decoded_video_timestamp описывает время видео,
не точное совпадение с фразой и не гарантию состояния между кадрами. Новая обычная
подготовка также использует декодированные времена. Старые пакеты остаются
approximate, их байты/хеши не исправляются задним числом.

Каталог публикуется после полной записи screen.json/completion.json. Повтор
проверяет хеш индекса и всех образцов. context проверяет сохранённый в занятии
хеш индекса и выбранные файлы, добавляет кандидаты в frames и отдельные
screen_scan_sources. Это не расширяет покрытие распознанной речи: экран без ASR
по-прежнему даёт coverage.complete=false. При повреждении используй scan-screen --rebuild: создаётся новый каталог,
повреждённый сохраняется в retired_screen_scans, а следующий обычный запуск
использует новый снимок. Не меняй хеш вручную. Новые параметры создают другой снимок. Перенос курса сохраняет пути screen_scans через якоря.

Подготовленное видео требует визуальной и, при неоднозначностях, слуховой сверки.
Сохраняй source_kind и screen_sample (scoped_id, относительный индекс/кадр, время,
sha256) в заметках наблюдения, не переписывай ASR/пакет. «Повтор с Java-подсказкой»
может исправить термин и испортить отрицание: сравнение моделей не является
прослушанной эталонной расшифровкой. Если звук нельзя проверить в текущей среде,
фиксируй неопределённость вместо приписывания удобной фразы преподавателю.

prepare продолжает работу по контрольным точкам звука, кадров, ASR и пакета.
Рабочая папка .jobs отделена от опубликованных фрагментов. В checkpoint.json
сохраняются идентичность источника, параметры и хеши завершённых этапов.
Ранний сбой не требует удаления папки; обычный повтор prepare продолжает ту же
работу. Непроверенные старые файлы без manifest/checkpoint сохраняются отдельно
и пересоздаются из источника, не принимаются за проверенный кэш. Звук/кадры
после подтверждения их этапа проверяются; повреждение завершённого кэша требует
новой работы через prepare --rebuild. Используй этот флаг один раз; после сбоя
новой работы обычный prepare возобновит её.

Опубликованный фрагмент собирается в отдельной временной папке, проверяется и
переименовывается целиком. Повтор не переписывает его кадры или заметки.
Если опубликованная копия повреждена, а рабочий кэш цел, prepare создаёт другую
копию и убирает прежнюю из активного контекста. Прежние файлы остаются в истории.
Блокировка рабочей папки исключает одновременную обработку одного задания;
ожидание ограничено 30 секундами. Для длинной уже запущенной обработки вторая
команда может сообщить busy — повтори после проверки первого процесса.
Материалы можно добавлять во время ASR: короткая блокировка lesson.json остаётся
отдельной от блокировки обработки. Наличие готового пакета не означает изучения.
`--model-path LOCAL_MODEL_FOLDER` позволяет использовать общую скачанную модель.
Для перемещения материалов по таймкодам читай context, а не весь JSON в каждом
ответе. context объединяет все подготовленные фрагменты, пересекающие выбранный
диапазон `[time, time + window)`. Даже если его начало не обработано, доступное
продолжение возвращается вместе с явным пробелом. Полностью необработанный запрос
возвращает пустой материал и пробел на весь диапазон.

Формат context имеет schema_version=2. `coverage.ranges` — объединённые
обработанные интервалы внутри запроса; `coverage.complete` означает только
покрытие диапазона подготовленными пакетами. Это не подтверждение качества ASR,
полноты изображения или усвоения. `gaps` перечисляет необработанные интервалы.
Старые поля coverage.start/end — крайние границы доступного материала; при
нескольких ranges они не означают непрерывного покрытия. Без материала они null.

`source` и `registered_source` описывают зарегистрированное видео, `sources`
описывает каждый прочитанный пакет, его coverage, распознавание и пути к источникам.
`rules` теперь список путей; правила каждого источника доступны в sources.rules_file.
В 0.1.3 источники проверяются по закреплённому SHA256. context проверяет хеш
зарегистрированного пакета, текста и выбранных кадров. sources.identity_verification
равно pinned_source_hash_matches при успешном сопоставлении. Если оригинал доступен,
его текущие байты тоже проверяются. При его отсутствии остаётся проверенный кэш
с video_integrity=original_unavailable_using_pinned_hash и соответствующим warning.
Это проверка целостности и заявленной связи с видео, не аутентификация чужого
манифеста и не доказательство точности/полноты распознавания. Не принимай поддельные
метаданные как подтверждение того, что расшифровка действительно получена из видео.

Импорт: `prepare --import-prepared PREPARED_FOLDER`. Пакет должен иметь manifest
с source_sha256 и evidence_sha256 для transcript.json/кадров и совпадать с видео
занятия. Проверка проводится до и после копирования; затем пакет строится заново.
Звук при импорте не копируется; его хеш проверяется при resume исходной обработки.
Файл заметок можно дополнять — он не является автоматически подтверждённым ASR.

resume требует совпадения SHA256 видео, диапазона, интервала кадров, а также
хешей звука и подготовленных файлов. Другая частота кадров требует новой папки;
course.py выбирает её автоматически. Старые пакеты без этих полей не допускаются
к resume/импорту/преподаванию как проверенные: повтори prepare из доверенного видео.
Новая подготовка использует папку с префиксом v2 и хешем источника; прежние записи
без идентичности уходят в retired_fragments, их файлы не удаляются. Не дописывай
им хеши из текущего видео — это не подтверждает происхождение прежнего материала.
Рабочие копии сохраняются для восстановления, поэтому звук/кадры занимают место
и в рабочем кэше, и в опубликованном снимке. Автоматической очистки всей истории
курса пока нет. --rebuild не позволяет обходить несовпадение исходного видео.

Модель проверяется как комплект model.bin/config.json/tokenizer.json/vocabulary.txt.
Загрузчик блокирует каталог, проверяет размер/SHA256 частей и итогового файла,
при повреждении кэша выполняет ограниченный чистый повтор. Конфигурация и словарь
новой загрузки выбираются с той же ревизии репозитория, что веса. Инвентарь
model-ready.json и журнал установки не допускают неполный опубликованный комплект
к загрузке в обработчике. Сам факт наличия файлов не доказывает возможность
инференса: реальный загрузчик модели и ASR тоже могут сообщить ошибку.

Сетевой сбой оставляет проверенные части для повторного вызова, но не готовую
модель. Корректная местная модель используется без запроса метаданных по сети;
после её проверки временные части удаляются. Блокировки действуют для процессов
плагина; сторонние программы, напрямую читающие каталог, этот протокол обходят.
Внешние вручную собранные модели требуют проверки на реальном запуске.
Источник правил ревизий/хешей: [документация Hugging Face](https://huggingface.co/docs/huggingface_hub/package_reference/file_download).

IDs речи и кадров имеют префикс фрагмента. `provenance` хранит fragment_id,
local_id исходного элемента и packet_file. Точные совпадения (время + текст для
речи, время + SHA256 изображения для кадра) объединяются с сохранением всех
ссылок. Повторённая фраза в другой момент не удаляется. Различающиеся ASR-записи
из перекрывающихся фрагментов сохраняются, `speech_overlaps` требует их сверки.
Это не автоматическое сравнение смыслов. Список перекрытий ограничен 100 парами,
при превышении speech_overlap_details_truncated=true; сама речь не обрезается.
`selected_interval` показывает пересечение сегмента с запросом; исходные
start/end и полный текст сохраняются, фраза не режется посередине.

В frames может быть ближайший образец перед началом окна, включая стык пакетов.
Он имеет selection=preceding_sample и age_seconds. Это не доказательство того,
что экран оставался таким: screen_state_confirmed=false. Через необработанный
пробел такой образец не переносится. Кадры в окне тоже остаются приблизительными.

visual_notes объединяет относящиеся к диапазону наблюдения и неопределённости
из всех источников; ссылки на кадры имеют общие IDs. При изменении заметки
используй её provenance.notes_file и исходные local_id из provenance кадра,
а не записывай объединённую выдачу обратно в один файл. Все исходные заметки
остаются по paths в visual_notes.sources. Оригинальные пакеты context не изменяет.

## Общий прогресс

```sh
PYTHON PLUGIN_ROOT/scripts/course.py bind --course COURSE --lesson lesson-01 --chat CHAT_ID --profile default
PYTHON PLUGIN_ROOT/scripts/course.py status --course COURSE --profile default
PYTHON PLUGIN_ROOT/scripts/course.py progress --course COURSE --lesson lesson-01 --profile default --topic "HashSet" --stage understood --details "Разобрано 02:32–09:59; ученик объяснил роль ключа и дубликатов"
PYTHON PLUGIN_ROOT/scripts/course.py history --course COURSE --lesson lesson-01 --profile default --limit 100
```

Для нескольких чатов одного пользователя выбирай один COURSE и PROFILE.
Для другого ученика выбирай его локальные данные или отдельный профиль.
SQLite хранит события и текущее состояние атомарно, поэтому параллельные чаты
не перезаписывают журнал целиком. Это локальная общая память, не автоматическая
синхронизация разных компьютеров.

Для результатов по домашке передавай `--homework-revision REVISION_FROM_REVIEWED_TASK`
из `homework.revision` в status/context. Для старого задания без этого поля
используй `sha256:` плюс `homework.sha256`. Фиксируй эту версию **до проверки**,
не подставляй новую версию после смены условия. Параметр обязателен для
homework_passed; для practice_checked и needs_review по домашке он тоже связывает
результат с условием. Самостоятельную практику записывай в отдельную тему.

Если условие изменилось за время проверки, запись со старой версией отклоняется.
После изменения/удаления домашки status и context показывают старую проверку как
needs_review с invalidated=true. history сохраняет исходную оценку и комментарий
по прежней версии. Повторное добавление идентичного по SHA256 условия не сбрасывает
результат. Старый homework_passed без известной версии требует повторной проверки;
его исходное событие сохраняется. Профили мигрируют автоматически при чтении.

## Медиа и пересборки в 0.1.7

prepare и lecture.py принимают --audio-track INDEX (абсолютный индекс потока)
и --audio-channel INDEX (канал с нуля). При нескольких непустых дорожках команда
выводит допустимые индексы и требует выбора. Параметры входят в ключ работы.
Шкала аудио сохраняет задержку относительно видео; видеоряд не обрезается
по концу звуковой дорожки. Немое видео сохраняется с явным audio_quality.

Ошибки декодирования блокируют публикацию; last_error в checkpoint и
last_processing_error в занятии сохраняют диагноз. Старые checkpoint другой
версии алгоритма нельзя продолжить с новыми правилами: используй свежую папку
или prepare --rebuild. Старые опубликованные пакеты остаются доступными
с предупреждением о необходимости пересборки. При изменении pipeline key
старые варианты могут остаться рядом в истории активных фрагментов: context
покажет их предупреждения и перекрытия, не считай их независимыми репликами.

Поздний результат старого поколения не активируется поверх выбранной пересборки.
processing_jobs и screen_jobs содержат status pending/failed/complete. При неудаче
пересборки последний пригодный пакет сохраняется, но context предупреждает
о незавершённой работе. Кандидаты screen-pixels-v3 учитывают локальные изменения
в исходном разрешении; это не OCR и не доказательство полноты просмотра.

### Уменьшение повторов экрана в 0.1.8

screen-pixels-v4 сохраняет первые состояния тонкой вертикальной правки. Только
после нескольких обратимых повторов в том же месте она может получить
repeated_caret_like_change и перестать создавать новый кандидат. Периодические
опорные кадры остаются. Это эвристика мигания каретки, не подтверждение смысла: все
образцы сохранены, в спорном месте читай полный screen.json. Изменившийся текст,
переместившаяся каретка и одиночное появление символа этим правилом не исключаются.
Новая версия алгоритма создаёт отдельный scan и не переписывает старые индексы.

## Интервал кадров с 0.1.10

`lecture.py` и `course.py prepare` по умолчанию используют `--frame-every 10`.
Явно заданное значение сохраняется. Для возобновления прямого запуска прежних
версий с интервалом 20 секунд укажи `--resume --frame-every 20`. Для другой
выборки используй новый output или prepare --rebuild в курсе. Старый checkpoint
не подменяется настройками нового запуска. Даже шаг 10 секунд может пропустить
короткую правку; scan-screen остаётся инструментом её проверки.

## Обзорные листы с 0.1.11

Новые scan-screen используют screen-pixels-v5 и сохраняют overviews в screen.json.
В context ссылки доступны в screen_scan_sources[].overviews: absolute_path,
frame_ids и selected_frame_ids. Один лист содержит до 12 кандидатов по времени.
Он может включать кадры вне запрошенного окна. Оригинальные кадры, их хеши
и review_candidate сохраняются; листы не заменяют чтение кода в полном размере.
Проверяется целостность листов и совпадение их состава со списком кандидатов.
Старые v4-снимки читаются без обязательной пересборки.

## Продолжение скачивания с 0.1.12

После ошибки прямой HTTP-загрузки или загрузки файла Яндекс.Диска повтори
обычный prepare. Проверенный префикс остаётся в приватной .fetch-папке; он ещё
не является готовым видео. Сохранённые байты сверяются по SHA256, сервер должен
подтвердить сильный ETag и точный Content-Range. Полный ответ 200 заменяет
прежний префикс; новый файл всё равно должен совпасть с закреплённым хешем.
Без сильного ETag, после изменения URL или повреждения локальной части запрос
начинается заново. Изменившийся подписанный CDN-адрес также вызывает перезапуск.
Сайты через yt-dlp используют механизм yt-dlp. Совместимость с любым сервером
не гарантируется. Неполный файл никогда не публикуется как готовый материал.

## Личные настройки, темы и продолжение — 0.2.0

Команды используют `--course /path/course`. Профиль по умолчанию default;
для друзей выбирай разные --profile. Данные записываются вне плагина.

```sh
python course.py settings --course /path/course --profile alice
python course.py settings --course /path/course --profile alice --set style=partner --set format=steps --set detail=detailed --set level=intermediate --set checks=end --onboarding complete
python course.py settings --course /path/course --profile alice --onboarding skipped
python course.py settings --course /path/course --profile alice --scope course --set format=blocks
python course.py settings --course /path/course --profile alice --scope course --reset
```

`--profiles-dir /path/personal-profiles` у settings/status/context выбирает общую
папку предпочтений для разных курсов. Без него профиль хранится в learners курса.
Опрос предлагает ассистент при onboarding=not_asked; команда не открывает GUI.

`resume` читает последний учебный курсор профиля. Чтобы сохранить его, подготовь
JSON и передай --state-file, --expected-revision из предыдущего чтения:

```json
{
  "lesson": "lesson-01",
  "time": 1000,
  "topic": "Сравнение строк",
  "recap": "Разобрали сравнение двух строк",
  "next_step": "Дождаться ответа на вопрос",
  "pending_question": "Какой результат у сравнения в примере?",
  "misconceptions": []
}
```

```sh
python course.py resume --course /path/course --profile alice
python course.py resume --course /path/course --profile alice --state-file /path/cursor.json --expected-revision 0
```

Запись курсора не означает понимание темы и не создаёт оценку. После изменения
источника/набора подготовленных пакетов valid=false требует повторной сверки.

Необязательно добавь в этот JSON `"dependency_topics": ["string-comparison"]`.
Это 1–50 уникальных ID существующих неустаревших тем того же занятия. Укажи ВСЕ
темы, реально поддерживающие recap, pending_question и остальное состояние;
резюме может зависеть от нескольких тем. time должен попадать хотя бы в одну
из них (конечная граница включается). Команда сама не определяет смысловые
зависимости и не подтверждает полноту выбранного списка.

С явным списком сохраняется версия доказательств выбранных карточек: их
содержание, границы, boundary_review, хеши источника и пакетов, а для code_files
также хеш всего снимка кода. Изменённая, удалённая или устаревшая выбранная тема
даёт valid=false; независимые новые пакеты/темы и изменение updated сохраняют
курсор. Без dependency_topics действует прежняя привязка ко всему занятию;
пустой список запрещён, автоматического сужения или миграции старых записей нет.
Неизвестная версия/повреждённая структура зависимостей даёт invalid_checkpoint:
файл не перезаписывается до явного восстановления или архивирования.
Отдельные изменения visual_notes, code_stages, внешних ресурсов и домашки эта
схема не отслеживает; при опоре на них перепроверь материалы при продолжении,
в том числе с valid=true и в прежнем режиме привязки ко всем пакетам.

`topic --lesson ID --topic-file /path/topic.json` сохраняет карточку темы:

```json
{
  "id": "string-comparison",
  "title": "Сравнение строк",
  "summary": "Аннотация ассистента по проверенному фрагменту",
  "keywords": ["строки", "сравнение", "string", "comparison"],
  "start": 990,
  "end": 1010,
  "code_files": []
}
```

Диапазон обязан быть подготовлен полностью; code_files — относительные имена
из прикреплённого проверенного снимка, например src/Main.java. Без --topic-file
команда показывает карточки и признак устаревания. Добавление/пересборка пакетов
консервативно помечает старые карточки устаревшими: сверяй перед обновлением.

```sh
python course.py search --course /path/course --query "string comparison" --limit 5
python course.py project-map --course /path/course
```

Поиск локальный, лексический: речь + ключевые слова/описания карточек. Для запроса
по смыслу ассистент подбирает термины и перечитывает контекст результата. Это не
embedding-поиск, не гарантирует синонимы и не интерпретирует автоматически весь
видеоряд. Необработанные материалы не ищутся как будто они уже прочитаны.

Карта показывает проверенные файлы, изменения между соседними доступными
снимками и кандидаты связей по упоминаниям символов. Это не компилятор и не
доказанный граф вызовов. Отсутствие снимка разрывает сравнение. Фактическое
соответствие снимка конкретному моменту видео требует отдельной сверки.

## Точность длительности и словарь ASR — 0.4.3

Без --duration prepare использует точную шкалу пакетов видео, как обработчик,
вместо округлённого вывода FFmpeg. Явная длительность сохраняется. Старые пакеты
не переписываются: для них используй фактический coverage.end, а при необходимости
подготовь новую версию из источника. Новый ключ может отличаться от старого.

`prepare ... --vocabulary-file /path/terms.json` принимает JSON-массив терминов,
например `["UUID", "JSON", "UUID.fromString", "Mockito"]`. Выбирай короткий
список реально проверенных по коду/кадрам терминов, обычно10–20. Это необязательная
подсказка initial_prompt локальному ASR; без файла прежний prompt сохраняется.
Она не доказывает произнесённое слово и может усилить ошибочную гипотезу.
Сохраняй сомнения и сверяй речь с источником, не отмечай её проверенной автоматически.

Максимум100терминов,80символов на термин,4000символов подсказки,32KiBфайл.
Повторы удаляются, переносы/управляющие символы запрещены. Содержимое входит в
prompt и ключ работы; изменение файла создаёт другую работу. Исходный ASR и
прогресс не редактируются. В одном занятии старые и новые варианты могут
перекрываться: проверяй speech_overlaps, не считай варианты разными репликами.
Смена пакетов может потребовать перепроверки тем/курсора по существующим правилам.
