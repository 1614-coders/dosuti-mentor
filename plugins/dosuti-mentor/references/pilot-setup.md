# Подготовка внешнего пилота

Один сценарий создаёт личный runtime, скачивает полную модель, фиксирует версии,
проверяет FFmpeg/CPU int8 и обрабатывает 1–60 секунд видео с речью: локального файла или публичной HTTP(S)-ссылки.
Он не устанавливает системный Python и сам плагин Codex. Распознавание локальное;
первое скачивание библиотек/модели требует сети. CUDA не требуется.

В распакованном пакете Windows:

```powershell
.\Start-WindowsPilot.ps1 -Video 'C:\Videos\lecture.mp4'
```

Подходящий CPython 3.11/3.12 x64 выбирается автоматически; при его отсутствии
подготавливается приватная проверенная копия. Можно передать -PythonExecutable
для выбора существующего интерпретатора. -PilotRoot выбирает
новую папку, -Start/-Seconds — интервал с отчётливой речью, -Model — tiny/base/small/medium/large-v3.
Если PowerShell запрещает запуск ps1, используй Python напрямую без изменения
ExecutionPolicy:

```powershell
py -3.12 -X utf8 .\plugins\dosuti-mentor\scripts\pilot_setup.py --root "$env:LOCALAPPDATA\DoSutiMentorPilot" --video 'C:\Videos\lecture.mp4'
```

PowerShell-вход сохраняет bootstrap-report внутри PilotRoot/reports; при раннем
отказе до создания управляемой папки — рядом с PilotRoot. Python для этого не нужен. Он не создаёт ложную папку успешного прогона. Сбой до исполнения
самого ps1 (например, ExecutionPolicy) этим скриптом записать невозможно — заполни
ручной шаблон. Общие Python/Git и политики системы автоматически не меняются.

После успешной подготовки открыть выданную папку project в Codex, вызвать
$test-learning. Новый чат внутри того же проекта может сказать «продолжи тест»
без пути: pilot.py project-status --project PROJECT возвращает известный прогон.
Это чтение привязки выбранного проекта, не глобальный поиск курсов и не
автоматическое определение нативного ID чата. При overrides нужен явный chat ID.

Структура PilotRoot:

- setup.json и SETUP_REPORT.md — все попытки, шаги, ошибки, версии зависимостей;
- attempt-*.log — ограниченный хвост вывода команды, частичная маскировка секретов;
- runtime/venv и models/ — установленные зависимости и локальная модель;
- smoke-NN/ — отдельная короткая реальная обработка для каждой попытки;
- run/ — pilot.json, отдельный course с профилем pilot, TEST_REPORT.md;
- project/ — .dosuti-pilot.json и явная привязка к run/course.

Пустой/обычный существующий PilotRoot не принимается как собственный. Повтор той же
команды продолжает подготовку с новой записью попытки, не стирает прежние ошибки,
smoke-пакеты и учебный прогресс. Старый running после прерывания помечается interrupted.
Неактуальный/повреждённый журнал не перезаписывается. Самопроверка не меняет оценки.
Установка плагина в Codex и педагогическая проверка остаются not_checked, пока
их не выполнил человек. Успех smoke означает выполненную обработку и непустой
ASR с кадрами, а не доказательство правильности распознанного текста.

Готовые runtime/model можно использовать без сети:

```text
PYTHON PLUGIN_ROOT/scripts/pilot_setup.py --root NEW_SETUP --video LOCAL_VIDEO --runtime EXISTING_RUNTIME --model-path EXISTING_MODEL --offline
PYTHON PLUGIN_ROOT/scripts/pilot_setup.py --root SETUP --status
```

Runtime — папка над venv. В режиме online установка меняет только runtime/model
внутри выбранного PilotRoot; внешние пути допускаются только для offline-проверки.
Даже offline выполняются загрузка модели в CPU и обработка, а не только чтение
версий. Новая попытка при ошибке скачивания использует штатный downloader с
проверкой частей; шаги имеют ограниченное ожидание. Совместные запуски сериализованы.

Перед передачей проверить оба Markdown-отчёта и выбранные логи: автоматическое
маскирование неполное, локальные пути/вывод программ могут быть личными. Отправки
нет. До удаления отдельно скопировать нужные отчёты; тестовые данные, runtime,
модель и установка плагина удаляются отдельно по просьбе человека.

Для последующих учебных команд на Windows передавай -X utf8 выбранному Python,
чтобы пути/JSON с кириллицей не зависели от кодовой страницы консоли.

В0.4.41 ограниченный хвост attempt-*.log обновляется во время работы каждые15секунд
и по завершении шага. Это позволяет отличать медленную загрузку от отсутствия
прогресса. При ошибке записи журнала управляемый дочерний процесс останавливается.

## Начало из чата по ссылке

После установки плагина можно открыть распакованную папку как проект и написать
$test-learning с целью и ссылкой на видео. Ассистент запускает тот же сценарий,
обсуждает размещение данных при необходимости и подключает QA по явной просьбе.
Распакованная папка нужна для Windows bootstrap до появления Python; копия в кеше
установленного skills-плагина сама по себе не содержит корневые PowerShell-сценарии.
Без доступного исполнения в чате или этой папки полностью автоматический старт
не гарантируется. Не проси пользователя вручную выполнять команды, если можешь
сам выполнить согласованный локальный запуск.

-Video принимает URL без предварительного скачивания человеком. После подготовки
runtime отдельный worker регистрирует занятие в QA и получает видео штатным адаптером.
Доступны Яндекс Диск, прямой HTTP(S) и площадки через yt-dlp в пределах поддержки;
авторизация/DRM не обходятся. Ошибки отражаются отдельным шагом video в setup.json.
URL хранится в lesson, хеши и download.json связывают повтор с теми же байтами.
Повтор берёт проверенный кеш; offline запрещает загрузку при его отсутствии.
При изменённом источнике/повреждённом кеше сохраняй ошибку, не сбрасывай pin.

Короткая проверка и обучение используют один файл в папке занятия, без второй
копии под smoke. Исходный локальный файл не переносится и не удаляется. Для URL
lesson уже существует: передавай его в prepare-lecture, а не добавляй дубликат.

## Очистка раннего сбоя

Если run ещё не создан, Complete-WindowsPilot.ps1 выбирает setup_cleanup:
план с внешним отчётом → проверка человеком → Apply по тому же файлу.
Маркера собственного дома достаточно при отсутствии setup.json; неизвестные
корневые записи и появление run требуют полного QA-сценария или разбора.
Не создавай фиктивный pilot ради удаления. Наличие .cleanup-pending.json
запрещает новые setup/runtime-команды; повтори применение исходного плана.
Плохой/неполный экспорт и активные блокировки оставляют данные на месте.
Без работающего внешнего Python или проверенного временного помощника команды
не исполнятся: не обещай полностью автономную очистку без сети и интерпретатора.
