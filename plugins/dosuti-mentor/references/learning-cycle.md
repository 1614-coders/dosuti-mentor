# Переходы полного учебного цикла

Это порядок работы ассистента с существующими хранилищами, не новый автомат
состояний. Читай его при первом запуске и возвращении к занятиям. Пользователь
видит один вопрос или одно ближайшее действие. JSON, команды, revision, пути
профиля и названия состояний ниже предназначены только ассистенту. Не показывай
их в обычном диалоге; при сбое объясни причину простыми словами. Не обещай
сохранение, если запись не подтвердилась. Не заставляй выполнять внутренние команды.

## Знакомство → диагностика

После установки разреши подключение и профиль по connections.md. Новое знакомство
веди по start-learning.md: приветствие и восемь вопросов, по одному, каждый ответ
сохраняется до перехода. Пауза не является пропуском и не создаёт ответа.
Завершённое знакомство не повторяется ни в этом, ни в другом чате того же профиля.

При возвращении к занятию сначала восстанови его точку по последнему разделу;
завершённая диагностика не повод заново предлагать уже принятый маршрут.
Перед предложением диагностики прочитай diagnostic, а не только preferences:

- not_started: предложи добровольную проверку; accept — только после согласия.
- accepted: продолжай текущую проверку; покажи сохранённый pending_prompt, если он
  есть, иначе составь один вопрос по сохранённым next_competence/next_difficulty.
  Не делай новый accept и не теряй уже отвеченные вопросы.
  Если последний ответ уже сохранил next_competence=null, выполни complete,
  а не задавай дополнительный вопрос.
- paused: предложи продолжить; resume — после согласия, затем тот же вопрос.
- completed: используй сохранённый summary и переходи к результатам и маршруту;
  не предлагай новую диагностику автоматически.
- declined: перейди к учебному шагу без повторного предложения проверки.

«Позже» до начала оставляет проверку незапущенной. Учитывай ответ в текущем чате;
не выдумывай дату, отказ или согласие. Отказ от диагностики не означает отказ от
занятия. Результаты знакомства и самооценка не являются диагностическим evidence.

## Результаты → предложение маршрута → материалы

При status=accepted заверши диагностику через complete, когда проверка закончена
или ученик просит остановиться. При status=completed повторный complete не нужен:
бюджет fixed_15_v1 завершает попытку после последнего ответа/пропуска.
Кратко объясни summary: что проверено, что подтверждено, где пробелы,
что осталось неизвестным и откуда разумно начать. Не выгружай журнал и не задавай
снова вопросы знакомства. Неполная диагностика позволяет предложить предварительный путь.

Перед proposal прочитай intent. Если цель ещё не сохранена, запиши только ясную
цель из фактических слов ученика через существующий intent.goal: ответы знакомства
сами её не создают. При существенной неопределённости уточни только её одним
вопросом. Не переспрашивай уже ясную цель и не подменяй существующую при продолжении.
Для профессии используй plan-career, для курса — порядок преподавателя, для темы —
небольшой маршрут по её реальным предпосылкам. Не выдавай техническую ссылку на
диагностический ответ за смысловое соответствие темы.

Проверь имеющиеся unit и источники. Подготовленные карточки можно связать с proposal
до начала урока; предложение не означает, что ученик уже изучил материалы.
Если подходящей темы нет, через research-topic/prepare-lecture подготовь только
нужную первую тему. Не принимай план ради возможности помочь с конкретной задачей.

Покажи краткий маршрут с причиной выбора первого шага и задай один вопрос:
«Подходит такой порядок?» Сохрани proposal отдельно; accept_proposal — только по
ясному согласию с показанным планом. Отказ оставляет план непринятым: предложи
уточнить именно неудобный шаг или сразу помочь с выбранной темой. Согласие на
диагностику не является согласием на Roadmap. При устаревшем предложении после
записи из другого чата перечитай данные и обсуди обновлённый вариант.

После принятия переходи к первому доступному шагу. Если подготовка нужна, сообщи
«Подготавливаю материал для первого занятия», выполни её сам и проверь material-status.
Не проси ученика передать уже доступные материалы заново. При отсутствующем
источнике объясни проблему и запроси только недостающий материал или разрешение
на доступный поиск. Если источник готов, скажи «Материал готов, начинаем с …» и
передай в teach-unit/teach-lecture. Установка, подготовка и объяснение не доказывают освоение.

## Занятие → практика → продолжение

Перед объяснением прочитай preferences, включая onboarding_answers: там могут
быть выбранные формат, подробность и частота проверок, ещё не отображённые в
effective. Следуй явному выбору ученика в диалоге; не заменяй adaptive/examiner
неподходящими старыми настройками и не записывай их как учебный результат.
Не повторяй анкету для выяснения уже известного формата.

Следуй [правилам подачи](lesson-presentation.md): краткая цель, польза и план,
затем законченные смысловые блоки. Проверка по умолчанию adaptive — в подходящем
месте, не после каждого блока; явные настройки сохраняй. Одно «понятно» позволяет
продолжить, но не создаёт оценку. После явного запроса начать не спрашивай разрешение
повторно и не ограничивай число занятий в день.
Оценку сохраняй только после содержательного ответа и сверки с критериями. Ошибка → объясни конкретную ошибку и предложи
одно упражнение; помощь → новая задача без подсказки; самостоятельный успех →
краткий итог и один уместный следующий шаг (следующий критерий/тема или повторение
позже). Не выдавай повтор уже показанного решения за самостоятельную проверку.
Сохрани фактический checkpoint с незавершённым вопросом перед паузой/ожиданием
ответа. Если нужно пересмотреть маршрут, предложи изменение, не замени принятый
план автоматически. Результат критерия не снимает unverified с общей компетенции.

В новом чате разреши то же подключение, сохрани новый стабильный session ID и
прочитай intent/learning_progress вместе с preferences и diagnostic. Отсутствие
локального learning.checkpoint в learn-unit не означает отсутствие общей истории:

- При valid=true и единственном stopped_at используй его фактический вопрос/шаг.
  Если это unit из другого чата, прочитай его learn-unit с ID НОВОГО чата, сверь
  версию и общие попытки, затем продолжай по сохранённому checkpoint из stopped_at.
  Новую точку пиши только в новую session, не переиспользуй ID прежнего чата.
- При continuation_choice_required=true предложи выбрать между понятными
  названиями тем и местами остановки одним вопросом. Не выбирай последний revision.
- При неполных данных, устаревшем источнике или needs_review не используй старый
  шаг автоматически; объясни, что требуется сверить, сохрани историю.

Покажи короткое «Остановились на …, продолжим с …» и сохранённый вопрос, вместо
нового знакомства, повторной диагностики или меню внутренних команд. Явная новая
задача ученика имеет приоритет над автоматическим продолжением.


Для продолжения с lesson_id прочитай learn-unit с этим ID и ID нового чата.
Проверь lesson_state: paused возобновляй через resume по намерению ученика;
completed не является активным продолжением. Отсутствие checkpoint у контекста
не создаёт вымышленной точки остановки: используй его сохранённые цель и план.
Если switch_request уже confirmed/cancelled, не спрашивай решение повторно.
Confirmed сохраняет старое занятие paused; выбранная тема указана в target_topic.
Незакрытый request — ожидание прежнего ответа, а не новое подтверждение.
Обычная просьба остановиться сохраняется pause с checkpoint без лишних вопросов.
Контракт и атомарные операции — в разделе жизненного цикла unit-learning.md.
