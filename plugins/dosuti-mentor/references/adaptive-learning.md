# Адаптация и повторение — 0.4.19

Результаты остаются в learners/PROFILE/unit-learning.json. Новый формат
unit_learning_v2 читается вместе со старым v1. Чтение v1 не меняет байты; первая
явная запись публикует v2, сохраняя все прежние события/ревизии. Старый плагин v1
не обязан читать новые события: после обновления не редактируй журнал старой версией.
Неизвестная/повреждённая схема сохраняется, записи блокируются.

```sh
PYTHON PLUGIN_ROOT/scripts/course.py study-next --course COURSE --profile USER --session CHAT_ID --limit 5
PYTHON PLUGIN_ROOT/scripts/course.py learn-unit --course COURSE --profile USER --session CHAT_ID --unit-id UNIT
```

study-next — чтение без записи, не автоматическая смена маршрута. Возвращает
recommendations, blocked, continuations текущего чата, counts/truncated,
learning_intent, journal_revision, as_of и policy. До20 предложений на вывод,
кандидаты от всех зарегистрированных unit курса, не от произвольного интернета.
Без unit очередь пуста; старый SQLite не преобразуется в выдуманные оценки.

learn-unit.learning.adaptive содержит состояние каждого критерия, evidence_revision/
at, error_tags, due_at, suppressed, next_actions и later_verified_criteria.
evidence_events содержит последние оценки текущей версии по критериям, без
дублирования общей оценки нескольких критериев; ключ — evidence_revision.
Это даёт преподавателю фактический вопрос/ответ/пояснение даже без полной истории.
Очередь study-next не выгружает тексты ответов: для них прочитай выбранный learn-unit.
Источники stale дают blocked/review_sources, а не новую ошибку ученика. Повреждённый
журнал не даёт достоверных рекомендаций. Поля criteria/all_criteria_demonstrated
по-прежнему означают сохранённые оценки, не доказательство профессии/долгой памяти.

## Объяснимый следующий шаг

| Последняя оценка критерия | Предложение |
| --- | --- |
| Нет ответа | initial_check; после explained — check_understanding |
| needs_review | review_error: разобрать фактическую ошибку |
| practice_with_help | fresh_independent_task: новая задача без помощи |
| solved_independently | continue_or_wait до1 дня; затем recheck_due |
| checked_later | continue_or_wait до7 дней; затем recheck_due |

Приоритет: ошибка → самостоятельная задача после помощи → наступившее повторение →
неясное время → первичная проверка. Одинаковый приоритет сортируется по unit/критерию.
Сохранённое время в будущем помечается future_timestamp/review_evidence_time;
неразбираемое старое время не превращается в выдуманную дату повторения.
Предпосылки передаются в рекомендациях, но не являются автоматическим запретом:
при неизвестной базе предложи проверку, не считай предпосылку доказанным знанием.
Учти цель/настройки, незавершённый вопрос и желание ученика; не выбирай урок молча
только по номеру приоритета. Решение о подходящей сложности принимает ассистент.

Интервалы1/7 дней и минимум24ч — прозрачные инженерные эвристики текущей версии,
константы в adaptive_learning.py. На конкретном ученике эффективность не доказана,
в пользовательских настройках интервал пока не меняется. Нет фонового таймера,
напоминаний/отправки сообщений; рекомендации пересчитываются при обращении.
Нет процента профессии, прогноза трудоустройства или автоматического оценивания.

## Наблюдаемые ошибки

Для assessment допускается необязательный error_tags: до5 уникальных значений
concept/application/syntax/reasoning/testing/attention/unknown. Теги задаёт ассистент
по фактическому ответу, только для needs_review/practice_with_help. Это описание
проявившейся ошибки, не личностный диагноз. Нельзя выводить тег из пропуска задания,
самооценки или смены источника. Пустой список допустим; старые ответы не размечаются
задним числом. Поле details сохраняет конкретное объяснение оценки.

## Проверено позже

Пример нового assessment:

```json
{"stage":"checked_later","details":"Новая задача решена без помощи; критерий проверен через день","question":"Новая задача","answer":"Фактический ответ","hints":0,"criteria":[1,2],"recheck_of":{"1":5,"2":7}}
```

Каждый recheck_of указывает ревизию последнего самостоятельного ответа по этому
критерию той же unit/версии (solved_independently или checked_later). Ссылки на
другую тему/версию, прошлый ответ перед более поздней ошибкой/подсказкой, неизвестную
ревизию отклоняются. Допускаются разные baseline для разных критериев.

От каждого baseline должно реально пройти не меньше24ч по UTC-временам событий.
hints=0, ответ/вопрос обязательны. Повтор того же текста с изменением регистра/
пробелов отклоняется; смысловую новизну вопроса и правильность проверяет ассистент.
Разные слова не доказывают новую задачу. Ранний ответ можно сохранить обычным
solved_independently, но нельзя называть checked_later. Ошибка на повторении —
обычный needs_review (или practice_with_help после подсказки), не checked_later.

checked_later не становится самостоятельным глобальным сертификатом знания.
all_criteria_demonstrated принимает обе успешные стадии; later_verified_criteria
отдельно перечисляет актуальные критерии checked_later. Будущее время не включается
в этот список. Возврат источников и прошлых хешей сохраняет прежнюю семантику истории.

## Выбор пользователя

```sh
PYTHON PLUGIN_ROOT/scripts/course.py learn-unit --course COURSE --profile USER --session CHAT_ID --unit-id UNIT --review-file DECISION_JSON --expected-revision N --expected-unit-sha256 SHA
```

```json
{"choice":"defer","criteria":[1],"until":"2026-10-18T12:00:00+03:00","reason":"Пользователь попросил вернуться позже"}
```

choice=skip/defer/resume. Для skip/resume until=null; для defer дата с timezone,
строго после события, не дальше90 дней. --expected-revision и SHA относятся к
реально просмотренному состоянию, CAS и проверка источников те же. Это выбор
ученика, а не оценка. Пропуск/отсрочку сохраняй по реальному пожеланию, не потому,
что так удобнее модели. skip убирает предложение до resume или новой фактической
попытки; defer — до даты или новой попытки. Дата не создаёт проверку/оценку сама.

Решения общие для unit/профиля и версии, checkpoints остаются раздельными по
session. Новая версия темы не наследует старый skip/оценку. Новый ответ по критерию
делает прежнее решение неактуальным. Смена цели не стирает ответы. Старая lesson/
SQLite остаётся отдельной системой. С0.4.20 большой журнал unit автоматически
продолжается в сегментах v3 по [unit-learning.md](unit-learning.md). История может стать
неактуальной после смены источника, но не удаляется. Перенос курса сохраняет журнал.

## Добровольная начальная диагностика

Это отдельный журнал фактических ответов в целевом пути, а не unit assessment,
самооценка или обязательный экзамен. Предлагай его, когда исходные знания меняют
первый шаг. Согласие требуется до accept; явный отказ можно сохранить как decline,
но он не блокирует помощь, маршрут и последующее согласие. Простое приветствие,
прямой вопрос или просьба о лекции не запускают диагностику.
Предложи явно: «Хочешь пройти добровольную проверку исходных знаний, чтобы выбрать
первый шаг? Полная новая диагностика — 15 вопросов; можно остановиться раньше,
сделать паузу или отказаться». Задавай по одному вопросу. Пропуски входят в 15.

```sh
PYTHON PLUGIN_ROOT/scripts/course.py diagnostic --course COURSE --profile USER --session CHAT_ID
PYTHON PLUGIN_ROOT/scripts/course.py diagnostic --course COURSE --profile USER --session CHAT_ID --update-file EVENT_JSON --expected-revision N --reason 'Фактический выбор или ответ пользователя' --history-limit 10
```

Каждый EVENT_JSON содержит одно действие. Ассистент создаёт предметные вопросы,
оценивает ответ и объясняет изменение сложности; скрипт валидирует поля и переходы,
не генерирует тесты и не проверяет правильность сам.

```json
{"action":"accept","question_policy":"fixed_15_v1","selection_policy":"adaptive_v1","competences":["Проследить выполнение цикла","Объяснить уникальность ключа в map"]}
```

#### Структурированная оценка одного ответа

Для новых заданий сохраняй rubric вместе с prompt ДО ответа. Компетенция уже
задана в prompt.competence; не дублируй её второй независимой строкой.

```json
{"action":"prompt","competence":"Объяснить уникальность ключа в map","prompt":"После put(\"a\",2) и put(\"a\",3) назови get(\"a\") и size() и объясни результат","difficulty":"applied","format":"code_analysis","rubric":{"action":"Проследить замену значения и размер map","required":["Назвать конечное значение 3","Объяснить размер 1 при одинаковом ключе"],"alternatives":["Допустим эквивалентный разбор по шагам или иной верный способ доказательства"],"critical_errors":["Утверждать, что оба одинаковых ключа остаются отдельными элементами"]}}
```

Rubric содержит наблюдаемое action, required (1–20 уникальных обязательных элементов),
critical_errors (0–20 существенных ошибок), необязательные alternatives (0–20).
Это описания действий/решений, не ключевые слова для автоматического сравнения.
Элементы каждого списка — непустые строки до 2000 символов; action — до 4000.
Нумерация элементов начинается с 1 и фиксируется событием вопроса. Для дизайна
можно требовать «объяснить недостаток контраста» и «предложить читаемый вариант»,
разрешив несколько обоснованных цветовых решений.

В answer сохраняются прежние answer/evaluation/evidence/prompt_revision и новое assessment:

```json
{"result":"correct","met":[1,2],"unmet":[],"unverified":[],"critical_errors":[],"assistance":{"status":"independent","details":null},"verification":{"method":"assistant_review","details":"Оба обязательных элемента объяснены в фактическом ответе","limitations":["Проверен один пример, код не запускался; это не подтверждение всей компетенции"]}}
```

Это значение поля assessment, не отдельное событие. Полный answer по-прежнему
требует evaluation (конкретное обоснование), next_difficulty, next_competence и
selection_reason. Фактическую реплику ученика сохраняй без подмены образцовым решением.
Met/unmet/unverified — непересекающиеся уникальные номера, вместе покрывающие ВСЕ
required сохранённого вопроса. Critical_errors — номера наблюдённых существенных
ошибок из rubric.critical_errors. Python проверяет структуру и согласованность,
не истинность решения и не качество критериев. Корректный альтернативный способ
оценивай по действиям и смыслу критериев, а не совпадению формулировок.

| result одного ответа | Условия структурной согласованности | Совместимое evidence |
|---|---|---|
| correct | Все required выполнены, нет невыполненных/непроверенных и существенных ошибок | confirmed только при independent; иначе needs_practice |
| partial | Есть выполненные и невыполненные элементы, нет существенных ошибок; непроверенные отдельно | needs_practice |
| incorrect | Есть невыполненные элементы; если что-то выполнено, требуется явно отмеченная существенная ошибка | unknown |
| insufficient | Есть непроверенные элементы, нет вывода о доказанном незнании | unknown |

Существенная ошибка требует incorrect. Assistance.status: independent — известно,
что существенной помощи не было; assisted — была помощь, details обязателен и
содержит фактическую подсказку/помощь; unknown — сведений нет, не подменяй нулём
подсказок. Details может быть null при independent/unknown. При assisted/unknown
даже correct не даёт confirmed. Не путай полноту решения с самостоятельностью.

Verification содержит method, details и непустой список limitations. Methods:
assistant_review — содержательная оценка наставником; execution — выполненная
команда; mixed — запуск плюс разбор; unknown — способ достоверной проверки неизвестен,
допустим только insufficient со всеми required в unverified. Для execution/mixed обязателен execution с command,
целочисленным exit_code и фактическим output (до 16000 символов, может быть пустым).
Для остальных methods поле execution запрещено. Не заявляй запуск/прохождение
тестов без реального выполнения и результатов; при отсутствии запуска используй
assistant_review и назови ограничение. Наличие записи execution не является
программной аттестацией запуска: это сохранённые сведения ассистента, не доверенный
независимый протокол тестового раннера.

Нельзя прислать новую rubric в answer или заменить ожидающий prompt. Assessment
допустим только для вопроса с заранее сохранённой rubric; такой вопрос требует
assessment в ответе. В проекции ответа сохраняется точная rubric вместе с
prompt_revision. Старый ожидающий вопрос без rubric оценивай по прежнему контракту,
не выдумывая задним числом критерии, четыре категории или сведения о помощи.
Skip остаётся отдельным событием: сохраняет rubric вопроса, но не assessment/evidence.
Схема diagnostic_learning_v1 и бюджет fixed_15_v1 не меняются.

#### Итоговая карта и предложение учебного маршрута

Summary() учитывает все ответы текущей попытки, а не только последний. Competence_map
содержит competence, status, criteria, evidence, gaps, confirmed_levels, has_conflicts,
reason_codes, skipped_questions и ограничения scope. Статусы: confirmed — подтверждено
в наблюдаемом объёме; partial — есть частичное подтверждение; gap — наблюдался
конкретный невыполненный критерий; insufficient — недостаточно данных.

Каждый элемент criteria относится к ТОЧНОМУ описанию required и конкретной сложности
basic/applied/transfer. Он содержит positive_revisions, independent_revisions,
error_revisions, unverified_revisions и число разных independently решённых текстов
заданий. Evidence ссылается на answer_revision/prompt_revision и сохраняет исходные
result, сложность, помощь, объяснение оценки и наблюдённые существенные ошибки.
Выводы объясняй через эти факты, не выдумывай проценты владения темой.

Консервативное правило confirmed: минимум две самостоятельные проверки каждого
наблюдаемого критерия на разных текстах заданий той же сложности, без наблюдённых
ошибок или непроверенных результатов по этому критерию. Это техническая политика
достаточности наблюдений, не научно валидированная гарантия освоения. Разные тексты
не доказывают смысловую новизну; её оценивает наставник. Подтверждение ограничено
scope=observed_criteria_and_difficulties_only, а не всей областью компетенции.

Одна правильная проверка, помощь, неизвестная самостоятельность или непроверенные
части не дают полного confirmed. Ошибка не стирается более поздним успехом: оба
события остаются в карте, has_conflicts показывает противоречие по тому же критерию
и сложности. До отдельного доказательного пересмотра противоречивый критерий
остаётся gap. Успех на basic не подтверждает applied/transfer. Confirmed_levels
перечисляет только уровни с подтверждёнными наблюдаемыми критериями; карта может
одновременно показывать подтверждённый basic и пробел на transfer.

Insufficient и пропуск не доказывают незнание. Для legacy-ответа без assessment
result/помощь остаются неизвестными, criteria не выдумываются. Legacy unknown даёт
insufficient, а reported confirmed/needs_practice — ограниченное partial с явной
пометкой legacy_scope_unknown. Журнал не мигрирует и не перезаписывает старые оценки.

Пропуск ещё одного задания по уже подтверждённым тем же критериям/сложности не
стирает подтверждение и не требует учить их заново. Непроверенный новый объём
в пропущенной задаче остаётся ограничением. Focus_criteria в рекомендациях содержит
неподтверждённые критерии со сложностью, исключая уже подтверждённый объём.

При досрочном завершении fixed_15_v1 добавляется diagnostic_completed_early;
незавершённая попытка имеет diagnostic_was_not_completed. Пропуски и неизвестные
области показывай отдельно. Сводка ограничена текущей попыткой: предыдущие попытки
остаются в attempts, не смешивай их автоматически с другой целью или контекстом.

Summary.recommendations содержит конкретные основания, критерии и ревизии ответов:
address_specific_gap — работа с наблюдённым пробелом; collect_independent_evidence —
самостоятельная проверка ещё недостаточно подтверждённого объёма; clarify_or_assess —
уточнение/диагностика неизвестного, а не автоматическое повторное изучение.
Полностью подтверждённый наблюдаемый объём не получает рекомендации учить его заново.

В diagnostic.route_guidance и learning_progress.diagnostic передаётся сохранённая goal.
Сама summary остаётся независимой от текущей цели, чтобы факты не менялись при её смене. Сопоставляй
рекомендации с её смыслом, материалами и запросом ученика: программа не ранжирует
профессии/темы по ключевым словам. Объясни карту и предложи подходящий персональный
Roadmap через существующий intent.proposal. Укажи основания diagnostic_event_revisions
и unit/критерии только при проверенной содержательной связи; учитывай противоречивые
ответы, не цитируй лишь удобный последний. Используй прежние adaptation_basis/CAS.

Study-next передаёт proposal_guidance: цель, диагностическую ревизию, рекомендации и
acceptance_required=true. Это данные для обсуждения, не автоматически созданный или
принятый план. После согласия пользователя примени существующий accept_proposal.
При отказе сохрани текущий принятый маршрут; не заменяй его и не навязывай диагностику.
При новом ответе в другом чате перечитай основания перед принятием предложения.

Learning_intent использует карту вместо вывода «unknown = пробел». Для старых ссылок
на другую попытку карта той попытки используется только как основание этих ссылок,
не как автоматическое подтверждение новой цели. Техническая ссылка на unit не
доказывает смыслового соответствия, и диагностическая карта не завершает unit/шаг.
Если карта подтверждает наблюдаемый объём, начальная проверка связанной unit получает
check_unverified_scope: обсуди непокрытый критерий и причину проверки, а не читай
известное заново. Ошибки в реальной практике unit и запланированные повторные проверки
по-прежнему могут быть обоснованной причиной вернуться к материалу.

#### Выбор следующего задания

Для новой адаптивной попытки добавляй selection_policy="adaptive_v1" вместе с
question_policy="fixed_15_v1" в accept. Старые попытки без selection_policy
сохраняют прежние правила; не меняй их историю ради включения ограничений.
Чтение diagnostic возвращает selection_guidance, не меняя current.next_difficulty,
current.next_competence, сохранённые ответы или Roadmap. Используй его после ответа
и перед новым заданием вместе с фактической целью и материалами. Если valid=false,
не начинай новую диагностику поверх повреждённого журнала; repair_diagnostic
означает необходимость сохранить и восстановить данные. Ошибка исходного контекста
также видна в starting_guidance, не выдумывай неизвестную цель.

| action | Действие наставника |
|---|---|
| increase_or_change | После correct/independent предложи более сложную задачу или другую компетенцию; на transfer можно перейти к новой ситуации/теме либо завершить |
| independent_recheck | Correct с assisted/unknown: предложи новое самостоятельное применение без повторения подсказанного решения |
| probe_gap | Partial: проверь конкретные unmet; не объявляй весь ответ неправильным |
| check_prerequisite | Incorrect: проверь необходимую предпосылку по фактической ошибке, критериям и существенным ошибкам; не обнуляй уровень автоматически |
| clarify_response | Insufficient: уточни задание/получи проверяемый ответ, используй unverified; не делай вывода о незнании и не понижай сложность автоматически |

Focus_criteria содержит соответствующие описания из сохранённой rubric, last_response —
фактический ответ, assessment, помощь и способ проверки. Это опора для следующего
вопроса, не новая итоговая карта знаний. Legacy-ответ без assessment даёт
review_legacy_evidence: не выдумывай четыре категории по одному evidence=unknown.
Switch_after_skip требует другой компетенции или завершения без фиктивной оценки.
При resume_pending покажи уже сохранённый вопрос, не создавая новый; при paused
без вопроса сначала resume. При completed/declined не задавай новый вопрос без согласия.

Remaining — оставшиеся слоты, near_end=true при 1–3 слотах. Priority_competences
содержит непроверенные до достоверного результата компетенции. Это НЕ утверждение
о пробелах. Conclusive здесь означает correct/partial/incorrect конкретного ответа,
не освоение темы; insufficient/skip/legacy неизвестность не дают такого охвата.
Приоритет среди кандидатов выбирай по goal, subject, материалам и важности для
ученика; порядок списка сам по себе не рейтинг важности. Ближе к концу предпочитай
важные непроверенные темы, сохраняя добровольность и право завершить раньше.

Rotation_recommended появляется после двух подряд вопросов одной компетенции,
rotation_required — после трёх, если остаётся другая непроверенная компетенция.
В помеченной adaptive_v1 попытке код отклоняет выбор четвёртого подряд вопроса
той же компетенции при таком условии. Проверка проводится уже при сохранении
answer/skip с next_competence, чтобы не сохранить переход, из которого нельзя
продолжить. На вопросе 15 автоматическое завершение имеет приоритет.
Если единственная компетенция или другие уже проверены, жёсткая ротация не
требуется: обоснуй дальнейшее уточнение, не зацикливайся механически.

Used_prompts содержит тексты уже заданных вопросов. Для adaptive_v1 точное
совпадение текста нового prompt с прежним в этой попытке отклоняется до записи.
Программный слой не сравнивает смысл и не нормализует код/пробелы внутри него:
поверхностно перефразированная копия не становится полезной задачей. Выбирай новый
пример, проверяющий нужное действие; не обходи ограничение косметическими правками.

Наставник выбирает конкретную компетенцию, сложность и формулировку. Сохраняй
next_difficulty, next_competence и selection_reason по прежнему контракту. В причине
назови фактический результат, помощь, критерий/предпосылку, цель и ограничение
бюджета, когда они повлияли на выбор. Наличие непустой причины не доказывает её
педагогическую обоснованность. Старые события воспроизводятся без новых проверок
выбора; ограничения применяются только при новых записях помеченной попытки.

#### Бюджет новой попытки

Для каждой новой диагностики явно передавай question_policy="fixed_15_v1" в accept.
Маркер относится только к этой попытке. Схема diagnostic_learning_v1 и журнал прежние;
accept без маркера означает старые правила, его не используй для новой полной диагностики.
Старые active/completed попытки без маркера читаются и продолжаются без нового лимита.

В current.question_budget для новой попытки возвращаются limit=15, asked, remaining,
current_question и limit_reached. Это проекция событий prompt, не отдельное хранилище.
Один сохранённый prompt расходует один слот, даже если ответа ещё нет; answer/skip,
pause/resume и повторное чтение слотов не расходуют. Новый accept создаёт свой бюджет.
После сохранения вопроса покажи «Вопрос 4 из 15» по current_question и limit, затем
само задание. При повторном открытии pending_prompt используй прежний номер;
не сохраняй его повторно как новый prompt. Для старой попытки не выдумывай лимит 15.

Шестнадцатый prompt запрещён в apply(). После ответа или пропуска вопроса 15 status
автоматически становится completed в том же событии; current.next_competence=null.
Прочитай результат записи: при completed не отправляй дополнительный complete и
не задавай следующий вопрос; перейди к существующей summary. Для последнего ответа
или пропуска передавай next_competence=null и фактический selection_reason. Даже если
модель передаст продолжение, исчерпанная попытка всё равно завершится автоматически.
Next_difficulty остаётся совместимым обязательным полем события, не создаёт вопрос 16.

Досрочно завершить можно через complete, в том числе с pending_prompt: заданный вопрос
остаётся учтённым и сохранённым, но не создаёт фиктивный answer/skip/evidence.
После досрочного complete current_question=null: ответ больше не ожидается,
но сам неотвеченный pending_prompt сохраняется и asked не уменьшается.
Пауза на вопросе 15 сохраняет его номер; после resume ученик отвечает или пропускает
его, либо завершает попытку досрочно. Пока последний вопрос не разрешён, limit_reached
не означает автоматического завершения. После его ответа/пропуска завершение гарантировано.

В diagnostic CLI начальный next_difficulty можно опустить: он выбирается по
самооценке из preferences (zero/basics → basic, basic_experience/confident → applied,
significant_experience → transfer). Неизвестная/неинтерпретированная самооценка
даёт difficulty=null, calibration=true: передай явный next_difficulty для предметной
калибровки или сначала сохрани однозначную интерпретацию вместе с оригинальным текстом.
Выбор делает наставник по смыслу реплики, предмету, специализации и названным
пробелам, не регулярные выражения и не количество лет. Перед согласием
прочитай starting_guidance: предмет, direction/area, фактический text, цель и самооценка.
Выбор предметной задачи и её конкретность обеспечивает наставник по start-learning.md.
Не давай продвинутому Java-ученику начальное определение переменной по умолчанию.
В событии сохраняется обычный полный accept, diagnostic_learning_v1 не меняется;
старый явный next_difficulty поддерживается. starting_guidance относится только к
новой попытке и не заменяет сохранённый next_difficulty после ответа или паузы.
Ошибка требует сначала выяснить конкретный пробел; самооценка не создаёт evidence.

Компетенции выбирай по цели, названной области, материалам и уже проверенным
ответам; не используй универсальную таксономию областей. Формулируй наблюдаемое
действие, которое проверяет конкретный вопрос. Для фактов и условий задач
используй проверенные материалы; при недостатке контекста уточни или отметь
ограничение. Не выдавай предположение о знаниях за evidence.

Начальная сложность — гипотеза подачи, не подтверждение уровня. Для новичка начни
с basic (основы), при сообщённом опыте можно начать с applied (применение) или
transfer (перенос в новую ситуацию). После частично верного ответа объясни ошибку,
сохрани needs_practice и предложи более простой вопрос; после уверенного ответа
можно усложнить. Эти значения не являются числовой шкалой, рейтингом или mastery.

Ниже показаны совместимые базовые события для старого вопроса без rubric.
Для новых вопросов используй структурированный prompt и assessment из раздела выше;
не отправляй базовый answer без assessment на вопрос с rubric.

```json
{"action":"prompt","competence":"Проследить выполнение цикла","prompt":"Что напечатает for (int i=0; i<2; i++) System.out.println(i);? Объясни порядок.","difficulty":"basic","format":"code_analysis"}
```

Вопрос относится к одной из competences и текущей next_difficulty; после ответа
он обязан использовать сохранённую next_competence. Первый вопрос выбирает
ассистент из competences. Поле format описывает фактически предъявленное задание:
`single_choice` — один вариант, `multiple_choice` — несколько вариантов, `open` —
свободный ответ, `practical` — практическая задача, `code_analysis` — разбор кода,
`bug_search` — поиск ошибки, `explanation` — объяснение решения или понятия.
Выбирай формат по проверяемому действию, а не чередуй механически. Сохрани вопрос до
ответа; одновременно допустим один pending_prompt. Ответ ссылается на его revision:

```json
{"action":"answer","prompt_revision":2,"answer":"Напечатает 0 и 1, затем условие станет ложным","evaluation":"Обе итерации и выход объяснены; это проверка одного примера","evidence":"confirmed","next_difficulty":"basic","next_competence":"Объяснить уникальность ключа в map","selection_reason":"Порядок итераций объяснён на одном примере; теперь проверяем ещё не затронутую компетенцию о ключах map"}
```

После каждого фактического ответа выбери next_competence из competences,
next_difficulty и запиши selection_reason: что именно показал ответ и почему
нужен следующий вопрос. Это может быть уточнение той же компетенции, более простой
пример после ошибки, перенос после уверенного ответа или переход к ещё не
проверенной компетенции. Следи за охватом нескольких компетенций, не повышай
сложность только внутри одной и не переключай область молча. Перед следующим
вопросом объясни выбор ученику. Если это последний ответ перед complete, сохрани
`next_competence: null` и непустой selection_reason с фактической причиной
завершения и границами проверки. Не придумывай следующий вопрос ради записи.
После такого ответа новые prompt запрещены, включая после pause/resume; для новых
вопросов заверши попытку через complete и получи согласие на новый accept.
Скрипт проверяет принадлежность и переход;
содержательность причины и оценку ответа проверяет ассистент.

Answer сохраняет исходный prompt/difficulty/format, конкретную competence, фактический
answer и объяснение evaluation. evidence — `confirmed|needs_practice|unknown`:
подтверждение проверенного действия, наблюдаемая необходимость практики или
недостаточность ответа для вывода. Частично верный ответ не подтверждает всю тему.
«Не знаю» как реальный ответ на вопрос сохрани с unknown и пояснением; предложи
более простой пример или следующую компетенцию с конкретной причиной. После
частичного ответа укажи верную часть и пробел, затем выбери уточнение или практику.
Молчание не создаёт answer и оценку: предложи паузу либо завершение, сохраняя
нерешённый вопрос. Явный пропуск отдельного вопроса сохраняй отдельно и не
считай неверным ответом:

```json
{"action":"skip","prompt_revision":2,"next_difficulty":"basic","next_competence":"Объяснить уникальность ключа в map","selection_reason":"Вопрос о цикле пропущен; продолжаем с другой непроверенной компетенцией","skip_reason":"Эту тему ещё не изучал"}
```

`skip_reason` необязателен и может быть null. `next_competence` должен быть другой
оставшейся компетенцией либо null, если диагностику нужно завершить. Пропуск
сохраняет сам вопрос и причину, но не создаёт evidence; такая компетенция остаётся
непроверенной. Для нового набора вопросов после завершения нужен новый accept.
Не сохраняй выдуманные ответы.

Действия `{"action":"pause"}`, `{"action":"resume"}`, `{"action":"complete"}`
передаются по одному. Pause сохраняет pending_prompt и ответы; resume возможен
только из paused и возвращает accepted, в том числе из другого чата. Пока paused,
новые вопросы/ответы запрещены. Complete завершает активную диагностику даже с
непроверенными компетенциями или оставшимся вопросом: незавершённое сохраняется,
не превращается в evidence. Назови неизвестное явно; complete не означает освоение.

`{"action":"decline"}` создаёт отдельный отказ; accept/decline начинают новую
попытку только если прежняя завершена или отклонена. При активной/paused сначала
продолжи или заверши прежнюю. Последующие диагностики добавляют историю, не
перезаписывают прошлую. Чтение возвращает current и attempts (с реальными answers),
а также summary: проверенные компетенции, подтверждённые знания, частичные
подтверждения, пробелы, непроверенные области, пропущенные вопросы, рекомендуемую
точку начала и ограничения достоверности. Summary формируется из сохранённой
попытки и не пишет отдельный файл, поэтому одинаково доступен после перезапуска
и в другом чате.
status=`not_started|accepted|declined|paused|completed`, last_action хранит конкретный
переход. Если компетенция отсутствует в answers, она остаётся неизвестной.

Хранение: `learners/USER/diagnostic-learning.json`, schema=diagnostic_learning_v1,
последовательные revision/events, timestamp, reason и session каждого события.

Контракт расширения v1: обязательные прежние поля действий сохраняются. В новом
prompt обязательно `format` из перечисления выше. В новом answer обязательны
`next_competence` (непустая строка до 1000 символов, точное имя из competences,
либо null для последнего ответа перед complete) и `selection_reason`
(непустая строка до 4000 символов: причина выбора или завершения). Они сохраняются в answer
и в current как последний выбор; следующий prompt обязан совпасть с ним и с
next_difficulty. В новом skip обязательны `prompt_revision`, `next_difficulty`,
`next_competence` и `selection_reason`; необязателен `skip_reason` (строка либо
null). При next_competence=null следующие prompt запрещены;
next_difficulty остаётся обязательным полем совместимого события, но не назначает
будущий вопрос. Format копируется из вопроса в answer. Остальные текстовые поля
сохраняют прежние ограничения; неизвестные поля и неподдерживаемые значения
отклоняются без записи. Смысловую конкретность selection_reason обеспечивает
ассистент, скрипт проверяет наличие текста, а не оценивает рассуждение.

При чтении старых событий format может отсутствовать, а next_competence и
selection_reason могут отсутствовать вместе. Одно поле пары без другого невалидно.
Старым событиям ничего не дописывается, их байты и прежнее представление attempts
не меняются, неизвестный формат/выбор не угадывается. До первого нового answer
в старой попытке следующий вопрос можно выбрать из её competences; новые записи
уже требуют расширенные поля. Schema остаётся diagnostic_learning_v1; это
совместимость нового читателя со старой историей, старый плагин не обязан читать
расширенные события. После обновления не редактируй журнал старым плагином.

Журнал общий для чатов профиля в курсе; разные профили/курсы независимы. ID попытки —
revision её accept/decline. Это позволяет ссылаться на факт, не копируя его в progress.
Файл и его части переносятся вместе с профилем, абсолютных путей в событиях нет.
Отсутствующий файл означает not_started/revision=0; чтение ничего не создаёт и не
требует миграции старого профиля. Допустим history-limit 0..100; весь attempts
возвращается независимо от него. Журнал ограничен 64 MiB, большие документы
используют существующий document_parts_v1 и diagnostic-learning-objects.

Запись под блокировкой, атомарная и с обязательным expected-revision; при конфликте
перечитай состояние вместо перезаписи. Повреждение/неизвестная схема дают valid=false,
запись не исправляет их молча. Ссылки и hard links на журнал отклоняются.
Диагностика не пишет intent, preferences, onboarding, unit_learning, course.progress
или маршруты и не назначает следующий учебный шаг автоматически. Используй узкое
свидетельство как основание обсуждения; согласование плана остаётся отдельным действием.
