# Загрузка видео 0.3.6

У prepare есть `--download-fragments N` (1..8, по умолчанию 4) и `--site-timeout SEC`
(120..7200, по умолчанию 1800). Эти параметры относятся к страницам площадок через
yt-dlp; прямые HTTP-файлы и Яндекс.Диск сохраняют свой загрузчик и прежние таймауты.
N ограничивает параллелизм фрагментированного протокола, а не число видео.
При ошибках доступа не увеличивай N: верни 1–2 или используй локальный файл.

Загрузчик выдаёт прогресс с новыми строками и интервалом обновления около 5 секунд;
это вывод yt-dlp, не стабильный машинный API процентов. Метаданные проверяются
до загрузки; скачивание имеет отдельный общий timeout. Отсутствующий фрагмент
прерывает загрузку вместо публикации заведомо неполного ролика. Проверка первых
кадров и хеша сохраняется, но не доказывает отсутствие дефектов во всём видео.

В папке video сохраняется download-status.json последней попытки сайта:
running, ready, failed или interrupted; failed может иметь категории timeout,
access_required, network, unsupported, site_failed либо validation_or_download_failed.
Сообщения доступа и сети классифицируются по диагностике yt-dlp: это подсказка,
не точное определение причины. Сырой stderr и URL-токены в status не сохраняются.
При успешной загрузке предупреждения yt-dlp выводятся в stderr; они не теряются.
Для принудительного убийства процесса запись running может остаться незавершённой:
проверь процесс перед повтором. Status не является свидетельством целостности;
опирайся на download.json и штатные проверки хеша.

Кэш читается до сети. Изменение N/timeout не перескачивает проверенный файл и
не меняет pin. Прямой HTTP resume работает по прежним правилам. Частичные загрузки
сайтов после ошибки по-прежнему удаляются; продолжение HLS между запусками не
реализовано. Публичность ссылки не гарантирует доступность: авторизация, DRM,
география и ограничения площадки могут препятствовать загрузке.

Скорость зависит от сервера и протокола. Проверены настоящий yt-dlp на локальном
HLS и офлайн-кэш; ускорение конкретного Rutube/YouTube ролика в этом выпуске
не измерялось. Предупреждение об отсутствии ffprobe возможно с bundled ffmpeg;
сохраняй его и оценивай результат штатного декодера, не объявляй диагностику полной.

## Диагностика в status (0.3.8)

Для каждого занятия status возвращает download_diagnostics без сетевого запроса
и пересчёта хеша видео. media_integrity=not_checked и advisory_only=true означают,
что это только отчёт о последней попытке. ready не доказывает сохранность кэша;
running не доказывает, что процесс ещё работает. Используй штатные prepare/context
для проверки источника перед обучением.

Новые отчёты имеют UTC-время и SHA256 адреса источника (не содержимого видео).
source_binding=source_url_matches подтверждает только совпадение адреса. Старые
отчёты читаются как legacy_unbound, без автоматической привязки. Для другой ссылки
показывается source_mismatch. Отсутствие отчёта даёт not_recorded — это обычная
ситуация для старых курсов, локальных файлов и прямых загрузчиков. unreadable означает
повреждённый/неподдерживаемый отчёт; сам файл не переписывается. Прогресс остаётся
доступным. Сырой message и неизвестные поля не передаются из отчёта в status.
next_step строится из известных состояний/категорий. Предел диагностического файла
64 KiB, ссылки и специальные файлы не читаются. Это не изоляция от враждебного
процесса с теми же правами и не аутентификация источника отчёта.
