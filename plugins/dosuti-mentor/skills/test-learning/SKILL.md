Явно сообщи: это тестовый прогон, учебные данные будут в отдельной папке.
Используй scripts/pilot.py из этого пакета; контракт и команды:
[external-pilot.md](../../references/external-pilot.md).
Для замеров, плана 5–10 вопросов теории и 5–10 заданий практики, единого отчёта
и очистки прочитай [pilot-evidence.md](../../references/pilot-evidence.md).
Следуй этому контракту на протяжении прогона, а не только в конце.

В текущей выбранной папке проекта сначала проверь только известный маркер
.dosuti-pilot.json. Если он есть, вызови pilot.py project-status --project PROJECT
(с chat ID при явных overrides). При connected=true используй возвращённый pilot,
course/profile и status; не спрашивай путь, не начинай новый прогон. Если чат
отключён, выбран другой курс или нужен chat ID, уважай это и уточни выбор.
Не ищи маркер в соседних/родительских проектах. Проект не открыт автоматически:
человек должен один раз открыть подготовленную папку project в Codex.

При новом Windows-прогоне не требуй заранее созданного курса/маркера и ручной
обработки видео. Сначала выясни цель и подачу по start-learning, используя уже
сказанное; затем попроси ссылку или локальный файл, если источник ещё неизвестен.
Проверь наличие Start-WindowsPilot.ps1 и Windows-Runtime.ps1 в текущей явно
выбранной распакованной папке. Сверь версию её plugin.json с этим установленным
пакетом. Если папка неизвестна, попроси открыть переданную распакованную сборку;
не сканируй компьютер и не скачивай вместо неё старую GitHub-версию.

По выбранной ссылке/файлу сам запусти Start-WindowsPilot.ps1 -Video SOURCE
-CpuMode economy доступным инструментом исполнения. Строку SOURCE передавай
как один аргумент, не исполняемый shell-текст. Локальное скачивание человеком
перед этим не требуется. Выбери отдельный PilotRoot, используй существующий
управляемый тестовый корень при повторе; не переопределяй другую привязку молча.
После ошибки прочитай SETUP_REPORT.md и доступный status, не создавай новый корень
для каждого повтора. При недоступном исполнении/ограничениях PowerShell честно
объясни конкретную причину вместо обещания уже идущей подготовки.

При passed прочитай возвращённые pilot/course и параметры подключения. Если человек
просит тест именно в текущем проекте, свяжи QA с ним через connect-project после
чтения актуальной ревизии; при существующем другом подключении уточни замену.
Иначе предложи открыть возвращённый project. Для URL занятие уже зарегистрировано
и скачано в course/lessons/video-ID: найди его по сохранённой source и SHA256,
не регистрируй и не скачивай ту же ссылку ещё раз. Короткий smoke подтверждает
среду, а не подготовку/освоение всей лекции: дальше prepare-lecture по этому lesson.
Уточни ещё неизвестные код, домашку и ресурсы. Сохрани ранее полученные ответы
знакомства в созданном QA-профиле, не спрашивая их заново.

При новом прогоне на других платформах или с готовым runtime выбери новую папку вне установленного плагина, runtime и обычных
курсов. start создаёт отдельный course, профиль pilot. При продолжении сначала
status по известной папке, не создавай новый прогон и не повторяй знакомство.
Не переключай существующее подключение проекта на QA без просьбы пользователя.
Для обычных учебных команд всегда указывай course из status и профиль pilot
(где поддерживается); для каждого нового чата используй отдельный session.

Проведи обычный start-learning: реальные цель, уровень, предпочтения и обсуждение
маршрута. Тестовый статус не разрешает отвечать за человека, принимать план за
него или придумывать оценки. Можно пропустить любой этап с явной отметкой.
В первых сообщениях выясни удобный формат объяснений, темп и цель, сохрани настройки.
Затем prepare-lecture по его материалам, teach-lecture/teach-unit и review-homework.
Уточни наличие кода, домашки и допматериалов; при пробелах предложи research-topic
с фактической проверкой источников. Создай assessment-plan перед проверкой.
Ответы и подсказки записывай по одному в assessment-answer; допускай паузу и пропуск.
Не ограничивай полный тест одним вопросом, но не заставляй проходить всё за сеанс. Читай соответствующий навык
при переходе. Сверяй кадры/код/реплики; фиксируй неопределённости и ошибки.

Записывай итог каждого этапа сразу. installation оценивается по факту действий
тестировщика, не по тому, что этот навык доступен. environment — doctor и реальный
короткий медиа-прогон перед длинной обработкой. На Windows локальный Apple Vision
недоступен: покажи ограничение и продолжи с кадрами, если чат умеет их просматривать.
Присутствие зависимостей не равно успешной обработке. Нужда в ручной помощи,
время ожидания и ошибки установки — полезные результаты теста.

Для установки/runtime используй [единый сценарий](../../references/pilot-setup.md):
ранние ошибки и версии хранятся в setup.json/SETUP_REPORT.md до появления курса.
Если среда уже готова, повторные загрузки не нужны: offline проверит её и короткий
фрагмент. Курс можно явно привязать к отдельному пустому тестовому проекту через
pilot.py connect-project. Обычный проект пользователя не переключай на QA.

После урока предложи открыть новый чат в том же подключённом тестовом проекте.
Он найдёт pilot через project-status. Для отдельного чата вне проекта передай путь pilot. Проверь сохранённые
цель, настройки, принятый/предложенный план и продолжение по обычным инструментам.
Не объявляй resume пройденным по чтению status в старом чате. Проверка спустя
сутки требует реального времени и нового ответа; один сеанс её не заменяет.

Запрашивай отзыв коротко: что получилось, что мешало, насколько понятно объяснение,
какую ошибку человек заметил. tester_feedback заполняй только его словами, свои
выводы помещай в observation. Не задавай все вопросы сразу ради формальности.
После каждого этапа/серии ответов экспортируй единый TEST_REPORT.md, чтобы частичный
результат уже лежал на диске. Он включает setup-попытки, замеры, ответы и отзыв.
Если до run не дошло, покажи доступный SETUP_REPORT.md.
Предложи проверить личные данные перед
ручной передачей. Скрипт не очищает произвольный текст от секретов автоматически.

После запроса на удаление сохрани единый отчёт снаружи и подготовь cleanup-plan
по pilot-evidence. Очистку выполняй только для показанной собственной тестовой
папки; не удаляй исходные материалы вне неё и общий runtime. Плагин и историю
чатов удаляют отдельно средствами Codex после очистки, пока скрипты ещё доступны.
Не объявляй полное удаление по одному status/test_data_removed. До фактической
проверки removal остаётся not_checked; человек может дописать итог во внешний отчёт.

При продолжении читай continuation из status/project-status с фактической --session.
Там есть открытые операции, следующий вопрос текущего плана и сохранённые настройки;
проверь обычный учебный checkpoint. Устаревший план не продолжай как актуальный.
Для зависшего автоматического таймера используй interrupted с причиной; активный
worker блокируется lease. Legacy без владельца требует явного
--allow-unknown-owner после проверки, что обработка действительно остановлена.
Не подставляй нулевую длительность. При pending cleanup доступен только статус
восстановления и повтор cleanup-apply, не продолжение обучения.
Экспорт возвращает coverage.complete. Не удаляй данные при false: поправь причину
неполноты или сохрани их до следующей попытки. Старый план очистки пересоздай.
