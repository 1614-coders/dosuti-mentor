Выясни ближайшее умение и задачу проекта по уже известной цели. Не превращай просьбу
научиться в написание всего приложения за ученика. Сначала используй имеющиеся
курс/профиль/настройки по [connections.md](../../references/connections.md), при
необходимости [start-learning](../start-learning/SKILL.md). Не меняй подключение
проекта или реальный курс ради теста. Поддержка проверена на узких Java-сценариях;
другие языки требуют своей среды и проверки, не обещай универсальную приёмку.

## Основания и история

Прочитай [project-learning.md](../../references/project-learning.md).
Если есть серия, прочитай project-timeline --timeline-id и выбранный переход:
список ID не подтверждает актуальность снимков. Если серии нет, собери её только
по имеющимся материалам с явным порядком/репозиториями/current или pinned.
Узнай, связаны ли репозитории, если оснований нет. Не объединяй их по сходству имён.
При отсутствии промежуточной записи/кода отметь gap; не реконструируй автора из догадок.
Для одной лекции без серии используй teach-lecture, для новой темы — research-topic.

Изменения файлов показывают состояния до/после, а не причину и порядок действий.
Проверь before/after, stale, gap, truncated и неоднозначные кандидаты переноса.
Не выдавай same_content_move_candidate за установленное переименование.
Для реального экранного объяснения сверь код с кадрами и записью через teach-lecture;
привязывай stage к правильному концу перехода. Даже matches — ручная аннотация,
не доказательство непрерывного изменения на видео. partial/differs/unknown сохрани.

Если объяснение зависит от речи преподавателя, добавь video-источник unit для
нужного диапазона: stage сам по себе не закрепляет всю расшифровку/ASR.

Не подменяй промежуточный код финальным. При gap можно объяснить сохранённые
состояния по отдельности и дать собственное упражнение, но нельзя приписать
переход преподавателю. При неполной/неработающей сборке покажи ограничение;
возможное исправление обозначь собственным вариантом, не оригиналом автора.

## Учебная задача

Выбери небольшой законченный переход/аспект. Объясни, что подтверждено источниками,
и предложи ученику одну задачу: воспроизвести поведение, разобраться в изменении,
дописать небольшой метод или проверить его тестом. Теорию давай в объёме задачи.
Сохрани критерии результата и исходные условия в собственном assistant-материале;
при наличии задания преподавателя используй его и уточни покрытые критерии.

Подготовь unit по project-learning: kind=timeline для зависимости, отдельные
kind=code с конкретными версиями/строками для примеров до/после, text для своей
практики; при необходимости video/homework/resources. Объясняющая причина в твоём
материале — гипотеза, пока не сверена с речью/материалом автора. Не скрывай её в
summary как факт. В text-снимок включай нужный код, а не только имя внешнего файла.

Код ученика и свои изменения держи в выбранной рабочей папке вне sealed-снимков
преподавателя. При неясном месте сначала уточни папку. Чужие сборки/скрипты осмотри
перед запуском; для небольшого своего примера применяй правила проверки из
[research-lesson.md](../../references/research-lesson.md). Не устанавливай зависимости
или запускай сервисы только ради приветствия. Фактические команды/вывод/версию среды
сохраняй в заметках практики, не называй статический разбор успешной компиляцией.

## Обучение и продолжение

После создания или выбора unit прочитай learn-unit с profile/session и продолжай
через [teach-unit](../teach-unit/SKILL.md). Это единый журнал результатов, не второй
автоматический зачёт через старый lesson/progress. При stale сначала сверь основание;
не пересохраняй карточку автоматически для обхода проверки.

Объясняй по настройкам пользователя, затем дай практику и дождись ответа/кода.
Подсказывай постепенно; готовое решение по явной просьбе допустимо, но не означает
самостоятельное выполнение. Сохрани реальный вопрос, ответ, подсказки и проверенные
критерии. Для solved_independently нужна новая самостоятельная попытка после помощи.
Компиляция проекта без ответа ученика не доказывает его понимание.

Для выбора следующей практики учитывай learning.adaptive или review-learning:
ошибка/помощь/самостоятельное решение требуют разных шагов; пропуск не ошибка.
Проверку позже не отмечай до фактической новой попытки и нужного интервала.

Сохраняй checkpoint этого чата: что разобрано, какое состояние проекта/версия
использованы, следующий шаг и незавершённая задача. Другие чаты профиля видят общие
попытки, но имеют свои checkpoints. Смена исходников или объяснения требует сверки
и сохраняет историю; смена цели не стирает уже выполненные задачи.
