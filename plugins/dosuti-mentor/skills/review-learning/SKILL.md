Используй [connections.md](../../references/connections.md) для курса/профиля и
стабильного session ID. Прочитай [adaptive-learning.md](../../references/adaptive-learning.md)
и study-next; для выбранной темы затем learn-unit. Это рекомендации текущей модели
по сохранённым данным, не измеренная готовность к профессии и не фоновый таймер.

Для принятого маршрута используй study-next.roadmap: он связывает рекомендацию
с компетенцией, обоснованием и фактическими целевыми критериями. Объясни один
подходящий следующий шаг: ошибка — разбор/практика, помощь — новая самостоятельная
задача, объяснение — проверка, наступивший срок — повторение, подтверждённые
целевые критерии — следующая доступная тема. Уважай skip/defer и зависимости.
Один подтверждённый target не означает освоение всех критериев unit.
Review_route означает обсуждение изменений; покажи отличие от plan и только после
согласия принимай отдельный proposal с актуальным adaptation_basis. При
incomplete не выбирай продолжение по неполным данным. При legacy_unmapped
используй имеющиеся свидетельства, не создавай targets или оценки задним числом.
Непокрытый пробел требует содержательного сопоставления, не случайной темы.

Если есть текущий вопрос/checkpoint чата, учитывай его до переключения темы.
Покажи один ближайший вариант с понятной причиной: ошибка, решение с подсказкой,
наступившее повторение или ещё непроверенный критерий. Пользователь может выбрать
другую задачу, пропустить или отложить. Не навязывай очередь, не отмечай отказ ошибкой.
Никаких новых оценок при простом чтении/приветствии/истечении времени.

Учитывай route_state preliminary/proposed/accepted и needs_review в learning_intent.
Сначала прочитай `learning_progress`: в нём единообразно видны изученные/
подтверждённые unit, диагностические пробелы, checkpoint текущего чата и ближайший
шаг принятого маршрута. `diagnostic_guidance` объясняет приоритет шага по
фактической оценке, но не заменяет выбор пользователя и не перестраивает план
автоматически.
История lesson/unit видна и при отсутствующем/неактуальном плане; не называй её
пустой из-за смены цели. При `needs_review` не предлагай следующий шаг старого
маршрута. Сверяй `continuations`: при `continuation_choice_required` предложи
ученику выбрать точку, не назначай последнюю по ревизии. Старый lesson-курсор
общий для профиля, unit-checkpoints имеют session. `legacy_recorded_claim`
означает старую сохранённую оценку, не независимую проверку критериев unit.
Прочитай основания ближайшего шага (step_bases/basis_status либо career_status),
сопоставь с реальными ответами и доступным unit. Диагностика может отсутствовать
или быть отклонена: назови неизвестное, не блокируй обучение. Смена цели требует
нового предложения; прежние ответы сохраняются. study-next только читает данные:
не принимай и не перестраивай маршрут автоматически по очереди рекомендаций.

Проверь valid, blocked/stale, версию источников, learning_intent, предпосылки и
настройки подачи. Ошибка источника требует сверки, а не переобучения ученика.
При повреждённом журнале объясни ограничение сохранения/рекомендаций, сохрани файл.
Если unit нет, предложи подготовить материал через prepare-lecture/research-topic
или текущую помощь Codex, не выдумывай прошлый результат.

## Практика и проверка

Для review_error прочитай последний фактический ответ из adaptive.evidence_events
по evidence_revision критерия и разбери question/answer/details/error_tags,
не делай личностных выводов. Для fresh_independent_task дай новую подходящую задачу,
после помощи не повторяй готовый ответ как самостоятельный успех. Для recheck_due
подбери задачу на перенос понимания, не тот же вопрос с переставленными словами.
Объяснение темы веди через [teach-unit](../teach-unit/SKILL.md); для проекта
доступен [teach-project](../teach-project/SKILL.md).

Успешную проверку позже сохрани checked_later только если есть фактический ответ,
нет подсказок, baseline каждого проверенного критерия — последняя самостоятельная
попытка той же версии, прошло минимум24ч и задача содержательно новая. Сопоставь
recheck_of с evidence_revision выбранных критериев до ответа; не подменяй baseline
после конфликта. Ранняя новая задача может быть solved_independently, но не later.
Не исправляй время реального профиля ради прохождения ограничения.

Неверный ответ — needs_review с конкретным объяснением и наблюдаемыми error_tags;
ответ после помощи — practice_with_help. Теги необязательны и относятся к ответу,
не ученику. Письменный вывод/правильность оцениваешь ты; CLI лишь проверяет контракт.
Не выставляй все критерии по одному частичному ответу и не выдумывай ответы.

## Выбор и продолжение

Если человек просит пропустить/отложить/вернуться, запиши review_decision только
по названным критериям с фактической причиной. Для «позже» без даты можно предложить
ближайший срок, но не выдумывай согласие на обязательное расписание; skip сохраняет
пропуск без срока, если именно это выбрано. Нет автоматической рассылки уведомлений.

Записывай через learn-unit с текущими CAS/SHA. При конфликте перечитай, учти новые
ответы/решения; не подставляй свежую ревизию в старую оценку автоматически.
Checkpoint сохраняет вопрос/следующий шаг именно этого чата; другой чат не начинает
его заново без причины. История ответов общая внутри выбранного профиля курса.
Рекомендация и принятие плана не равны освоению, а checked_later не гарантирует
память навсегда. Следующий шаг выбирай с учётом задачи человека и данных, а не
только формального приоритета.
