# Windows: подготовка внешнего тестового прогона

Статус: кандидат 0.4.40 для первого внешнего теста, не подтверждение совместимости.
Полный запуск на Windows ещё не выполнен. `$test-learning` и локальный журнал
реализованы. Репозиторий: https://github.com/1614-coders/dosuti-mentor .

## Быстрый сценарий подготовки

В распакованном пакете рядом с README.md запустить:

```powershell
.\Start-WindowsPilot.ps1 -Video 'C:\Videos\lecture.mp4'
```

Нужен установленный Python3.12 с launcher py (либо -PythonExecutable). Скрипт
проверит зависимости/FFmpeg, скачает локальную модель и обработает30секунд с речью
на CPU. Если в начале тишина, выбрать -Start и -Seconds. При сбое покажет отчёт;
повтор сохраняет прежние попытки. Он не устанавливает сам плагин Codex.

После успеха **открыть выданную папку project в Codex**, вызвать $test-learning.
Новый чат в этом же проекте может написать «продолжи тест»: путь уже в привязке.
Вне этого проекта по-прежнему нужен явный выбор тестового прогона.
Детали, вариант без ps1, offline и ранние отчёты:
[pilot-setup.md](plugins/dosuti-mentor/references/pilot-setup.md).

## Окружение и установка runtime

Первый целевой вариант: Windows x64, Python 3.12, PowerShell, Codex с доступом
к локальной папке. Windows ARM требует отдельной проверки зависимостей.
Распаковать исходный пакет в отдельную папку и открыть PowerShell в её корне
(рядом с README.md). Установка runtime скачивает зависимости из интернета:

```powershell
py -3.12 --version
$LtPilotRoot = Join-Path $env:LOCALAPPDATA 'DoSutiMentorPilot'
py -3.12 -X utf8 .\plugins\dosuti-mentor\scripts\setup_local.py --runtime "$LtPilotRoot\runtime"
& "$LtPilotRoot\runtime\venv\Scripts\python.exe" .\plugins\dosuti-mentor\scripts\course.py --help
```

Активация venv и изменение ExecutionPolicy не нужны. Если `py` недоступен,
сначала установить Python 3.12 с Windows launcher либо указать полный путь
к установленному python.exe. Не подменять этот этап сообщением «готово».
Модель распознавания речи скачивается отдельно; наличие Python-пакетов не
доказывает, что модель загружена и работает. Использовать CPU для первого пилота.

Локальный Apple Vision OCR на Windows недоступен. Doctor сообщает
`unsupported_platform`, не запускает Swift и не блокирует обычное обучение.
Кадры можно показывать и разбирать в чате при доступной возможности просмотра
изображений; это не локальный OCR и не доказанная автоматическая сверка кода.
Локальная обработка видео/речи не делает сам Codex офлайн-системой.

## Подключение и первый тест

Добавить marketplace из GitHub-репозитория,
установить DoSuti Mentor через каталог плагинов Codex, открыть новый чат в
отдельной тестовой рабочей папке. Для добавления источника через CLI применяется
`codex plugin marketplace add https://github.com/1614-coders/dosuti-mentor.git`
и затем `codex plugin add dosuti-mentor@dosuti-mentor-local`.
Этот способ загружает текущую версию default branch, не закреплённый тег.
Загрузка Python runtime отдельно не устанавливает плагин в Codex.

В новом чате вызвать `$test-learning` и сообщить:
«Проведи тестовый прогон на Windows. Используй отдельный тестовый курс,
сохраняй этапы и отчёт, затем помоги разобрать мою лекцию».
Codex выберет новую папку прогонов рядом с runtime, но вне него, и покажет путь.
Цели, настройки, ответы и оценки этого теста остаются в тестовом курсе.
Первичная загрузка ASR-модели требует сети и места на диске. Попросить Codex
использовать CPU и сначала короткий фрагмент. Не требуется CUDA/NVIDIA.

В подготовленном тестовом проекте новый чат находит прогон через project-status.
Если используется отдельный чат вне проекта, передать путь: «продолжить тестовый
прогон из <путь>». Он читает журнал и продолжение, не знакомится заново.
После реального урока попросить экспортировать отчёт. Если что-то сломалось,
экспортировать частичный отчёт, не пытаться выдать все этапы за пройденные.

Если плагин вообще не установился, заполнить [шаблон](TEST_REPORT_TEMPLATE.md)
вручную: ошибка установки — полноценный результат теста.

## Отчёт и удаление

Открыть TEST_REPORT.md и SETUP_REPORT.md (если запускали подготовку), проверить личные данные в заметках и сохранить отдельную
копию вне тестовой папки. Передать её вручную. Отчёт не содержит видео/репозиторий
автоматически, но записанные человеком или Codex заметки требуют просмотра.

Затем удалить DoSuti Mentor через настройки плагинов Codex. Материалы курса,
runtime и модель хранятся отдельно; удаление установки не гарантирует их очистку.
По желанию удалить только созданную для пилота папку DoSutiMentorPilot, предварительно
убедившись, что там нет нужных курсов и что отчёт скопирован наружу. Не удалять
общие Python/Git или каталоги других плагинов. Если модель лежит в общем кэше,
не очищать весь кэш ради этого теста.

Отметить результат удаления в скопированном Markdown вручную. Для последующей
обычной версии установить актуальный релиз и начать обычный курс через
`$start-learning`. QA-прогресс автоматически в обычный курс не переносится.

Проверка Windows-ветвей с mock на macOS не заменяет запуск на Windows.
