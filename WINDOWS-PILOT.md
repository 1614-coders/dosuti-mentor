# Windows: помощь с тестовым запуском

Для первого запуска следуй [четырём шагам в README](README.md#первый-запуск-на-windows).
Здесь — подсказки при ошибках и удаление после теста. Версия плагина — 0.4.57;
реальная проверка на Windows ещё не выполнена. Целевой первый вариант — Windows x64,
Python 3.12, PowerShell и Codex с доступом к локальным папкам. ARM требует отдельной проверки.

## Команда codex не найдена

Наличие приложения само по себе не подтверждает, что CLI доступен в PowerShell.
Установи Codex CLI по [официальной инструкции OpenAI](https://learn.chatgpt.com/docs/codex/cli),
выбрав вариант Windows. Закрой и заново открой PowerShell, проверь `codex --version`,
затем вернись к шагу 2 README. Если команда есть, но `plugin` не поддерживается,
обнови CLI по той же инструкции.

Не устанавливай случайный одноимённый пакет и не считай подключение пройденным,
пока команды добавления источника и установки плагина не завершились успешно.

## Команда py не найдена или Python 3.12 отсутствует

Это больше не блокирует `Start-WindowsPilot.ps1`: он ищет рабочий CPython
3.11/3.12 x64, проверяет SSL, создание venv и запуск pip. Если подходящей копии нет,
скачивает фиксированную сборку Python Build Standalone в `PilotRoot\runtime\python`,
проверяет SHA256 архива и python.exe. Для автоматической распаковки нужен `tar.exe`.
Сетевые ошибки и несовпадение SHA останавливают установку с отчётом.
Если хочешь выбрать существующий Python явно, укажи путь:

```powershell
.\Start-WindowsPilot.ps1 -Video 'C:\Videos\lecture.mp4' -PythonExecutable 'C:\Path\To\Python312\python.exe'
```

Оба пути в примере нужно заменить на свои. PATH и реестр не настраиваются.
Bootstrap-отчёт находится в `PilotRoot\reports`; только при ошибке до подготовки
самой папки он сохраняется рядом с ней. `-Offline` запрещает автозагрузку Python,
моделей и зависимостей; этот режим требует уже подготовленного runtime.

## PowerShell запрещает запуск ps1

Используй тот же сценарий напрямую через Python из распакованной папки рядом с README:

```powershell
py -3.12 -X utf8 .\plugins\dosuti-mentor\scripts\pilot_setup.py --root "$env:LOCALAPPDATA\DoSutiMentorPilot" --video 'C:\Videos\lecture.mp4'
```

Этот запасной способ требует уже установленного подходящего Python.
Замени путь к видео. Активация venv и изменение ExecutionPolicy не нужны.
Если сама оболочка не дала запуститься ps1, он не мог записать отчёт: сохрани
текст ошибки вручную. Не выполняй подряд ручную установку runtime и основной
сценарий в одну неподготовленную папку — это разные способы настройки.

## Папка уже существует, но не содержит setup.json

Сценарий не принимает обычную папку за свою и не удаляет её содержимое.
Выбери новую отдельную папку:

```powershell
.\Start-WindowsPilot.ps1 -Video 'C:\Videos\lecture.mp4' -PilotRoot "$env:LOCALAPPDATA\DoSutiMentorPilot-Test2"
```

Если прежний setup.json есть и читается, повторяй исходную команду: история
попыток и учебный курс сохранятся. Повреждённый журнал сначала сохрани для разбора.
Переустановка плагина не требует удаления лекций или обычных курсов.

## Загрузка долгая или оборвалась

Смотри текущий шаг и `attempt-*.log` внутри тестовой папки. Ограниченный хвост
обновляется во время выполнения. Медленное скачивание не означает зависание;
на первом запуске загружаются библиотеки и модель. После сетевой ошибки можно
повторить ту же команду: pip использует доступный кэш, загрузчик модели проверяет
сохранённые части. Не удаляй историю ради повтора.

## Нет распознанной речи

Выбери участок, где речь отчётливо слышна. Например, начать с 60-й секунды:

```powershell
.\Start-WindowsPilot.ps1 -Video 'C:\Videos\lecture.mp4' -Start 60 -Seconds 30
```

Модель работает на CPU, CUDA/NVIDIA не требуется. Успех короткой обработки
не доказывает точность всех слов или экранного кода. Несколько аудиодорожек,
повреждённое видео и другие ошибки записываются для разбора; их нельзя отметить
как успешное обучение. При недоступной ссылке сначала предоставь локальный файл.

## Codex не видит навык или начинает тест заново

После установки открой новый чат и проверь доступные навыки: имя может быть
`test-learning` или `dosuti-mentor:test-learning`. Если плагина нет, вернись к
подключению, не начинай повторную обработку видео.

Открыть нужно папку `project`, которую вывел сценарий подготовки, а не папку
скачанного репозитория. Новый чат должен находиться в том же тестовом проекте.
Если он открыт в другом месте, явно передай путь тестового прогона из поля `pilot`.
Не создавай новый курс только потому, что потерялась привязка.

При отдельных отключениях/привязках чатов может понадобиться известный ID чата.
Глобального поиска прогонов по компьютеру и автоматического определения нативного
ID нет. [Подробности подключения](plugins/dosuti-mentor/references/external-pilot.md).

## Где отчёт, если что-то сломалось

- `SETUP_REPORT.md` в тестовой папке — установка, версии и ошибки до создания курса.
- `run/TEST_REPORT.md` — единый экспорт установки, времени, материалов, ответов и отзыва, если курс уже появился.
- `reports/bootstrap-*.md` — проверка/выбор Python; при самом раннем отказе
  `DoSuti-bootstrap-*.md` находится рядом с тестовой папкой.

Если плагин вообще не установился, используй [ручной шаблон](TEST_REPORT_TEMPLATE.md).
Частичный отчёт полезен. Перед передачей проверь Markdown и нужные логи на личные
данные: автоматическое маскирование неполное. Видео/модели отправлять для отчёта
по умолчанию не требуется; автоматической отправки нет.

## После теста

Заверши обработку и закрой тестовые чаты/проект. В PowerShell из распакованной
папки плагина выполни:

```powershell
.\Complete-WindowsPilot.ps1
```

Команда сохранит отчёт и план в `%USERPROFILE%\DoSutiReports`, покажет полный путь
к JSON-плану. Данные пока не удаляются. Просмотри отчёт и путь удаляемой папки.
Затем выполни, заменив пример пути на выведенный файл:

```powershell
.\Complete-WindowsPilot.ps1 -Apply -PlanFile "C:\Users\Имя\DoSutiReports\cleanup-ID.json"
```

Если при установке указывал другое место, в обеих командах добавь
`-PilotRoot 'D:\DoSutiMentor'`. Другую папку отчётов можно выбрать через
`-OutputDirectory 'D:\DoSutiReports'`; она должна находиться вне папки данных.
Изменённые после плана файлы, занятые блокировки и неполный экспорт останавливают
удаление. При прерывании повтори исходный Apply с тем же планом, не редактируй его.

Если есть подходящий Python вне удаляемой папки, используется он. Иначе сценарий
временно распакует проверенный Python рядом с внешними отчётами из кеша установки.
Временный помощник после работы удаляется. Если кеш уже очищен, сценарий
останавливается; для разрешения загрузки помощника добавь `-AllowDownload`.
Нужны место для временной копии Python и исходная распакованная папка плагина.
При предупреждении об остатке помощника его путь указан явно — закрой процессы
и удали только эту временную папку.

После успеха проверь квитанцию `cleanup-…-receipt.json`: `test_data_removed`
означает удаление данных теста. Плагин, его тестовый источник, ZIP/распакованная
копия и история тестовых чатов удаляются отдельно средствами Codex/Проводника.
В квитанции это честно остаётся `plugin_removed=false`, `chat_history_removed=false`.
Не удаляй общие Python/Git, внешние модели и обычные курсы. Системные журналы,
резервные копии и безопасное затирание диска этим сценарием не охватываются.

Если установка не дошла до курса, эти же команды выбирают ранний режим:
сохраняют доступные bootstrap/setup-журналы и полную опись файлов. Достаточно
маркера собственной новой папки; setup.json может ещё отсутствовать. Ошибки
экспорта, неизвестные файлы/курсы и активная установка блокируют удаление.
Если QA-run уже существует, используется полный QA-экспорт, обхода его проверок нет.
Старая папка без ownership не принимается: сохрани отчёт и отдельно проверь путь.
При отсутствии Python, проверенного архива и сети автоматическая очистка всё ещё
недоступна; можно сохранить доступные журналы и удалить выбранную папку вручную
после остановки процессов.
Для ассистента: [контракт очистки](plugins/dosuti-mentor/references/pilot-evidence.md#очистка-после-передачи-отчёта).

## Источник плагина уже подключён

Если `dosuti-mentor-local` ссылается на прежнюю папку, не удаляй данные курса.
Открой распакованную новую папку как проект в Codex и напиши:

> Переключи локальный источник dosuti-mentor-local на эту распакованную папку
> и установи плагин из неё. Сохрани все курсы, настройки и прогресс.
> Проверь путь источника и установленную версию, затем сообщи результат.

После успешного подключения вернись к шагу 3 README. Если Codex сообщает об ошибке,
сохрани её текст для разбора; не продолжай установку из двух разных копий.

## Проверка замеров ресурсов

В SETUP_REPORT.md после шагов установки должны быть выборки ОЗУ, CPU и диска.
В итоговом TEST_REPORT.md ищи «Ресурсы компьютера». При «нет замера» сохрани отчёт:
это отсутствие данных, а не нулевая нагрузка. Сравни с Диспетчером задач во время
длинной обработки; измеряются Python и его дочерние процессы, а не весь Codex.
Пики отдельных процессов нельзя сравнивать с общей занятой памятью системы.
После принудительного завершения сводка может оставаться running; отметь сбой.

Для проверки удаления сначала сохрани итоговый отчёт снаружи. После очистки данных
проверь отсутствие выбранной тестовой папки, затем отдельно удали плагин, добавленный
ради теста источник, скачанный ZIP/распакованную копию и тестовые чаты. Оригиналы
лекций и общий Python сохраняются. Впиши фактически выполненные действия в отчёт;
скрипт не подтверждает удаление приложения, истории и системных следов автоматически.

## Запасной запуск по ссылке

Обычно команды выполняет чат по README. Для ручной диагностики из распакованной папки:

```powershell
.\Start-WindowsPilot.ps1 -Video 'https://example.org/lecture.mp4' -CpuMode economy
```

Замени ссылку на свою публичную лекцию; локальный путь по-прежнему принимается.
Дождись status: passed. При ручном запуске открой возвращённую папку project в Codex
и вызови $test-learning. При работе в исходном чате ассистент может явно подключить
курс к текущему проекту по твоей просьбе — переносить чат не обязательно.
Шаг video в SETUP_REPORT.md показывает сбои получения; повтори тот же запуск для
использования проверенного кеша. Не меняй хеш и не удаляй историю ради повтора.
