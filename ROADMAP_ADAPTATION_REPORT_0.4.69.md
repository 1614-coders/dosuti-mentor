## Реализация

1. В существующий step_bases добавлены необязательные targets. Каждый содержит
   компетенцию, rationale, unit_id, unit_sha256, номера проверяемых критериев
   и необязательные диагностические свидетельства. Код проверяет соответствие
   компетенции процитированному ответу, наличие unit в шаге, актуальность версии
   и существование критериев. Неподходящая по смыслу тема должна быть отклонена
   ассистентом: валидность ссылок не считается семантическим доказательством.
2. study-next.roadmap использует существующую политику adaptive_learning для
   целевых критериев. Возвращает компетенцию, обоснование, оценки диагностики,
   состояния критериев, ревизии/время ответов и рекомендации: initial_check,
   check_understanding, review_error, fresh_independent_task, recheck_due,
   review_route. Непокрытые диагностические пробелы и шаги без сопоставления
   явно отмечены. Новые темы программа сама не придумывает и не вставляет.
3. Завершение целевого шага определяется указанными критериями; это не объявляет
   остальные критерии unit освоенными. Учитываются зависимости и решения skip/defer.
   Объяснение темы не подтверждает освоение. Более поздняя ошибка меняет совет.
   Историческая диагностика не переписывается после обучения.
4. Принятый план сохраняется, пока ученик явно не согласится с новым proposal.
   Adaptation_basis фиксирует ревизию исходного принятого плана и журналов
   диагностики/unit. Первый targeted-proposal получает снимок при записи; для
   пересмотра существующего плана снимок передаётся явно из свежего study-next.
   При сохранении и принятии снимок перепроверяется под существующими locks.
   Ответ из другого чата делает старое предложение требующим пересмотра.
5. Метаданные хранятся в learning-intent.json со схемой learning_intent_v5.
   V1–v4 читаются без изменения, новые события сохраняют старую историю. Старые
   заголовки не могут объявлять targets/adaptation_basis. Новых хранилищ нет.
   Общий и карьерный маршруты используют один механизм.

Инструкции plan-career/review-learning/teach-unit обновлены: ассистент объясняет
выбор темы, проверяет её содержание, показывает отличие предложения от plan и
не принимает его автоматически. При неполных данных нет формального выбора
по недостоверной сводке. Legacy_unmapped не блокирует обычную помощь ученику.

## Проверки

Новые регрессионные проверки находятся в tests/test_roadmap_adaptation.py.
Проверены: сохранение targets, необязательная/отклонённая диагностика,
несовпадение компетенции, неверные критерии/версия, malformed-поля,
объяснение без освоения, помощь и ошибки, самостоятельное решение и новая
ошибка, диагностический пробел с последующей практикой, целевые критерии
без полного освоения unit, зависимости, повторение, skip, смена цели,
новая диагностика, новый ответ из другого чата, устаревшее предложение,
явное принятие, сохранение схемы v5, чтение старого плана без миграции,
непокрытый пробел, повреждение/смена источников и изменение unit между чтениями,
отсутствие записи при чтении советов, общий механизм карьерного пересмотра.

Первый запуск новых тестов на исходном коде дал ожидаемые ошибки отсутствующего
контракта targets. По ходу реализации исправлен конфликт имён title у шага и
критерия; тесты не ослаблялись. Последующие полные прогоны проходят.

Мутационная проверка в памяти: отключение сравнения adaptation_basis с актуальными
ревизиями вызвало ожидаемое падение теста принятия после ответа в другом чате.
Исходные файлы при мутации не менялись.

Финальные результаты:

- Добавлен 21 регрессионный тест нового механизма.
- Целевой прогон: 74 теста, все прошли.
- Полный прогон: 1095 тестов — 1080 прошли, 15 пропущены, ошибок и падений нет.
  Пропуски относятся к проверкам, требующим Windows/PowerShell.
- Проверка синтаксиса изменённых Python-механизмов и git diff --check прошла.

## Ограничения

- Уместность темы, достаточность критериев и правильность оценки ответа остаются
  обязанностью ассистента. Совпадение компетенций/номеров не доказывает их смысл.
- Старым маршрутам новые связи не приписываются задним числом. Шаг без targets
  не получает выдуманных компетенций; старый способ завершения остаётся доступным.
- Снимок адаптации консервативный: даже checkpoint или несвязанная запись unit
  из другого чата требует перепроверки предложения. Это не стирает план/результаты.
- Чтение нескольких хранилищ не образует общего атомарного снимка. Принятие
  предложения защищено locks/ревизиями; промежуточную сводку при изменениях
  следует перечитать. Нагрузочный benchmark больших маршрутов не проводился.
- Автоматические тесты подтверждают программный контракт. Реальный учебный диалог
  Codex, нативные Windows/Linux и педагогическая эффективность здесь не проверялись.
- После записи v5 совместимость старых версий плагина с новыми метаданными
  не обещается. Обратная совместимость чтения старых журналов сохранена.
