# Исправление образовательного прогресса DoSuti Mentor 0.4.67

Дата: 2026-10-19. База: актуальный main `8008fba0a47549a950dd11e2689fb13e92db0f56`,
версия 0.4.66. Работа выполнена локально в `fix/educational-progress-0467`.
Коммит и push не выполнялись.

## Воспроизведение

На исходном коде пять новых тестов дали две ошибки и два падения; один прошёл.
Подтверждены все четыре проблемы:

1. Нет lesson-истории и результатов в learning_progress.
2. Самостоятельно пройденный unit исчезает из сводки без принятого плана.
3. Незавершённый первый шаг скрывает завершённый независимый второй.
4. Нет списка продолжений; одна точка выбирается по максимальной ревизии.

## Исправления

- История lesson и unit собирается до проверки наличия/актуальности плана.
  Изменение цели и needs_review сохраняют видимость истории; следующий шаг
  неактуального маршрута не предлагается.
- Старый SQLite читается через mode=ro без создания базы, таблиц и миграции.
  Поддерживается схема без homework_revision. status/context также используют
  этот читатель. Механизмы записи progress и CAS остальных журналов сохранены.
- В сводке есть последние lesson-статусы, оценки, задания, история обоих
  механизмов и счётчики. explained не подтверждает знания. Старые оценки
  имеют verification=legacy_recorded_claim; они не приравниваются к независимым
  ответам на критерии unit. Проверка актуальности домашки переиспользуется.
- completed_steps вычисляется по всем шагам до выбора следующего. Сценарий
  «шаг 1 не завершён, независимый шаг 2 завершён» возвращает [2].
  blocked_steps показывает прямые и транзитивные зависимости отдельно от
  факта выполнения. Учтены существующие карьерные метаданные шагов.
- continuations содержит lesson-курсор и последние unit-checkpoints каждого
  unit/session, включая неактуальные с причиной. Старый lesson-курсор общий
  для профиля; ему не приписывается вымышленный чат. При нескольких актуальных
  точках stopped_at=null и continuation_choice_required=true. CLI resume
  принимает --session, сохраняя прежние поля и механизм записи курсора.
- Полная история unit не загружается для формирования сводки: существующий
  потоковый читатель хранит ограниченные очереди по 100 событий/успешных заданий.
  Общие счётчики учитывают весь журнал. Физические хранилища не объединялись.

## Оставшиеся ограничения

- 15 тестов пропущены из-за отсутствующего PowerShell/Windows. Реальный
  пользовательский диалог Codex и нативные Windows/Linux в этой работе не проверены.
- WAL-SQLite не читается сводкой: даже mode=ro может менять shared memory.
  Выдаётся явная причина и valid=false, unit-данные сохраняются доступными.
  Автоматического checkpoint/переключения journal_mode нет. Внешняя база
  должна быть приведена к rollback-режиму её владельцем перед таким чтением.
- История в ответе ограничена последними 100 событиями каждого механизма;
  полные журналы не удаляются. Количество событий и признак усечения доступны.
- Старые lesson-оценки не содержат критериев/ответов уровня unit: достоверность
  выше сохранённого утверждения им не приписывается.
- Отдельные хранилища не образуют общего атомарного снимка при одновременной
  записи из другого чата. Каждая запись сохраняет прежние locks/CAS; при
  параллельном обновлении следует перечитать сводку.
- Шаг без привязанных unit автоматически завершённым не считается.
- Большие журналы продолжают проверяться потоковым проходом; нагрузочный
  benchmark для сотен unit в этой работе не проводился.
