# DoSuti Mentor 0.4.70 — защита непроверенных связей Roadmap

Дата: 2026-10-20. Основание: проверенный main 0.4.69,
`c3f26446d23eabfe509bb3b8d0daee2f71b3b713`.
Изменения локальные; коммит и push не выполнялись. Этап 3 не начинался.

## Воспроизведение и исправление

Отрицательный Java-сценарий воспроизвёл ложное завершение: неизвестная компетенция
synchronized/happens-before связывалась с существующей unit HashMap, и правильное
решение по замене ключа завершало шаг многопоточности. Два новых теста до исправления
воспроизвели завершение без проверки связи, положительная проверка не поддерживалась.

Теперь успешное выполнение критериев unit и проверка их связи с компетенцией —
различимые факты в существующих данных. Target без alignment_review, с verdict
unsupported либо uncertain не завершает шаг и не покрывает диагностический пробел.
study-next показывает alignment_unverified, реальные состояния критериев и
review_route вместо назначения практики по неподтверждённой связи. Результат самой
unit сохраняется; не требуется повторять уже решённую задачу ради нового review.

Положительный review требует diagnostic_reason и criterion_links на каждый целевой
критерий: точный текст критерия, индекс источника, дословную цитату реального
содержимого и объяснение связи. Общий флаг supported без этого не принимается.
Проверяются актуальная версия unit, полный набор критериев и принадлежность цитат
источнику. Notes, название и аннотации не заменяют источник. Поддержан текст
документа/кода/домашки/ресурса/research и речь video.

В навыки добавлена содержательная процедура: прочитать фактический вопрос/ответ,
материал, объяснить проверяемое действие по каждому критерию и найти контрпример —
может ли ученик решить задачу без заявленной компетенции. Если может, supported
недопустим. При недостатке данных нужен uncertain, а не выдуманное обоснование.

## Совместимость и согласование

- Новых хранилищ нет: review находится внутри target существующего intent-журнала.
- Журналы v1–v5 читаются без миграции. Старые targets без review остаются доступны
  как непроверенные связи. Их завершение по одному успеху unit теперь намеренно
  не утверждается; история, unit-результаты и выполненные задания не удаляются.
- Первый review записывает learning_intent_v6; предыдущие события сохраняются
  дословно. Следующие изменения контекста сохраняют v6. Старые заголовки не могут
  выдавать новые reviews за поддерживаемые данные.
- Review обновляется только через proposal с действующими CAS/adaptation_basis и
  отдельное принятие. Чтение не дописывает review в принятый план. Существующая
  защита от новых ответов другого чата, смены цели и источников сохранена.

## Предметный разбор Java

Это разбор текущим ассистентом и сценарии программных компонентов, а не отдельная
живая сессия Codex с учеником и не автоматический семантический evaluator.

| Пробел / критерий | Материал / наблюдение | Содержательный вывод |
| --- | --- | --- |
| Замена повторного ключа и size | HashMap, два put с одним ключом; ученик объясняет замену | Связь supported; самостоятельный ответ подтверждает этот критерий |
| synchronized, видимость и happens-before | Тот же HashMap и последовательные put | Связь unsupported: задачу можно решить без понимания межпоточной видимости |
| Компетенция без содержательно определённого критерия | «Решить задачу» и недостаточное описание проверки | Нужен uncertain и уточнение критерия/материала |
| Правильный ответ после подсказки | Материал соответствует компетенции, но помощь была | practice_with_help; нужна новая самостоятельная задача, не освоение |

## Ограничения

Программа проверяет происхождение свидетельств и защищает от автоматического
зачёта непроверенной связи. Она не понимает Java сама по себе: ложный полный review
с реальной, но неподходящей цитатой и неверным explanation всё ещё может пройти
структурные проверки. Равенство строк, supported или наличие цитаты не доказывают
смысловую истинность. Качество содержательного разбора остаётся обязанностью
ассистента; независимая приёмка его поведения в реальном Codex ещё нужна.

Для источника только в изображении или project timeline положительная цитата
пока требует подготовленного текстового источника; автоматический OCR не запущен.
Нет новых моделей/API и расходов на автоматический семантический классификатор.
Нативные Windows/Linux не проверены. Никакой абсолютной гарантии отсутствия
педагогических ошибок или заявления о закрытии реальной диалоговой приёмки нет.
