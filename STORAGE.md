# Где лежат данные и как их убрать

При новом Windows-прогоне выбирается одна папка через `-PilotRoot`. По умолчанию:
`%LOCALAPPDATA%\DoSutiMentorPilot`. Новые загрузки и данные этого прогона находятся в ней:

```text
DoSutiMentorPilot/
  runtime/       Python (если потребовался), venv, зависимости, запись выбранного Python
  models/        скачанные модели
  run/course/    лекции, материалы, код, ответы и учебный прогресс
  project/       подключение тестового проекта к курсу
  cache/         pip, загрузки Python, кеши инструментов
  temp/          отдельные рабочие папки активных процессов
  reports/       отчёты запуска PowerShell
  setup.json, SETUP_REPORT.md — история подготовки
```

`run` также содержит журналы QA и итоговый тестовый отчёт. Плагин устанавливает
сам Codex в собственный кеш приложения; распакованный исходный архив тоже находится
там, куда его сохранил пользователь. Эти две папки не входят в `PilotRoot`.

Существующие системный Python, явно выбранные внешние runtime/модели и исходники
пользователя не переносятся и не удаляются. В новую схему не мигрируют автоматически
старые курсы: их прежние пути продолжают работать. Старые общие кеши вне новой
папки тоже сохраняются, поскольку ими могут пользоваться другие программы.

## Python и повтор установки

Сначала проверяются существующий Python и ранее скачанная частная копия. Проверка
требует CPython 3.11/3.12 x64, модуль SSL, действительное создание venv и запуск pip.
Псевдокоманды и интерпретаторы Windows Store пропускаются из-за виртуализации путей.
Автоустановка через Windows launcher также выключена для проверочного процесса.
При отсутствии подходящей копии загружается
Python Build Standalone 3.12.15, релиз 20261013; URL и SHA закреплены в
`plugins/dosuti-mentor/references/windows-python.json`.
Архив и python.exe проверяются перед использованием; повреждённый существующий
частный Python автоматически не исполняется. Если другого подходящего Python
нет, установщик резервирует старую папку как `runtime/python-previous-ID`,
устанавливает проверенную новую копию и возвращает старую при обычной ошибке.
Успешная резервная копия сохраняется до согласованной очистки. При активной обработке
ремонт отказывается менять среду; повтори после её завершения. Offline-ремонт
возможен только при наличии проверенного кешированного архива. Если авария оставила
и старую, и неполную новую копию, сохраняй обе для разбора.

После удаления общего Python следующий запуск заново выбирает интерпретатор.
Если база или minor-версия venv изменились, создаётся новое окружение. Старое
сохраняется на время установки и возвращается при обычной ошибке/отмене. После
успеха резервная копия удаляется. Жёсткое выключение может оставить `venv-previous-*`:
эти остатки сохраняются для восстановления, автоматически в кеш их не принимают.
Зависимости устанавливаются из wheel: сборка расширений из исходников запрещена.
Pip запускается изолированно с явным кешем: внешние target/prefix и настройки
pip.ini не должны перенаправлять установку за пределы venv.
Если нужного wheel нет, установка завершится ошибкой с логом.

## Кеш и временные файлы

Python-worker получает собственные TEMP/TMP/TMPDIR, PIP_CACHE_DIR, HF_HOME,
XDG_CACHE_HOME и IMAGEIO_USERDIR; yt-dlp получает явный `--cache-dir`.
Это настройки дочернего процесса, а не постоянные системные переменные.
Обычное завершение/исключение убирает временную папку процесса.
После аварийного завершения она может остаться с маркером аренды.

После успешной Windows-подготовки и подготовки лекции в управляемом курсе кеш
подрезается до 1 ГиБ, удаляя старые кеш-файлы. Это лимит обслуживания после работы,
а не жёсткая квота диска во время загрузки. Если другой процесс ещё работает,
очистка откладывается. Модели, уроки, ответы и отчёты не входят в этот лимит.
Неизвестные временные файлы сохраняются; активные процессы блокируют очистку.

Для ассистента доступны команды (PYTHON — выбранный интерпретатор):

```text
PYTHON PLUGIN_ROOT/scripts/managed_storage.py --home DATA_ROOT --usage
PYTHON PLUGIN_ROOT/scripts/managed_storage.py --home DATA_ROOT
PYTHON PLUGIN_ROOT/scripts/managed_storage.py --home DATA_ROOT --apply --cache-mib 1024
```

Первая показывает логический размер по папкам без обхода внешних ссылок. Вторая
показывает план обслуживания. Третья применяет его, когда обработчики не активны.
Обработка новых файлов обычного старого курса без маркера дома сама по себе
не переносит его кеши: для такого курса нужен отдельный согласованный переход.

## Полное удаление теста

Сначала сохрани нужные отчёты вне папки данных. Заверши обработку и закрой тестовые
чаты/проект. Затем можно удалить выбранную папку данных через Проводник.
При ошибке «файл занят» заверши использующий её процесс, прежде чем повторять.
Общий Python, который был до установки, остаётся на компьютере.

Для проверяемого удаления с инвентаризацией используй штатный план pilot_cleanup
из WINDOWS-PILOT.md. Для существующего курса нужен полный экспорт QA; до его
создания сохраняются доступные журналы установки и опись. Нужен интерпретатор вне удаляемого
дерева. `Complete-WindowsPilot.ps1` автоматически подготавливает временный внешний
Python при необходимости и убирает его после очистки. Архив берётся из собственного
проверенного кеша; при его отсутствии загрузка разрешается только через -AllowDownload.
План и внешний отчёт сохраняются. Подробности — в WINDOWS-PILOT.md.
Удаление плагина и истории чатов выполняется отдельно в Codex.
Удаление папки не обещает очистить журналы Windows, антивируса или самого Codex.

Переносимая сборка: [документация поставщика](https://github.com/astral-sh/python-build-standalone/blob/main/docs/running.rst).
Реальная приёмка установки/удаления на Windows ещё требуется.

## Одновременная обработка

В одном управляемом доме модель загружает один рабочий процесс. Остальные ждут
слот до загрузки модели, показывая ожидание; таймаут — 6 часов. После освобождения
слота повторно используются обычные checkpoints. Блокировку держит сам worker,
ОС освобождает её при его аварийном завершении. Установка зависимостей тоже занимает
этот слот, чтобы не менять venv под работающим обработчиком.

Это ограничение внутри одной папки данных, не глобальная квота ОЗУ компьютера.
Разные дома и старые неуправляемые курсы могут работать параллельно. При гибели
worker уже запущенный дочерний FFmpeg может кратковременно продолжать работу;
сценарий не обещает принудительно завершать любые осиротевшие процессы.

## Установка оборвалась до курса

Complete-WindowsPilot.ps1 автоматически выбирает ранний режим, если run ещё нет.
Он принимает только собственный дом с валидным маркером и известными выходами
установщика. Внешний отчёт содержит доступные bootstrap/setup-журналы и опись;
отсутствие setup.json не подменяется выдуманными попытками или нулевыми замерами.
Неизвестные корневые записи, повреждённые журналы, неполный экспорт и занятые
блокировки запрещают удаление. После прерывания Apply продолжай исходным планом;
начало установки во время pending-очистки заблокировано.

Отчёт, план, квитанция и внешний apply-lock сохраняются намеренно. Плагин и чаты
остаются отдельным действием. При отсутствии внешнего Python/кеша и сети помощник
не может запуститься; ручное удаление собственной папки после сохранения журналов
остаётся запасным вариантом.
