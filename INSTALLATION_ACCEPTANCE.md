# Приёмка установки DoSuti Mentor 1.0.0

**Живой Codex smoke test: NOT VERIFIED.** Сценарий ниже предназначен для отдельной
приёмки после публикации одобренного кандидата в main. Автоматические тесты не
заменяют фактический интерфейс Codex. До публикации main может содержать 0.8.0.

## Подготовка

Используйте отдельную учётную запись/пустой каталог QA, собственный DATA_ROOT
и отсутствие исходных пользовательских данных. Для обновления берите копию
существующего QA-курса, включая профили и progress. Не меняйте чужие настройки Codex.
Запишите ОС, Python, Codex, URL/ref marketplace и фактическую версию.

## Первая установка из публичного main

1. Откройте Codex. Попросите установить плагин по запросу из [README](README.md#как-установить).
   Для CLI проверьте --help, затем штатные команды:
   ```text
   codex plugin marketplace add 1614-coders/dosuti-mentor --ref main
   codex plugin add dosuti-mentor@dosuti-mentor-local
   codex plugin list --json
   ```
2. Подтвердите источник main и manifests 1.0.0 фактически установленной копии.
   Не подменяйте main локальным кандидатом. Без права чтения публичного репозитория
   зафиксируйте отказ; токен владельца или push scopes не требуются.
3. Проверьте доступность setup-dosuti и выполните техническую настройку с QA DATA_ROOT.
   Ожидается проверенный приватный Python, импорты, допустимые версии и FFmpeg,
   bootstrap verified=true. Курсы/ASR-модели и анкета не должны запускаться установкой.
4. Повторите setup: исправный runtime не пересобирается. Проверьте --check/--verify
   из [технической инструкции](plugins/dosuti-mentor/references/installation.md#локальные-компоненты).
   Ошибка или timeout не должны называться успешной установкой.
5. Откройте новый чат, выполните `$start-learning`. Проверьте восемь вопросов по одному,
   возможность пропуска, отсутствие выдуманного chat ID и выбор курса.

## Учебный round trip

На отдельном QA-курсе задайте цель, пройдите диагностику и согласуйте Roadmap.
Проверьте объяснение, практику, ответ ученика и сохранение фактического прогресса.
Добавьте локальный текст/code из копии fixture; на macOS/Linux отдельно PDF и видео
с короткими разрешёнными тестовыми материалами. На Windows следуйте ограничениям
[known issues](WINDOWS_KNOWN_ISSUES.md), не обходите отказ unsupported pipeline.

Попросите показать курсы, явно выберите другой профиль/курс и убедитесь, что данные
не смешались. Перезапустите Codex, откройте новый чат и продолжите выбранный курс;
не должна заново выполняться анкета существующего профиля. Поиск вакансий без
согласия не запускается. Отмена операции не должна удалять учебные данные.

## Обновление и неполная установка

Сохраните hashes/bytes копии QA-курса и профилей при остановленных процессах.
Обновите прежнюю опубликованную установку через marketplace main по
[инструкции](plugins/dosuti-mentor/references/installation.md#обновление-установленного-плагина).
Проверьте manifests 1.0.0, новый чат, тот же DATA_ROOT, курсы и прежние ответы.
Runtime может обновиться из-за Pillow 13; курсы/профили не должны измениться от setup.
Не переходите на старый main поверх новых данных без проверки совместимости.

Неполную установку моделируйте только в disposable QA-среде (например, отсутствующая
обязательная зависимость). --verify должен отказать диагностируемо, не объявить
успех и не удалять данные. Не ослабляйте sandbox и системные политики ради теста.

## Протокол результатов

Для каждого этапа запишите PASS / FAIL / NOT VERIFIED, ожидаемое и фактическое,
логи stdout/stderr без секретов, версии и hashes учебных fixtures до/после.
Отдельно отметьте живой интерфейс, CLI fixtures и нативные Windows результаты.
Без фактического выполнения не заменяйте NOT VERIFIED на PASS.
