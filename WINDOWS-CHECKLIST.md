# Полный UX-пилот на Windows — 0.4.78

Ручная проверка обычного плагина, без отдельного тестового режима. Для чистого
прогона используй отдельную учётную запись Windows или явно отдельный управляемый
DATA_ROOT для QA. Новая папка проекта НЕ изолирует общий стандартный профиль.
Рабочие курсы не используй. Автоматические тесты не подтверждают
качество диалога или установку на твоём компьютере. Отмечай каждый этап: прошёл /
не прошёл / не проверен. Сохраняй текст непонятного ответа и ошибки.

1. **Установка.** Отправь Codex ссылку на GitHub и запрос установки из README.
   Разреши необходимые системные действия. ZIP не требуется. До start-learning
   не должно быть анкеты, курса или профиля. Повторная установка проверяет готовую
   среду; ошибки и отказ в разрешении не должны давать сообщение об успехе.
   Запиши версии Windows, Codex и плагина. При ошибке сохрани её полный текст.
   Codex CLI должен находиться через PATH; его не нужно копировать в папку проекта.
2. **Приветствие.** После установки открой нужный проект Codex, создай новый чат
   и отправь только `$start-learning`. Должны появиться возможности помощника и
   «Вопрос 1 из 8», варианты и возможность пропуска. Не должно быть просьбы
   самому запускать внутренние команды, читать JSON или выбирать папку профиля.
   При отсутствии прежнего подключения курс появляется в DATA_ROOT/courses/default,
   текущий проект не получает новый курс или файл подключения.
3. **Восемь вопросов.** Для простого прогона укажи цель «Хочу разобраться с Java
   HashMap», основы Java, пошаговый формат и остальные реальные предпочтения.
   Один вопрос на сообщение, номер и варианты понятны. Один вопрос пропусти.
   После нескольких ответов скажи «пауза», открой новый чат проекта и отправь
   `$start-learning`: продолжение с нерешённого вопроса, без новой анкеты.
   Исправь один ответ: остальные не теряются. После восьмого — только предложение
   необязательной диагностики, а не девятый вопрос знакомства.
4. **Диагностика.** Сначала ответь «Позже»: проверка не начинается. Затем явно
   согласись. Ориентир 10–20 вопросов, по одному; допускается раннее завершение.
   Ответь неверно, попроси пропустить один вопрос, затем дай самостоятельный ответ.
   Вопросы должны учитывать ответы. Пауза и новый чат восстанавливают текущий вопрос,
   не обнуляя результаты. Можно остановить проверку без запрета продолжать учиться.
5. **Результаты.** Заверши диагностику. Ожидается понятный итог: что проверено,
   что подтверждено, где пробелы и что неизвестно, откуда начать. Пропуск не ошибка,
   самооценка не доказательство знаний. Завершённая диагностика не запускается заново.
6. **Roadmap.** Наставник предлагает короткий порядок тем с причиной первого шага.
   Он ещё не принят. Сначала откажись от неудобного порядка: план не принимается
   молча. Затем согласуй вариант. При продолжении в новом чате цель и принятый план
   сохраняются. Диагностика и маршрут требуют разных согласий.
7. **Материалы.** Для короткого урока передай ассистенту файл
   [java-map-pilot.md](plugins/dosuti-mentor/tests/fixtures/java-map-pilot.md).
   Это пересказ реального справочника Oracle с отдельно отмеченным примером
   наставника, без видео, ASR и OCR. Ассистент сам готовит тему и сообщает переход
   «Материал готов, начинаем…». Готовый материал повторно загружать не просит.
8. **Урок и практика.** Объяснение идёт выбранным способом, небольшими шагами.
   Сначала ошибись о размере HashMap; после объяснения попроси подсказку и реши
   пример с помощью. Затем реши НОВУЮ задачу без подсказки. Ожидается разная реакция:
   разбор ошибки → новая самостоятельная практика → итог и следующий шаг.
   Одно объяснение и подсказанный ответ не считаются самостоятельным освоением.
9. **Новый чат.** Остановись на конкретном вопросе, попроси сохранить продолжение.
   В новом чате этого же проекта отправь `$start-learning` и «Продолжим занятие».
   Анкета и диагностика не начинаются заново; сохраняются план, результаты и вопрос.
   При нескольких точках наставник спрашивает, какую продолжить; не выбирает молча.

## Дополнительные развилки

- В другом новом QA-проекте откажись от диагностики до её начала: урок доступен.
- При готовом уроке, отсутствии домашки или ещё не принятом плане нет технического
  тупика: наставник предлагает один понятный шаг, не просит управлять CLI.
- Ошибка записи/недоступный материал объясняется словами; нет ложного «сохранил»
  и нет отметки об освоении без фактического ответа.

## Что вернуть в отчёте

Версии системы/Codex/плагина; для каждого из девяти пунктов — статус, ожидаемое и
фактическое поведение. Приложи текст/скриншот каждого затруднения. Отдельно отметь
лишние вопросы, повтор знакомства, потерю ответа, показ JSON/путей/команд и моменты,
когда пришлось самому что-либо чинить. Добавь короткий отзыв: что удобно, что мешало.

Не удаляй QA-курс до сохранения отчёта. Этот чеклист сам ничего не устанавливает,
не очищает и не собирает данные автоматически. Рабочие курсы не используй для пилота.
